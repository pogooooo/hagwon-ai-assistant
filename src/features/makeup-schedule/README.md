# 13. 휴·보강 일정 관리 (makeup-schedule)

> **모든 학원·반·원생·일정은 테스트용 가상 데이터다.**

반 휴강과 학생 결석의 보강 일정을 등록·변경·취소·조회하고, 원장이 확정한 최신 일정을 상담봇(4. RAG 상담) 자료에 바로 반영한다. 대상자와 충돌은 코드로 계산하고, 날짜·시간은 저장값만 쓴다(LLM이 만들지 않음).

## 구조

```text
src/features/makeup-schedule/
  model/            # 클라이언트·서버 공용 순수 로직(서버 모듈 import 없음)
    types.ts        # 학원·반·원생, 일정(ScheduleEvent), 안내문, 충돌 타입
    schedule.ts     # 등록·확정·보강 변경/취소·휴강 취소, 충돌 검사·추천, 학생별 조회
    notice.ts       # 안내문 문구, 상담 자료(RAG) 문서 본문
    time.ts         # KST 날짜·시각 도우미
    demo-academy.ts # 가상 교습소(AC_TEST_A와 같은 ID)
  server/rag-sync.ts  # 확정 일정 → SourceDocumentInput + schedule_change 사실 → onDocumentChanged
  store.ts            # 관리 화면 상태(zustand, 브라우저 저장)
  ui/                 # 관리 화면 컴포넌트
  academies/AC_TEST_A # RAG 평가 형식(academies-v1) 예시 문서와 질문 6개
  __tests__/          # 규칙 단위 테스트, 상담 엔진 통합 테스트
src/app/makeup-schedule/page.tsx  # /makeup-schedule 화면
```

## 기능

| 기능        | 내용                                                                                                                         |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 등록        | 반 휴강(반 원생 전체) 또는 학생 결석(그 학생만). 수업 없는 요일·중복·반 전체 휴강일의 결석 등록은 거부                       |
| 확정        | 임시 저장은 안내·상담에 쓰지 않는다. 확정하면 revision 1, 안내문 대기 목록과 상담 자료에 반영                                |
| 보강        | 정규 수업 길이로 종료 시각 계산. 강사·교실·원생 겹침, 교습 종료 시각, 정원은 확정을 막고 공휴일은 경고만 한다                |
| 가능 시간   | 학생별 보강 가능 시간(요일·시간대) 등록. 반 보강은 못 오는 인원을 경고, 결석 보강은 그 학생이 못 오는 시간이면 확정을 막는다 |
| 추천        | 이후 14일 안에서 충돌 없는 시간 중 올 수 있는 학생이 많은 순으로 3개(평일 16시·주말 10시 이후 + 학생이 등록한 시간대)        |
| 변경·취소   | 보강 변경·취소, 휴강·결석 취소. 확정 내용이 바뀔 때마다 revision 이 오르고 이력·안내문이 남는다                              |
| 학생별 조회 | 기간 안의 정규·휴강·결석·보강을 날짜순으로(확정분만). 다른 학생 결석은 섞지 않는다                                           |
| 상담 반영   | 반 휴강은 `class_members`, 결석은 `student_private` 문서. 보강 취소·휴강 취소는 해당 문서를 철회해 다음 질문부터 빠진다      |
| 안내 발송   | 문자·알림톡은 외부 계정 연동 전이라 발송 대기 목록까지                                                                       |

## 실행

```bash
npm run dev
```

`http://localhost:3000/makeup-schedule` 에서 "예시 일정 불러오기"로 시작한다. 앱이 정적 빌드라 일정은 그 브라우저에만 저장된다. 운영에서는 백엔드 일정 DB에 저장하고, 확정·변경·취소 때마다 서버에서 `syncScheduleEvent(queue, academy, event)` 를 호출한다.

```bash
node --disable-warning=MODULE_TYPELESS_PACKAGE_JSON --test "src/features/makeup-schedule/__tests__/*.test.ts"
```

통합 테스트는 손으로 쓴 휴보강 문서(`TA_CANCEL_*`, `TA_MAKEUP_*`)를 빼고, 화면과 같은 규칙으로 만든 일정을 실제 상담 엔진에 넣어 `academies/AC_TEST_A/cases.jsonl` 질문을 던진다.

## 현정 님과 확인할 것

1. **학생 결석 보강 답변:** 엔진이 휴보강 사실을 학생 범위 없이(`studentIds: []`) 조회해서 `student_private` 일정은 검색에는 걸리지만 근거 사실이 비어 보류된다(`answer/info.ts` `loadFacts`, `answer/event-evidence.ts`). 대상 학생 범위로 조회하도록 바꿀지
2. **TA-001:** "이번 주 수요일 수업 있나요?"에 휴강은 답하지만 연결된 11/14 보강을 함께 말하지 않는다
3. **TA-003·005:** 답변 내용은 맞는데(미확정·담당자 안내) 상태가 `partial` 이 아니라 `answered` 다. 상태 기준을 어느 쪽으로 볼지
4. 반별 휴강을 신규 방문자에게 비공개로 두는 기준이 맞는지
5. `academies/AC_TEST_A`를 평가 하네스에 넣을지, 넣는다면 어디에 둘지
6. 운영 백엔드에서 `syncScheduleEvent` 를 부를 위치(일정 저장 API)
