# AXR 통합 운영 서비스

교사는 **사진 채점 → 과제 등록 → AI 풀이로 채점할 과제**에서 반·과목·쪽별 문항 범위를 정합니다. 학생이 문제와 풀이가 함께 보이는 사진이나 PDF를 제출하면 CLOVA가 인쇄된 문제를 전사하고, 별도 호출에서 그 문제를 풀어 학생 답과 비교합니다. 잘린 지문이나 판독 불일치는 교사 확인 대상으로 남습니다. 별도 배점이나 공식 정답을 사용하려면 **정답·배점을 직접 지정하는 과제**를 선택합니다. 교사는 **제출 검수**에서 원본·AI 풀이·학생 답·점수를 대조하고 확정합니다. 학생과 보호자는 임시 원본 삭제 확인 후 공개된 결과를 볼 수 있습니다.

학생 분석과 새 상담은 사진 채점의 확정 결과를 사용합니다. 학부모 월간 알림에는 교사가 검토·승인한 학생별 월간 리포트 본문이 들어갑니다. 승인 후 해당 채점이나 출결 근거가 바뀌면 다시 분석하고 승인해야 합니다. 기존 교재 자료는 과거 상담·알림의 출처를 열 때 현재 권한과 개정 상태를 확인합니다.

## 실행과 경로

Node 24.19.0에서 `npm ci`, `npm run dev`를 실행합니다. 기본 주소는 `http://127.0.0.1:8791`, 가상 관리자 계정은 `TA_DIRECTOR` / `axr-demo`입니다. 포트·DB·새 DB의 초기 비밀번호는 `.env.local`에서 설정합니다. 이미 생성된 계정 비밀번호는 환경 변수 변경으로 덮어쓰지 않습니다.

`/makeup`과 `/makeup-schedule`의 GET/POST는 운영 서버에서 `/schedule`로 연결됩니다. Next 프로토타입은 `npm run dev:prototype`으로 별도 실행합니다. `npm run build`/`npm start`는 Next 정적 프로토타입의 빌드/미리보기입니다. 운영 서버·SQLite 배포 명령이 아닙니다.

공공정보·학교 시험·음성 기능의 설정, 승인 조건, 실제 연결 여부와 평가 기준은 [추가 기능 검증 기록](../../../docs/new-features-srs-validation.md)을 참고합니다. 상담 답변을 자동 지식화하는 F2 기능은 제외했습니다. Speech/Voice 키가 없으면 음성 화면의 글 입력 대체 경로를 사용할 수 있습니다.

운영자 홈에서는 처리 중인 상담과 채점 검수 대기를 확인하고, 학생·보호자 홈에서는 다가오는 일정, 숙제, 확정 학습 기록을 확인합니다. 홈 목록에는 계정이 열람할 수 있는 기록만 표시합니다. 상담은 처리 중·내 상담·완료, 일정은 월간 달력·휴보강·공지 및 예약으로 이동할 수 있습니다. 모바일에서는 메뉴를 가로로 이동할 수 있습니다. 상담 캐릭터는 계정별로 저장합니다. 미전송 질문은 현재 브라우저 탭에 보존하고 로그아웃하거나 제출하면 지웁니다.

## main의 이전 교재 숙제 기록

다음은 과거 분류·검수 데이터의 생성 규칙입니다. 이 브랜치에서는 승인된 상담 출처를 읽을 수 있으며 새 숙제는 `/grading`에서 받습니다.

1. 관리자/담당 교사가 분류 JSON과 반·숙제 제목·분석 월을 등록합니다. 첨부 규약의 `formatVersion=1.x`, `rubricVersion=1.0`, 수학 11개·영어 14개 태그를 검증합니다.
2. **전달받은 결과 등록·수정**에서 팀 채점 결과 JSON을 업로드합니다. 아래 형식은 이 서비스의 수신 어댑터 계약입니다. 팀의 최종 출력 형식이 확정됐다는 뜻은 아닙니다. 쪽수와 인쇄 번호로 분류 문항에 연결합니다.
3. 업로드만으로 공개하지 않습니다. 담당자가 결과를 검수·확정하면 영역/유형별 분석과 월별 합계가 저장됩니다.
4. RAG는 최신 분류에 맞는 확정 결과만 사용합니다. 수정·재분류·철회 시 이전 분석을 상담에서 제외하고, 재검수 후 새 분석 버전을 발행합니다.
5. 분류 버전·결과 버전·검수 사유·분석 원본을 DB에 보존합니다. 상담 인용에서 실제 숙제와 문항 결과로 이동합니다.

```json
{
  "formatVersion": "1.0",
  "assignmentId": "team-homework-01",
  "studentId": "TA_STU_001",
  "classificationRevision": 1,
  "results": [
    { "page": 42, "displayNumber": "1", "outcome": "correct" },
    { "page": 43, "displayNumber": "1", "outcome": "incorrect" }
  ]
}
```

`outcome`은 `correct`, `incorrect`, `unknown`입니다. 누락 문항은 미확인이며 정답으로 추정하지 않습니다. 다른 숙제/학생/분류 버전, 없는 좌표, 중복 좌표를 거부합니다. 첨부 분류 JSON의 `agreement`는 분류 일치 횟수이며 학생 점수가 아닙니다.

인증된 관리자/교사 세션에서 `POST /learning`에 `action=results-import`, `assignmentId`, `studentId`, `classificationRevision`, 현재 결과 `revision`(첫 등록 0), `reason`, `resultsFile`을 multipart로 보낼 수 있습니다. 파일 대신 `gradedResults` JSON 문자열도 받습니다. 기존 세션·동일 출처·담당 반 검사와 버전 충돌 검사를 모두 적용합니다. 외부 시스템 전용 서비스 계정/토큰·웹훅은 아직 없으며 팀 서버 연결 시 확정할 항목입니다. OCR·자동 정오답 판정·자동 태그 분류를 수신 기능에 추가하지 않았습니다.

수동 오답 입력은 검수 보조로 보존했습니다. 이 경로에서는 명시적으로 전체 확인을 선택했을 때만 미입력 문항을 정답으로 처리합니다. 팀 결과 JSON 수신에는 이 추론을 적용하지 않습니다.

### 분석 기준과 권한

- `itemStatus=classified`, 태그 `status=adopted`만 집계합니다. 참고/보류 태그·미분류·결과 미확인 문항은 정답률 분모에서 제외하고 제외 수를 따로 표시합니다.
- 태그마다 문항을 한 번, 같은 영역 내에서는 중복 없이 한 번 셉니다. 전체 정답률은 문항 기준이며 태그별 수의 합이 아닙니다. 월별 합산도 문항 수로 가중합니다.
- 정답률은 `정답 수 / 집계 가능한 확인 문항 수 × 100`입니다. 분모 0이면 정답률 사실을 만들지 않습니다. 수학 세부 유형은 참고용입니다.
- 혼합 수학/영어 반에 분류 자료를 등록하거나, 이미 분석이 있는 반의 과목을 변경하지 못하게 합니다.
- 학생은 주 소속 반과 추가 수강 반을 가질 수 있습니다. 등록·종료 이력을 저장합니다. 교사는 현재 담당하는 반의 현재 수강생 자료만 봅니다. 다른 과목 반의 개인 자료를 같은 학생이라는 이유로 읽지 못합니다.
- 학생 본인과 연결 보호자는 반 이동 후에도 자신의 과거 확정 분석을 조회할 수 있습니다. 과거 반 자료의 공개 범위 전체를 넓히지 않습니다. 현재 소속이 아닌 반의 결과를 새로 쓰는 것은 차단합니다.

## 휴·보강 및 시간표 개정

팀 `feat/makeup-schedule-rag-doc`의 `ba816647af3bfca104609acc0cb9c0c03ac1ed29`까지 내용을 가져와 SQLite·권한·운영 상담에 연결했습니다. Git 원본 main은 변경하지 않습니다.

- 원장 확정 전 일정은 상담에서 제외합니다. 반 전체 휴강과 개인 결석을 구분하고, 보강 미정/복수 결석/날짜 불일치는 확인 또는 부분 답변으로 처리합니다.
- 정규 수업과 보강의 강사·교실·원생·시간·학원 전체 동시 인원을 검사합니다. 여러 교실 인원을 합산하며 이어지는 수업은 중복 합산하지 않습니다.
- 공통 공지와 팀 일정의 중복, 상담 예약과 정규/보강 강사 시간 충돌을 검사합니다. 빈 보강 변경을 취소로 처리하지 않으며, 휴강 철회로 복구될 수업과 보강 충돌도 확인합니다.
- 기존 시간표 변경에는 적용일이 필요합니다. 오늘 이전 또는 마지막 개정판보다 이른 변경은 거부합니다. 이전 기간을 보존하고 휴·보강에는 등록 당시 수업 정보를 저장하므로 원래 시각·길이·인용이 바뀌지 않습니다.
- 안내문은 DB 발송 대기함에 저장합니다. 실제 문자·알림톡은 발송하지 않습니다. 모든 운영 반을 등록해야 전체 자원 충돌을 확인할 수 있습니다.

## 네이버 AI 연결

운영 서버와 Cloudflare는 네이버 CLOVA Studio HCX-007을 사용합니다. 일반 안내는 질문 항목별 원문 선택을, 학습 방향은 승인된 지도 근거에 제한한 문장 구성을 요청합니다. 반·원생·정형 시간표·비용은 기존 권한 조회와 전용 엔진을 유지합니다. 운영 설정에 Gemini가 남아 있어도 Google로 전송하지 않습니다. 과거 비교 실험용 공급자만 독립 평가 코드에 보존합니다.

```dotenv
RAG_GENERATION_PROVIDER=clova
RAG_CLOVA_API_KEY=
RAG_CLOVA_ALLOW_PERSONAL_DATA=false
RAG_GENERATION_DAILY_CALL_LIMIT=100
```

키는 서버 환경 또는 Cloudflare Secret에 등록합니다. 개인 학습 기록의 외부 처리는 별도 허용 전 차단합니다. 일반 안내 AI는 승인된 학원 공개 문단을 읽습니다. 학생·반에 귀속된 자료, 표, 판독 불확실 OCR은 AI 입력에서 제외합니다. 공통 규정 표를 포함한 표 답변은 기존 행·열 선택과 검증 경로에서 처리합니다. 기존의 대상 확인·접근 제한·정형 사실·시간표·차량별 셔틀·공지 조회를 먼저 수행합니다. 그 뒤 일반 문서 해석이 필요한 질문 전체와 요구 항목을 함께 보내고, 반환 항목의 누락·추가·중복, 원문 변조, 문서 ID, 마지막 승인 버전을 검사합니다. 일부만 확인되면 partial, 확인된 내용이 없거나 모델이 실패하면 보류합니다. 문장이 실제 질문에 답하는지는 모델 판단도 포함하므로 원문 일치 검사만으로 의미 정확성 전체를 보증하지는 않습니다.

최종 문항별 결과와 평가 기준은 [네이버 상담 검증](../../../docs/naver-consultation-verification-2026-11-17/README.md)을 참고합니다.

로컬 운영 서버와 Cloudflare의 호출 횟수는 SQLite의 `op_external_usage`에 저장됩니다. UTC 일자당 기본 100건이며 재시작해도 초기화되지 않습니다. 실패한 네트워크 호출도 한 건으로 계산합니다. 재시도·타 공급자 전환은 하지 않습니다. 이 횟수 제한은 네이버 계정 전체의 원화 과금 한도가 아닙니다. 사진 판독·음성 서비스에는 각각 별도 설정과 한도가 있습니다.

`npm run ai:check`는 공개 합성 안내 한 건으로 연결을 확인합니다. 현재 API는 [CLOVA v3 Structured Outputs](https://api.ncloud-docs.com/docs/clovastudio-chatcompletionsv3-so)입니다. 사진 판독은 기존 CLOVA 연결을 유지합니다. 음성 인식·합성도 네이버용 어댑터이며 전용 키가 없으면 비활성 상태입니다.

권한 위반은 평가상 0건입니다. 결과는 `.local/service-eval/service-final/`, 문항별 비교는 `.local/service-eval/comparison.json`, 테스트 로그는 `.local/service-tests-final.log`에 보존했습니다. OCR을 끈 첫 시도는 스캔 PDF를 읽을 수 없어 중단됐고, 이후 OCR을 켜 동일 조건으로 완료했습니다. 새 독립 정확도나 실제 Gemini 정확도 95%를 의미하지 않습니다.

실제 Gemini 연결 확인에서는 가상 공개 안내가 통과했고, 가상 학습 기록의 상담도 실행했습니다. 초기 학습 방향 요청은 모델이 `unknown`을 반환해 보류됐습니다. 검색되는 지도 근거를 갖춘 뒤에도 보류되어, 근거에 명시된 복습 방법을 요약하라는 생성 지시를 명확히 했습니다. 이후 **최종 답변과 2개 출처(확정 분석·복습 지도 자료)가 검증을 통과**했습니다. 이후 같은 질문을 운영 웹에서 다시 실행했을 때 `GENERATION_REJECTED`로 보류되는 사례도 확인했습니다. 따라서 연결 성공과 생성 품질 안정성을 구분합니다. 이 단일 가상 성공 사례를 상담 정확도로 계산하지 않습니다. 원문·추적 결과는 키가 없는 `.local/service-live-gemini.json`에 있습니다.

브라우저에서는 달력의 정규·휴강·보강 표시, 원본 캐릭터 3종과 계정별 선택, 캐릭터 변경 중 질문 초안 보존, 모바일 화면의 가로 넘침 여부를 확인했습니다.

## Cloudflare 데모

[AXR 가상 학원](https://axr-academy-hosted.pogoo.workers.dev/login)은 Cloudflare Workers에서 요청을 받고 Durable Objects에서 앱과 SQLite를 실행합니다. 기존 Cloudflare 주소는 새 주소로 연결됩니다. 클라우드 데모는 저장소에 있는 가상 학원 자료로 초기화하며, 로컬 데모 DB와 별도로 저장합니다.

저장소 루트에서 아래 순서로 배포합니다. 데모 Worker에 `AXR_HOSTED_DEMO_PASSWORD`와 `RAG_CLOVA_API_KEY`를 시크릿으로 등록합니다.

```sh
node deploy/cloudflare/prepare-hosted.mjs
wrangler deploy --config deploy/cloudflare/wrangler.hosted.jsonc
```

데모는 서버에서 네이버 CLOVA Studio로 직접 요청합니다. 이전 Gemini 중계 Worker 연결은 제거했습니다. 관리자 계정으로 로그인한 뒤 [설정](https://axr-academy-hosted.pogoo.workers.dev/settings)의 **가상 안내로 연결 확인**을 누르면 실제 모델이 운영 시작 시각을 14시로 답하고 가상 안내를 인용했는지 확인합니다. 공개 데모에서는 학생 자료의 외부 AI 전송을 차단합니다. 확정 수치와 일정은 저장된 근거를 조회해 답합니다.

클라우드 데모의 문서 업로드는 최대 5MB입니다. 텍스트 PDF를 파싱하고 원본을 내려받을 수 있습니다.

## 남은 운영 연결

기존 교재 숙제에서 공개한 분석은 상담의 인용 링크로 열 수 있습니다. 정정되거나 철회된 기록은 상담에서 제외합니다.

로컬 SQLite·가상 계정에서 구현·검증했습니다. 실제 팀 채점/분류 산출물 연결, 외부 인증·운영 DB/호스팅, 문자·알림톡 발송, 음성 서비스의 실제 계정 검증에는 별도 키가 필요합니다. CLOVA Studio 텍스트 호출은 합성 문항으로 검증합니다. 운영 업로드는 텍스트 PDF·DOCX·HWPX·TXT·Markdown을 읽습니다. 스캔 전용 PDF의 운영 업로드 OCR은 연결하지 않았고 확인된 텍스트를 별도로 입력합니다. RAG 자체 OCR과 원본 평가 경로는 보존했습니다. AI로 학습 원인·태도·미래 성적을 임의 진단하지 않습니다.
