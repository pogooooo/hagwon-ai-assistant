# AXR 통합 운영 서비스

숙제 **채점·분류 생성은 팀원 담당**입니다. 이 서비스는 전달된 분류와 정오답을 받아 검수·분석하고 SQLite에 저장하며, 확정된 결과를 RAG 상담 근거로 제공합니다. 실제 팀 결과 파일이 아직 없어 첨부된 분류 규격·태그와 가상 자료로 검증했습니다.

## 실행과 경로

Node 24.19.0에서 `npm ci`, `npm run dev`를 실행합니다. 기본 주소는 `http://127.0.0.1:8791`, 가상 관리자 계정은 `TA_DIRECTOR` / `axr-demo`입니다. 포트·DB·새 DB의 초기 비밀번호는 `.env.local`에서 설정합니다. 이미 생성된 계정 비밀번호는 환경 변수 변경으로 덮어쓰지 않습니다.

| 경로            | 기능                                                                           |
| --------------- | ------------------------------------------------------------------------------ |
| `/directory`    | 반·원생·복수 반 수강·보호자·담당 교사 관리                                     |
| `/learning`     | 팀 분류/결과 업로드, 검수, 문항·영역·유형·월별 분석과 출처                     |
| `/schedule`     | 정규 수업·휴강·개인 결석·보강·공통 공지·상담 예약, 월간 달력                   |
| `/documents`    | 파일/텍스트 등록, 검색·분류 필터, 개정·승인·철회, 선택 자료 답변 미리보기      |
| `/consultation` | RAG 상담, 이력, 근거 열람, 담당자 연결·배정·직접 답변                          |
| `/settings`     | 목업의 캐릭터 3종 선택, 관리자 AI 연결 상태·가상 호출 확인                     |
| `/homework`     | 기존 답안 입력·정답키 비교 기능을 보존한 경로. 이번 팀 연동 경로는 `/learning` |

`/makeup`과 `/makeup-schedule`의 GET/POST는 운영 서버에서 `/schedule`로 연결됩니다. Next 프로토타입은 `npm run dev:prototype`으로 별도 실행합니다. `npm run build`/`npm start`는 Next 정적 프로토타입의 빌드/미리보기입니다. 운영 서버·SQLite 배포 명령이 아닙니다.

첨부 서비스형 목업의 색상·카드·탐색 메뉴와 원본 호두/물방울/부엉이 이미지를 사용했습니다. 월간 달력, 모바일 하단 메뉴, 고정 상담 입력창, 캐릭터 변경 중 미전송 질문 보존을 구현했습니다. 질문 초안은 계정별 브라우저 탭 저장소에만 보존하며 로그아웃·전송 시 지웁니다. 캐릭터 선택은 DB에 계정별 저장합니다.

## 팀 결과 수신 → 검수 → 분석 → 상담

1. 관리자/담당 교사가 분류 JSON과 반·숙제 제목·분석 월을 등록합니다. 첨부 규약의 `formatVersion=1.x`, `rubricVersion=1.0`, 수학 11개·영어 14개 태그를 검증합니다.
2. **전달받은 결과 등록·수정**에서 팀 채점 결과 JSON을 업로드합니다. 아래 형식은 이 서비스의 수신 어댑터 계약입니다. 팀의 최종 출력 형식이 확정됐다는 뜻은 아닙니다. 쪽수와 인쇄 번호로 분류 문항에 연결합니다.
3. 업로드만으로 공개하지 않습니다. 담당자가 결과를 검수·확정하면 영역/유형별 분석과 월별 합계가 저장됩니다.
4. RAG는 최신 분류에 맞는 확정 결과만 사용합니다. 수정·재분류·철회 시 이전 분석을 상담에서 제외하고, 재검수 후 새 분석 버전을 발행합니다.
5. 분류 버전·결과 버전·검수 사유·분석 원본을 DB에 보존합니다. 상담 인용에서 실제 숙제와 문항 결과로 이동합니다.

```json
{
  "formatVersion": "1.0",
  "assignmentId": "team-homework-01",
  "studentId": "TA_STU_001",
  "classificationRevision": 1,
  "results": [
    { "page": 42, "displayNumber": "1", "outcome": "correct" },
    { "page": 43, "displayNumber": "1", "outcome": "incorrect" }
  ]
}
```

`outcome`은 `correct`, `incorrect`, `unknown`입니다. 누락 문항은 미확인이며 정답으로 추정하지 않습니다. 다른 숙제/학생/분류 버전, 없는 좌표, 중복 좌표를 거부합니다. 첨부 분류 JSON의 `agreement`는 분류 일치 횟수이며 학생 점수가 아닙니다.

인증된 관리자/교사 세션에서 `POST /learning`에 `action=results-import`, `assignmentId`, `studentId`, `classificationRevision`, 현재 결과 `revision`(첫 등록 0), `reason`, `resultsFile`을 multipart로 보낼 수 있습니다. 파일 대신 `gradedResults` JSON 문자열도 받습니다. 기존 세션·동일 출처·담당 반 검사와 버전 충돌 검사를 모두 적용합니다. 외부 시스템 전용 서비스 계정/토큰·웹훅은 아직 없으며 팀 서버 연결 시 확정할 항목입니다. OCR·자동 정오답 판정·자동 태그 분류를 수신 기능에 추가하지 않았습니다.

수동 오답 입력은 검수 보조로 보존했습니다. 이 경로에서는 명시적으로 전체 확인을 선택했을 때만 미입력 문항을 정답으로 처리합니다. 팀 결과 JSON 수신에는 이 추론을 적용하지 않습니다.

### 분석 기준과 권한

- `itemStatus=classified`, 태그 `status=adopted`만 집계합니다. 참고/보류 태그·미분류·결과 미확인 문항은 정답률 분모에서 제외하고 제외 수를 따로 표시합니다.
- 태그마다 문항을 한 번, 같은 영역 내에서는 중복 없이 한 번 셉니다. 전체 정답률은 문항 기준이며 태그별 수의 합이 아닙니다. 월별 합산도 문항 수로 가중합니다.
- 정답률은 `정답 수 / 집계 가능한 확인 문항 수 × 100`입니다. 분모 0이면 정답률 사실을 만들지 않습니다. 수학 세부 유형은 참고용입니다.
- 혼합 수학/영어 반에 분류 자료를 등록하거나, 이미 분석이 있는 반의 과목을 변경하지 못하게 합니다.
- 학생은 주 소속 반과 추가 수강 반을 가질 수 있습니다. 등록·종료 이력을 저장합니다. 교사는 현재 담당하는 반의 현재 수강생 자료만 봅니다. 다른 과목 반의 개인 자료를 같은 학생이라는 이유로 읽지 못합니다.
- 학생 본인과 연결 보호자는 반 이동 후에도 자신의 과거 확정 분석을 조회할 수 있습니다. 과거 반 자료의 공개 범위 전체를 넓히지 않습니다. 현재 소속이 아닌 반의 결과를 새로 쓰는 것은 차단합니다.

## 휴·보강 및 시간표 개정

팀 `feat/makeup-schedule-rag-doc`의 `ba816647af3bfca104609acc0cb9c0c03ac1ed29`까지 내용을 가져와 SQLite·권한·운영 상담에 연결했습니다. Git 원본 main은 변경하지 않습니다.

- 원장 확정 전 일정은 상담에서 제외합니다. 반 전체 휴강과 개인 결석을 구분하고, 보강 미정/복수 결석/날짜 불일치는 확인 또는 부분 답변으로 처리합니다.
- 정규 수업과 보강의 강사·교실·원생·시간·학원 전체 동시 인원을 검사합니다. 여러 교실 인원을 합산하며 이어지는 수업은 중복 합산하지 않습니다.
- 공통 공지와 팀 일정의 중복, 상담 예약과 정규/보강 강사 시간 충돌을 검사합니다. 빈 보강 변경을 취소로 처리하지 않으며, 휴강 철회로 복구될 수업과 보강 충돌도 확인합니다.
- 기존 시간표 변경에는 적용일이 필요합니다. 오늘 이전 또는 마지막 개정판보다 이른 변경은 거부합니다. 이전 기간을 보존하고 휴·보강에는 등록 당시 수업 정보를 저장하므로 원래 시각·길이·인용이 바뀌지 않습니다.
- 안내문은 DB 발송 대기함에 저장합니다. 실제 문자·알림톡은 발송하지 않습니다. 모든 운영 반을 등록해야 전체 자원 충돌을 확인할 수 있습니다.

## Gemini와 이후 네이버 AI 전환

현재 로컬 `.env.local`은 Gemini로 연결했습니다. 키는 서버에서만 읽고 Git·화면·로그에 포함하지 않습니다.

```dotenv
RAG_GENERATION_PROVIDER=gemini
RAG_GEMINI_MODEL=gemini-3.5-flash-lite
RAG_GEMINI_API_KEY=발급받은_키
RAG_GEMINI_ALLOW_PERSONAL_DATA=false
RAG_GENERATION_DAILY_CALL_LIMIT=100
```

가상 학습 자료로 실제 연동을 검증한 로컬 DB만 `RAG_GEMINI_ALLOW_PERSONAL_DATA=true`를 사용했습니다. 저장소 예제는 false입니다. 실제 학생 자료를 외부로 처리하는 설정은 운영 정책에 맞춰 별도로 지정해야 합니다.

확정 정답률·수강료·일정 조회는 생성 호출 없이 답합니다. 근거가 있는 학습 방향 요약에 Gemini를 사용하고, 수치·출처·다른 학생 ID·근거 없는 원인 단정을 검사합니다. 생성이 실패하거나 검증을 통과하지 않으면 담당자 확인으로 전환합니다. 근거가 없는데 AI로 답을 채우는 구조가 아닙니다.

한 서버가 공급자 인스턴스와 호출 한도를 공유합니다. 직접 호출에서도 한도·장애 차단을 검사합니다. UTC 하루 기준이며 **프로세스 재시작 시 카운터는 초기화**됩니다. 공급자 계정의 과금 한도와 동일한 장치가 아닙니다.

`npm run ai:check`는 고정 가상 안내 1건을 실제 API로 보내고 출처·시각을 검사합니다. 이후 `RAG_GENERATION_PROVIDER=clova`, `RAG_CLOVA_API_KEY`, 계정에서 사용 가능한 `RAG_CLOVA_MODEL`, `RAG_CLOVA_ALLOW_PERSONAL_DATA`를 설정하고 서버를 재시작하면 같은 어댑터 계약으로 전환합니다. 실패 시 다른 공급자로 자동 재전송하지 않습니다. 이번에는 실제 CLOVA 호출을 검증하지 않았습니다.

공급자 연결은 [Gemini 공식 호환 API 문서](https://ai.google.dev/gemini-api/docs/openai)와 [CLOVA Studio 공식 호환 API 문서](https://api.ncloud-docs.com/docs/clovastudio-openaicompatibility)를 기준으로 확인했습니다.

## 2026-11-13 통합 검증

`npm run check`(린트·타입·서식)와 `npm run build`를 통과했습니다. 기존 전체 625개에서 통합 회귀 7개를 추가해 **632/632 통과**, 실패·건너뜀 0개입니다. 새 항목은 결과 JSON 수신/누락/중복/대상·버전, 복수 반 권한과 이동 이력, 시간표 적용일·원본 시각·보강 길이, 공지 충돌, 자료 필터/미리보기 격리, 통합 경로/계정별 캐릭터/동일 출처 검사, 공급자별 데이터 허용/호출 한도입니다. 기존 테스트를 삭제·비활성화하지 않았습니다. 반 이동 시 본인 과거 분석도 숨기던 테스트 한 건은 변경된 요구사항에 따라 본인 조회 허용·이전 교사 차단·과거 반 쓰기 차단으로 확장했습니다. 평가 정답 파일은 바꾸지 않았습니다.

권한 위반은 평가상 0건입니다. 결과는 `.local/service-eval/service-final/`, 문항별 비교는 `.local/service-eval/comparison.json`, 테스트 로그는 `.local/service-tests-final.log`에 보존했습니다. OCR을 끈 첫 시도는 스캔 PDF를 읽을 수 없어 중단됐고, 이후 OCR을 켜 동일 조건으로 완료했습니다. 새 독립 정확도나 실제 Gemini 정확도 95%를 의미하지 않습니다.

브라우저에서는 달력의 정규/휴강/보강 표시, 목업 캐릭터 3종과 계정별 선택, 캐릭터 변경 중 질문 초안 유지, 모바일 가로 넘침을 확인했습니다. 원본 목업의 HTML/CSS·자산을 대조했으며 픽셀 단위 복제 검증은 아닙니다.

## Cloudflare 데모

[AXR 가상 학원](https://axr-academy-hosted.pogoo.workers.dev/login)은 Cloudflare Workers에서 요청을 받고 Durable Objects에서 앱과 SQLite를 실행합니다. 기존 Cloudflare 주소는 새 주소로 연결됩니다. 클라우드 데모는 저장소에 있는 가상 학원 자료로 초기화하며, 로컬 데모 DB와 별도로 저장합니다.

저장소 루트에서 아래 순서로 배포합니다. 데모 Worker에 `AXR_HOSTED_DEMO_PASSWORD`와 `RAG_GEMINI_API_KEY`를 시크릿으로 등록합니다. `RAG_GEMINI_MODEL`로 모델을 지정할 수 있습니다.

```sh
node deploy/cloudflare/prepare-hosted.mjs
wrangler deploy --config deploy/cloudflare/wrangler.gemini.jsonc
wrangler deploy --config deploy/cloudflare/wrangler.hosted.jsonc
```

데모는 미국 동부 배치 힌트를 설정한 비공개 Worker에 서비스 바인딩으로 Gemini 요청을 보냅니다. 관리자 계정으로 로그인한 뒤 [설정](https://axr-academy-hosted.pogoo.workers.dev/settings)의 **가상 안내로 연결 확인**을 누르면 실제 모델이 운영 시작 시각을 14시로 답하고 가상 안내를 인용했는지 확인합니다. 공개 데모에서는 학생 자료의 외부 AI 전송을 차단합니다. 확정 수치와 일정은 저장된 근거를 조회해 답합니다.

클라우드 데모의 문서 업로드는 최대 5MB입니다. 텍스트 PDF를 파싱하고 원본을 내려받을 수 있습니다.

## 남은 운영 연결

로컬 SQLite·가상 계정에서 구현·검증했습니다. 실제 팀 채점/분류 산출물 연결, 외부 인증·운영 DB/호스팅, 문자·알림톡 발송, 실제 CLOVA 계정 검증은 외부 시스템/자료가 필요합니다. 운영 업로드는 텍스트 PDF·DOCX·HWPX·TXT·Markdown을 읽습니다. 스캔 전용 PDF의 운영 업로드 OCR은 연결하지 않았고 확인된 텍스트를 별도로 입력합니다. RAG 자체 OCR과 원본 평가 경로는 보존했습니다. AI로 학습 원인·태도·미래 성적을 임의 진단하지 않습니다.
