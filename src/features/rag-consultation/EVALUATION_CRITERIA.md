## 2. 평가 항목과 문항을 선정하는 기준

상담에서 요청한 정보와 그 정보가 틀리기 쉬운 조건을 짝지어 고릅니다. 답변 가능 문항은 대상·시점·단위와 원본 위치를 지정할 수 있어야 합니다. 유사 반, 이전 요금, 다른 행사 회차, 미승인 초안, 권한 밖 리포트를 함께 두어 관련 문서 중 올바른 근거를 선택하는지 확인합니다. 답변이 어려운 문항은 필요한 사실의 부재, 충돌 또는 접근 불가 조건을 입력에 고정합니다.

| 평가 항목           | 선정 기준                                                                                                                        | 실패 예시                                     |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------- |
| 비용·강사·시간표    | 반별 금액·단위, 강사, 요일·시각·교실을 묻습니다. 학교급이 다른 유사 반, 복수 반, 열 순서가 다른 표, 현행·미래 요금을 포함합니다. | 금액은 맞지만 다른 반·기간·열을 인용함        |
| 복합 질문·부분 응답 | 비용과 강사 또는 일정처럼 독립된 두 정보를 한 번에 묻습니다. 두 근거가 있는 경우와 일부만 있는 경우를 둡니다.                    | 확인된 비용에 다른 요일 시간표를 붙임         |
| 승인 리포트와 권한  | 학생·월·단원을 지정해 정답률 또는 기록된 학습 방향을 묻습니다. 다른 학생, 미공개 월, 조회 권한 없는 계정을 포함합니다.           | 다른 학생이나 다른 월의 결과로 대체함         |
| 행사와 회차         | 제목이 같은 다른 날짜, 날짜·요일 충돌, 시각과 장소가 서로 다른 행·문단에 있는 공지를 넣습니다.                                   | 다른 회차의 시각과 장소를 결합함              |
| 문서 파싱과 인용    | 원본을 등록 경로로 파싱해 검색합니다. 표의 문서·쪽·절·행·열이나 스캔의 쪽·문단과 인용 내용을 확인합니다.                         | 값을 잘못 읽거나 맞는 값에 다른 문단을 인용함 |

입력은 문항 ID, 계정, 질문, 조회 기준 시각과 필요한 경우 이전 대화·세션, API 상태를 포함합니다. 질문 한 건이 정답률의 분모 1건입니다. 복합 질문은 모든 필수 슬롯이 맞아야 그 문항을 통과합니다. 부분 응답을 기대하는 문항은 확인 가능한 사실과 누락 목록을 모두 맞혀야 통과합니다.

## 3. 정답과 근거의 기입 기준

- `cases.jsonl`은 평가 입력과 기존 채점에 쓰는 기대 상태, 허용 출처, 필수·금지 문자열, 호출 상한을 저장합니다.
- `gold-v4.json`은 문항 ID별로 `status`, 필수 `slots`, 허용 안내 문장 `contextLines`, `maxGenerationCalls`를 둡니다. 필요한 경우 `missingFields`, `clarifyOptions`, `handoffReason`, `forbidden`을 지정합니다.
- 슬롯마다 대상과 값을 묶는 `claim`, 허용 답변 줄 `answerSpans`, 근거 묶음 `evidence`를 적습니다. 각 근거에는 `sourceId`, 위치·사실 ID·청크 ID 중 하나 이상, 필수 원문 `witness`를 적습니다. 표는 `columns`, 인용 원문 전체 대조가 필요한 경우는 `exactWitness`를 지정합니다.
- `evidence: [[A, B], [C]]`는 A와 B를 모두 인용하거나 C를 인용하면 해당 슬롯의 근거 조건을 충족한다는 뜻입니다. 비용과 시간표처럼 별개의 요청은 각각 슬롯으로 둡니다.
- 정답의 허용 표현은 대상, 기간, 수치, 단위, 조건을 유지하는 줄로 제한합니다. 누락 항목과 보류 사유도 요청 범위와 승인 자료를 기준으로 적습니다.

세트 7의 `AUTO7_SCHOOL_1-007`은 “초3 해시계반 월 수강료 및 월요일 시간표를 확인해 주세요.”입니다. 수강료 슬롯은 **213,190원**과 요금표 1행의 반·월 수강료 열, 시간표 슬롯은 **월요일 13:07~14:12, 412호**와 시간표 1행의 반·요일·시작·종료·교실 열을 요구합니다. 같은 반의 목요일 시간표를 묻는 `-008`은 비용만 확인되므로 `partial`과 `missingFields: ["수업 시간표"]`가 정답입니다. 월요일 시각이나 교실을 붙이면 금지값 위반입니다. [라벨 스키마](server/eval/holdout-review.ts)

## 4. 채점과 통과 조건

### 채점 버전

| 버전           | 판정 방식                                                                                                                                                                                                                                                                  |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 기존 채점      | 기대 상태, 필수·금지 문자열, 생성 예산, 안전 검사로 채점합니다. 허용 출처 목록에서 하나를 인용해도 출처 조건을 통과할 수 있습니다. 일부 구어체 평가는 비답변 상태를 묶어 비교합니다.                                                                                       |
| 슬롯 v2        | 사실별 필수 표현이 같은 답변 줄에 있는지 확인하고, 인용 묶음과 지정 위치·열을 대조합니다.                                                                                                                                                                                  |
| 슬롯 v3        | 허용 답변 구간과 실제 선택한 근거의 원문·위치를 추가로 대조합니다.                                                                                                                                                                                                         |
| 슬롯 v4 / v4.1 | 정규화한 답변 전체 줄과 실제 공개 인용을 확인합니다. 필수 슬롯을 모두 만족해야 하며 허용 목록에 없는 답변 줄과 근거가 없는 인용은 실패입니다. 출처 ID, 위치, 지정된 열 전체를 검사합니다. `exactWitness`가 있으면 NFC와 연속 공백을 정리한 뒤 인용 원문 전체를 비교합니다. |

v4.1은 공개 API의 `abstained`에 `handoff.needed: true`가 붙는 계약을 반영합니다. 정답에 사유가 있으면 실제 사유도 같아야 합니다. `handoff` 상태의 연결 정보는 v4에서도 검사합니다. 두 버전의 결과는 각각 기록합니다. [v2](server/eval/scoring-v2.ts) · [v3](server/eval/scoring-v3.ts) · [v4 및 v4.1](server/eval/scoring-v4.ts)

| 기대 상태   | 엄격 채점에서 확인하는 내용                                                 |
| ----------- | --------------------------------------------------------------------------- |
| `answered`  | 요청한 사실의 모든 슬롯과 올바른 인용                                       |
| `partial`   | 확인 가능한 사실과 인용, 누락 필드의 정확한 목록                            |
| `abstained` | 근거 부족·충돌 등에 따른 보류, 인용 없음, v4.1의 연결 필요 정보와 지정 사유 |
| `clarify`   | 기대한 선택지의 정확한 목록, 인용 없음                                      |
| `denied`    | 권한 제한 응답, 인용 없음                                                   |
| `handoff`   | 담당자 연결 필요 정보와 지정 사유, 인용 없음                                |

안전 검사는 관측된 검색 청크·사실, 생성 입력, 최종 인용에서 사용한 출처를 확인합니다. 미등록 출처, 다른 학원, 미승인 자료, 계정의 학생·반·역할 권한 밖 자료를 위반으로 기록합니다. 답변에 권한 밖 학생 이름·별칭이 나타나거나 생성 입력에서 해당 학생 이름이 관측되는 경우도 집계합니다. 위반 0건은 해당 평가 입력과 관측 경로에 대한 결과입니다. [안전 검사](server/eval/harness.ts) · [공개 응답 계약](contract.ts)

### 95% 판정과 보조 지표

두 목표 판정의 공통 조건은 슬롯 v4 계열 채점, 학원 3곳 이상, 300문항 이상, 정답 `ceil(전체 문항 수 × 0.95)` 이상, 알려진 학원 ID·문항 ID·문서 중복 없음, 안전 위반 0건입니다. 정상 API 문항에서 Mock 생성이 사용되면 목표 판정을 통과할 수 없습니다. 300문항에서는 **285개 이상**이 필요합니다. 자동 모드는 `--automated-holdout --reject-known-overlap`을 사용합니다. 사람 검수 독립 모드는 원본·정답·코드 해시와 검수 문항 ID가 일치하는 `--review-manifest`도 요구합니다.

중복 점검은 등록된 학원·문항 ID와 파일·본문 지문을 비교합니다. 정규화한 같은 질문·대화도 별도 목록으로 기록합니다. 같은 질문·대화의 존재만으로 자동 판정이 실패하지는 않습니다. 사람 검수 모드에서는 반복 질문 ID도 검수 기록에 포함해야 합니다. 형식과 해시 검사는 정답 문장의 의미나 실제 운영의 문항 분포까지 검증하지 않습니다. 요약의 `automatedGate`는 점수와 위반 수의 간이 확인이며 모드별 목표 판정은 `automatedHoldoutGate` 또는 `independentGate`에서 확인합니다. [중복 검사](server/eval/holdout-overlap.ts) · [통과 조건](server/eval/holdout-review.ts)

| 지표             | 분자와 분모                                                                            |
| ---------------- | -------------------------------------------------------------------------------------- |
| 엄격 정답률      | 모든 조건을 통과한 문항 / 전체 주석 문항                                               |
| 잘못된 보류율    | 기대 상태가 `answered`·`partial`인데 실제 응답이 두 상태 밖인 문항 / 답변 가능 문항    |
| 잘못된 응답률    | 기대 상태가 두 답변 가능 상태 밖인데 실제 `answered`·`partial`인 문항 / 답변 불가 문항 |
| 기존 인용 정확도 | 답변 가능 문항에 실제 답변을 낸 경우 중 기존 출처 기준을 만족한 문항 / 그 실제 답변 수 |
| 안전과 비용      | 위반 수, 생성 호출 수, 실제 HTTP 요청 수, 쿼리 p50·p95, 색인 시간·CPU·RSS를 별도 확인  |

요약의 기본 범주별 점수와 오류 단계는 기존 채점에서 계산합니다. 엄격 채점의 범주별 실패는 문항 ID로 `__slot-v4.1.json`을 결합해 확인합니다. 기존 `goldRetrieved`는 기대 출처 중 하나가 관측됐는지를 나타냅니다. 복합 질문의 모든 근거가 확보됐는지는 슬롯 단위로 확인합니다. [요약 산식](server/eval/harness.ts)

## 5. 최신 96%의 해석과 재현

| 세트 7 최초 실행           | 기존 채점 |           슬롯 v4.1 | 합성 자동 판정 |
| -------------------------- | --------: | ------------------: | -------------- |
| 계획 엔진 `engine-planned` |   288/300 | **288/300 (96.0%)** | 통과           |
| 기본 엔진 `engine`         |   264/300 |     144/300 (48.0%) | 기준 미달      |

계획 엔진은 학원별로 96/100이었습니다. 엄격 채점 오답 12개는 모두 스캔 행사 문항이었으며 해당 범주는 0/12였습니다. 관측된 안전 위반과 외부 생성 호출은 각각 0건입니다. 세트 7은 사람 검수 없이 구성한 합성 평가입니다. 실제 학원의 문의 분포와 Gemini 생성 품질은 별도 평가 범위입니다.

**정답 라벨에서 확인한 한계.** 현행 비용을 묻는 90문항의 108개 슬롯에 “2026년 12월 1일 적용”이라는 허용 대체 문장이 있습니다. 해당 현행 요금 원본은 12월 1일 직전에 만료되므로 그 대체 문장은 시점 조건과 맞지 않습니다. 최초 실행에서 계획 엔진이 이 문장을 실제로 쓴 사례는 0개였습니다. 라벨과 점수는 그대로 두고 원본의 유효 기간과 실제 응답을 대조했습니다.

세트 7의 원본과 문항은 로컬 `.git/rag-validation/automated-holdout/seed-7/inputs/`에 있습니다. 같은 상위 폴더에 `gold-v4.json`과 `frozen.json`, 첫 실행 결과 `runs/seed-7-first-pass/`를 보관합니다. 아래 명령은 해당 자료가 있는 AXR 작업 폴더에서 재현할 수 있습니다. `--label`은 새 이름을 사용합니다.

```powershell
$runner = 'src/features/rag-consultation/server/eval/run-eval.ts'
$caseRoot = '.git/rag-validation/automated-holdout/seed-7'
$env:RAG_MODEL_CACHE_DIR = (Resolve-Path "$caseRoot/cache").Path
$evalArgs = @(
  '--automated-holdout', '--holdout-root', "$caseRoot/inputs",
  '--gold-v4', "$caseRoot/gold-v4.json", '--contract-state',
  '--reject-known-overlap'
)
node --disable-warning=MODULE_TYPELESS_PACKAGE_JSON $runner @evalArgs --holdout-preflight
node --disable-warning=MODULE_TYPELESS_PACKAGE_JSON $runner @evalArgs --out "$caseRoot/runs" --label seed-7-recheck --variant engine,engine-planned
```

사전 점검은 문항과 라벨의 1:1 대응, 인용 자료의 승인 상태와 계정의 접근 권한을 확인합니다. 실행 중 입력·정답·평가 코드가 바뀌면 실패합니다. `summary.json`에서 해시와 판정, 문항별 JSON·CSV에서 실제 응답, `__slot-v4.1.json`에서 엄격 채점의 상세 검사 결과를 확인합니다. [최초 실행과 오류 분석](TEST_REPORT.md#스캔-행사-근거와-새-합성-평가-최초-실행)
