# 4. 파일 기반 RAG 상담 (rag-consultation)

학원 정보 파일과 원생별 분석 결과를 근거로 상담 답변을 만들고, 근거를 인용하며, 자료로 답할 수 없으면 지어내지 않고 보류하거나 담당자 연결 상태를 돌려주는 **독립 서버 모듈**입니다.
3·5·7·8·9번 기능이 아직 없어도 합성 데이터와 mock 어댑터로 전체 흐름을 실행하고 테스트할 수 있습니다.

> ⚠️ 모든 테스트 데이터는 완전한 가상 데이터입니다. 합성 데이터에서 테스트가 통과했다고 실제 원생 개인정보를 다루는 운영 환경이 안전하다는 뜻은 아닙니다. 외부 생성 API 연동도 **검증되지 않았습니다**(키·공급자 미선정).

### 기술 선택(최소 구성)

- **새 런타임 의존성 0개.** 이미 설치된 `zod`(입력·출력 검증)와 `axios`(클라이언트)만 사용합니다.
- **테스트**: Node 24 내장 `node:test` + TypeScript 타입 제거 실행(별도 테스트 프레임워크를 설치하지 않음). 이를 위해 `tsconfig.json` 에 `allowImportingTsExtensions` 를 켰습니다(`noEmit` 환경이라 빌드에는 영향 없음).
- **저장소**: 메모리 구현(`InMemoryRagStore`). 운영 DB 가 정해지면 같은 포트(`ApprovedFactsPort`, `RagDocumentsPort`)로 교체합니다.
- **검색**: 권한 필터를 통과한 후보 안에서만 계산하는 BM25(단어 + 한글 2-gram)가 기본값입니다.
  - 기술 조사 문서의 검색 기법(Kiwi 형태소 BM25, multilingual-e5-small 임베딩, Hybrid RRF, bge-reranker-v2-m3 재정렬, 점수 기반 보류)은 `InMemoryRagStore({ ranker })` 로 바꿔 끼울 수 있습니다(`server/retrieval/rankers.ts`, `confidence.ts`).
  - 모델을 쓰는 기법은 **개발·평가 전용**입니다(`kiwi-nlp`, `@huggingface/transformers` 는 devDependencies). 서비스 기본 경로는 모델을 불러오지 않습니다.

## 2. 구조

```text
src/features/rag-consultation/
  contract.ts            # 공개 계약(RagAnswer, 요청 스키마) — 클라이언트에서 import 가능
  api/rag-client.ts      # 웹/Capacitor 공용 상담 API 클라이언트(axios)
  server/                # ⚠️ 서버 전용(클라이언트에서 import 금지 — 테스트로 강제)
    index.ts             # 서버 공개 진입점
    service.ts           # 오케스트레이션: 보안 차단 → 대상 확정 → 조회/검색 → 충분성 → 0/1회 생성 → 사후 검사
    ports.ts             # 다른 기능과 연결할 포트(어댑터 경계)
    types.ts, config.ts  # 도메인 타입, 운영 사전(주제·단원·지시어)·정책 상수
    query/               # 규칙 기반 질의 해석(학생·반·기간·부정/비교 연산자), 대상 학생 확정
    answer/              # 학원 정보·학습 분석·학습 방향(생성) 답변, 표기, 숫자/식별자 사후 검사
    retrieval/           # 검색 전 권한 판정, BM25
    ingest/              # 표 행 보존 청크, 문서·사실 검증, 프롬프트 인젝션 표시
    store/               # 메모리 저장소(revision 전환·멱등·순서 보장), 색인 작업 큐(재시도·백오프)
    generation/          # disabled / mock / 회로 차단기 / OpenAI 호환 어댑터, 프롬프트, 출력 검증
    http/                # 표준 Fetch 핸들러(query·index·jobs), 사용자별 호출 제한
    events.ts            # onDocumentChanged, onAnalysisReportPublished
    adapters/fixture/    # 합성 평가자료·가상 학원 자료 → 저장소·카탈로그·모의 세션(테스트·로컬 전용)
    adapters/memory/     # 대화 상태·담당자 연결 초안·시계·로거(메모리)
    dev/dev-server.ts    # 로컬 개발 서버(127.0.0.1, 합성 데이터)
    __fixtures__/axr-synthetic-v1/  # 제공된 평가자료 원본(수정하지 않음)
    __fixtures__/academies-v1/      # 가상 학원 3곳 현실형 테스트 자료(FORMAT.md, validate_academies.py)
    __tests__/           # 회귀·보안·변경 반영·생성 장애·HTTP·단위 테스트
```

질문 처리 흐름(생성 API 호출은 질문당 최대 1회):

```text
요청 검증 → 서버 세션 → RagAccessScope
  → 질의 해석(규칙): 학생(이름·별칭·형제 지칭)/반/단원/유형/기간(이번 주·내일 포함)/금액/부정·비교·이전 연산자, 보안 플래그
  → 보안 차단: 타 학원 언급 · 전체 학생 요청 · 공유/권한 변경 · 권한 밖 학생(코드·이름) → denied
               출처 위조·"근거 없이" 요청 → abstained
  → 학원 정보: 정형 사실(수강료·교재비·시간표·강사·모집 현황·휴보강·보강 규정) 코드 조회 → 템플릿(0회)
              시설 등 속성: 승인 문서에 그 속성이 "있다"는 문장/값이 있을 때만 답변
              환불·셔틀·운영 시간 등: 운영 문서의 해당 절을 찾아 인용(0회)
  → 학습 분석: 대상 학생 확정(모호하면 clarify) → 확정 단원·유형·전체 정답률, 취약 영역, 기간/학생/단원 비교, 누적 추이(0회)
              근거 숙제·채점 수정본 표시, 원인·태도·예측·오귀속 요청 → abstained
  → 학습 방향: 리포트의 강사 확인 학습 방향이 있으면 인용(0회)
              없으면 공급자 가용성·개인정보 전송 승인 확인 → 가명 처리한 확정 사실로 1회 생성 → 출력 검증
              실패·장애 → handoff(재시도·공급자 자동 전환 없음)
  → 사후 검사: 인용 재조회(권한·승인·유효 버전), 답변 숫자 ⊆ 근거·계산값, 다른 학생 코드·이름 없음
```

## 4. API 계약

| 처리             | 경로                         | 권한                                                                |
| ---------------- | ---------------------------- | ------------------------------------------------------------------- |
| 상담             | `POST {base}/query`          | 서버 세션 필수(없으면 401). 사용자별 호출 제한(429 + `Retry-After`) |
| 문서 등록·재색인 | `POST {base}/index`          | `admin` 이고 문서의 학원이 세션 학원과 같을 때만                    |
| 색인 상태        | `GET {base}/index/jobs/{id}` | 같은 학원 `admin`. 다른 학원 작업은 404(존재 여부 비노출)           |

요청: `{ "question": string(1~500), "studentId"?: string, "conversationId"?: string }`.
`studentId` 는 대상 **힌트**일 뿐이며, `role`·`academyId`·`allowedStudentIds` 를 본문에 넣어도 무시합니다(테스트로 확인).

응답(`RagAnswer`): `status`, `answer`, `citations[{sourceId, documentId, title, location, revision}]`, `missingFields?`, `clarifyOptions?`, `handoff?{needed, reasonCode}`, `requestId`. 내부 trace 는 응답에 넣지 않습니다.

| status      | 의미                                                                             |
| ----------- | -------------------------------------------------------------------------------- |
| `answered`  | 필수 근거가 충분하고 인용·숫자 검사 통과                                         |
| `partial`   | 일부만 확인됨. `missingFields` 에 미확인 항목                                    |
| `abstained` | 자료 없음·충돌·원인/예측 요청 등. `handoff.needed=true`(연결 가능)               |
| `clarify`   | 대상 학생이 모호함. `clarifyOptions` 에서 선택                                   |
| `denied`    | 권한 범위 밖. 자료 존재 여부·다른 학생 정보를 드러내지 않는 동일 문구            |
| `handoff`   | 생성 필요 상담인데 공급자 장애·미승인·출력 검증 실패. `HandoffPort` 로 초안 생성 |

## 8. 남은 위험·결정 필요 사항

1. **서버 실행 위치 미정**: 정적 export 앱이라 별도 백엔드가 필요합니다. CORS·쿠키/토큰 규칙도 그 백엔드에서 정해야 합니다.
2. **생성 공급자 미선정**: HyperCLOVA X 대회 요건·무료 크레딧 미확인. Gemini 무료 API 는 미성년 대상 서비스 조항 때문에 기본 후보에서 제외(기술 조사 16.2). 공급자를 정하기 전에는 `RAG_GENERATION_ALLOW_PERSONAL_DATA=false` 를 유지해야 합니다.
3. **학생 지칭의 한계**: 권한 밖 학생 탐지는 서버 원생 명부(이름·별칭)와 학생 코드 패턴에 의존합니다. 명부에 없는 별명이나 오타로 부르면 탐지되지 않고, 자녀가 한 명이면 그 자녀로 해석됩니다. 그래서 답변에 대상 이름을 항상 넣어 잘못된 귀속이 드러나게 했습니다. 2글자 이름은 앞뒤가 다른 단어의 일부가 아닐 때만 인정하므로 흔한 낱말과 겹치는 이름은 운영 데이터로 확인이 필요합니다.
4. **규칙 기반 해석의 범위**: 운영 사전(`config.ts`)에 없는 표현은 보류 쪽으로 처리됩니다(과잉 보류 가능). 가상 학원 90건에서도 처음에는 표현 차이로 다수가 실패했으므로, 실제 질의 로그로 사전을 계속 확장해야 합니다.
5. **메모리 구현**: 저장소·작업 큐·호출 제한·대화 상태는 단일 프로세스 메모리입니다. 운영에서는 DB 트랜잭션(문서 변경 + 작업 행 동시 저장)과 공유 저장소가 필요합니다.
6. **파일 형식**: HWP/HWPX/PDF/스캔 OCR 은 지원하지 않습니다. 파싱 실패·신뢰도 부족을 관리자 검수 상태로 두는 흐름은 7번 기능과 함께 정해야 합니다.
7. **법·약관 검토**: 미성년 원생 데이터의 외부 전송·국외 이전·보존 정책은 법무·개인정보 담당 검토가 필요합니다.
