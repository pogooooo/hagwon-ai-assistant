- 모든 학원·원생·금액은 가상 데이터입니다. 수치는 이 브랜치에서 실제로 실행한 결과이며, 재현 명령과 결과 파일은 [TEST_REPORT.md](TEST_REPORT.md) 에 있습니다.

## 요약

1. **최종 상담 정확도(미공개 평가 393문항, 학원 3곳)**: 기본 BM25 RAG **19.3%** → 개선 전 엔진 **44.8%(176/393)** → 새 엔진 **52.7%(207/393)**. 1차 목표 85%에는 **미달**했습니다. 권한 위반·미승인 자료 사용은 0건입니다.
   - 개발 학원(153문항)에서는 개선 전 43.1% → 78.4% 였습니다. 미공개 평가와의 차이(약 26%p)는 개선 규칙이 개발 학원 표현에 맞춰져 일반화가 덜 됐다는 뜻입니다(4장).
2. **문서 파싱**: PDF(표·2단·여러 쪽 표), 스캔 PDF(OCR·회전), DOCX·HWPX·TXT 를 원본 그대로 파싱해 쪽·절·표·행 위치로 인용합니다. 업로드 → 색인 → 질문 → 쪽 인용을 통합 테스트로 확인했습니다.
3. **검색 기술**: e5 하이브리드와 bge 재정렬은 미공개 평가에서 정확도를 올리지 못했고(모두 207/393) 메모리·지연만 늘었습니다. 기본 경로는 **BM25 + 규칙 우선 + 검색 근거 라우팅**으로 두고, 모델 검색기는 개발·평가 전용으로 남겼습니다.
4. **실제 생성 API 는 검증하지 않았습니다.** 모든 결과는 정형 조회·문서 인용(생성 0회)과 mock 생성(학습 방향 일부, 미공개 평가에서 5회)입니다. 실제 LLM 성능으로 해석하면 안 됩니다.

### 3.2 질문 해석·근거 선택·바인딩·충분성(4단계)

규칙을 평가 문항에 맞춘 유사어로 늘리지 않고, 국어 문법(의문사·조사·날짜 표현)과 문서 구조(표 머리글·절 제목·적용 기간)를 쓰는 일반 규칙으로 고쳤습니다.

| 문제(3단계 오류 분리에서 확인)                   | 개선                                                                                                                                  | 파일                                        |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------- |
| 규칙이 주제를 못 찾거나 의문사로만 찾음          | **계층적 라우팅**: 규칙 우선, 약하면 사용자 원문 검색 → 가장 믿을 만한 근거의 자리(정형 사실·리포트·문서)로 경로 결정                 | `answer/evidence.ts`, `service.ts`          |
| 재정렬 모델이 엔진 키워드 묶음을 받음            | 검색 포트에 `question`(원문) 추가: 의미 검색·재정렬은 원문, BM25 는 키워드                                                            | `ports.ts`, `retrieval/rankers.ts`          |
| 답에 질문이 요구한 값이 없음                     | 의문사 → 답 유형(금액·날짜·시각·마감·시작·인원·장소·사람·비율) 충분성 검사, 근거 묶음 선택에도 사용                                   | `answer/evidence.ts`                        |
| 반을 정하지 않은 질문에 전체 반 목록             | 근거가 다른 문서면 그 문서로 답, 의문사로만 잡히고 근거도 없으면 보류                                                                 | `service.ts`                                |
| 같은 표의 다른 행·반·요일 값                     | 반 이름 줄임말(학생 수강 반 우선, 조사 허용), 행 유사 바인딩(학년·핵심 이름), 격자 시간표의 요일 칸·칸 안 요일별 시각, 행의 적용 기간 | `query/parse-query.ts`, `answer/info.ts`    |
| 같은 사실 유형의 학원별 이름(교재비/실험 재료비) | 원문 표 머리글을 비용 이름으로 쓰고, 질문한 비용이 자료의 다른 절이면 문서 근거로                                                     | `answer/info.ts`                            |
| 휴강·보강 연결 오류                              | 같은 공지 안 휴강·보강을 날짜순으로 짝지음                                                                                            | `answer/info.ts`                            |
| 날짜 해석                                        | 날만 말한 날짜(“21일부터”), 미래 달 질문은 그 달 1일 기준, 명시 날짜의 요일                                                           | `query/parse-query.ts`, `answer/context.ts` |
| 리포트 원문에만 있는 내용                        | 과제 이름 → 본인 리포트의 그 과제 행, 제출 횟수, 채점 수정 이력 절                                                                    | `answer/analysis.ts`                        |
| 후속 질문·대상 전환                              | 직전 주제 이어받기(변화·비교 동사는 새 주제 아님), 취약 영역 후속 질문의 기간 비교, 자녀 둘 이상이면 확인 질문                        | `service.ts`                                |
| 등수·성적 통계                                   | 자녀라도 등수 보류, 원생 권한 없는 계정의 반 평균 등 통계 보류                                                                        | `service.ts`                                |
| 근거 신뢰도                                      | 핵심어 일치(의문사 제외) + 절 제목 일치(문서 제목 제외) + 의미 검색·재정렬 점수                                                       | `answer/evidence.ts`                        |

시도했다가 되돌린 것: "질문이 요구한 값 + 핵심어 1개면 근거로 신뢰" 규칙은 기존 90문항에서 3문항을 새로 틀려 되돌렸습니다(`s4-r16` 직전).

## 4. 미공개 평가 결과와 미달 원인

| 지표(미공개 393문항)          | 기본 BM25 RAG | 개선 전 엔진   | 새 엔진   |
| ----------------------------- | ------------- | -------------- | --------- |
| 최종 상담 정확도              | 19.3%         | 44.8%(176/393) | **52.7%** |
| 답할 수 있는 질문 잘못된 보류 | 0.4%          | 25.3%          | 19.6%     |

학원별(개선 전 → 새 엔진): 누리 71 → 83/132 · 서담 62 → 75/139 · 온샘 43 → 49/122. 고친 문항 39개, 새로 틀린 문항 8개(순증 +31, +7.9%p).

**미달 원인**(오답 186개의 단계 분류, TEST_REPORT 4장):

1. **바인딩 48 · 질문 해석 29**: 개발 학원에서 고친 규칙이 다른 학원의 반 이름 체계·표 구성·말투에 그대로 맞지 않았습니다. 개발 학원 정확도(78.4%)와 차이가 큰 가장 큰 이유입니다.
2. **과잉 응답 29 · 다른 문서 인용 20**: 자료에 없는 개념을 묻는 질문을 관련 절이나 정형 값으로 답합니다. 개념 단위 "자료에 없음" 판정은 잘못된 보류가 커서 채택하지 못했습니다.
3. **보류 21 · 사후 검사 차단 18**: 근거를 찾고도 신뢰 기준·답 유형 검사·숫자 검사(OCR 불확실 숫자 포함)에서 막혔습니다. 안전 쪽 실패지만 정확도를 깎습니다.
4. **문서 파싱**: 미공개 학원의 2단 편집 소식지 3개 중 2개를 2단으로 판별하지 못했고, 품질 낮은 스캔 3개는 검수 필요(신뢰도 33~46)로 숫자를 쓸 수 없었습니다.
5. **부분 답변(1/15)·담당자 연결(3/8)**: 질문 일부만 답할 수 있을 때 `partial` 로 정리하는 처리가 약합니다.

미공개 평가 결과를 본 뒤에는 엔진을 고치지 않았습니다. 위 원인을 고치려면 새 개발 자료(다른 학원)로 다시 개선하고, 새로 만든 미공개 평가로 다시 측정해야 합니다.

## 6. 남아 있는 문제와 운영 전 필수 작업

1. **정확도 목표 미달(52.7% < 85%)**: 일반화가 부족합니다. 다른 학원 자료로 개발 자료를 늘리고, 바인딩·해석 규칙을 학원 구성(반 이름 체계·표 형식)에 덜 의존하게 바꿔야 합니다. 새 미공개 평가가 필요합니다(현재 393문항은 이미 한 번 봄).
2. **자료에 없는 질문의 과잉 응답(잘못된 응답 25.9%)**: 개념 단위 판정이 필요합니다. 형태소 분석 기반 "질문 핵심 개념 ⊆ 근거" 검사를 잘못된 보류와 함께 측정해 결정해야 합니다.
3. **2단 편집 판별·저품질 스캔**: 다른 레이아웃의 2단 문서를 놓쳤습니다. 저품질 스캔은 숫자를 쓰지 않도록 막았지만, 운영에서는 관리자 검수(7번 기능)가 필요합니다.
4. **사실 인용 위치**: 과정 단위 표(반 이름이 행에 없는 표)의 사실은 인용 위치가 문서 첫 문단으로 표시되는 경우가 있습니다(DEMO 예시 3).
5. **다른 학원 이름**: '학원'이 붙지 않은 다른 학원 이름은 알아보지 못합니다(검색 격리로 자료 유출은 없음).
6. **운영 연동**: DB·인증·서버 배포·DB outbox·RLS, 다중 인스턴스 호출 제한·대화 상태 공유.
7. **생성 API**: 공급자·약관(미성년·국외 처리) 확인 전에는 `RAG_GENERATION_ALLOW_PERSONAL_DATA=false` 유지. 실제 API 품질·지연·한도는 미측정.
8. **자원**: OCR 은 쪽당 약 25초(이 컨테이너 CPU) — 업로드 시 비동기 처리와 쪽 수 제한(30쪽)이 필요합니다.

## 후속 개선 · 질문 조건과 인용 위치

개발 문항에 원본 근거 행·열을 별도 라벨링하고 A/B/C/D Oracle을 실행했습니다. 기준판에서 질문 해석이나 근거만 개선해도 일부 답이 회복됐지만, 두 조건을 제공해도 복합 요청과 인용 위치에서 오류가 남았습니다.

- `QueryFrame`을 유지하며 질문 뒤 설명문과 직접 요청을 구분합니다. 여러 학년이 함께 등록된 반의 카탈로그 학년을 개별 토큰으로 대조합니다.
- 성적 결과와 담당 강사를 함께 물을 때 요청을 나누고, 앞 절에서 서버 권한으로 확정한 원생의 반을 뒤 절에 연결합니다. 반·과목을 하나로 확정할 수 없으면 뒤 절은 보류합니다.
- 수업 길이를 묻는 질문은 시각이 아닌 분·시간 단위의 근거를 확인합니다. 항목형 표의 명시적 행 이름은 검색 점수만으로 탈락시키지 않습니다.
- 수강료는 쉼표가 있는 원본 금액 셀을 확인하고, 같은 금액의 후보가 여러 행에 있으면 행을 단정하지 않습니다. 담당 강사는 카탈로그 반 이름과 일치하는 행을 인용합니다. 인용 위치 해석을 검색 라우팅에서 분리했습니다.

추가 모델과 외부 생성 호출 없이 개선했습니다. 공개된 393문항은 회귀 자료로만 사용했으며 새 학원에서 85%를 입증하지 못했습니다.

## 상담 경로 개편 · 비교 실행 단계

이전 서비스가 문장 분해, 조건 상속, 답변 합치기를 직접 수행했습니다. 개편 후 `query/plan.ts`가 `QueryPlan`을 만들고, 기존 승인 검색·정형 사실 어댑터가 근거를 제공합니다. 계획은 의도·필수 필드·요일과 기존 프레임의 학생·반·과목·날짜·비교·제외 조건을 보존합니다. 서비스에는 권한이 확정된 원생을 후속 요청에 연결하는 조정 로직이 남습니다.

`answer/evidence-bundle.ts`는 요청별 후보와 원본 인용을 공통 계약으로 다룹니다. 대상·권한, 정형 승인 상태, 시간표의 유효기간, 날짜·요일 충돌, 원본 셀 범위, 필수 값을 확인합니다. `answer/composer.ts`는 확인된 부분을 합치고 누락을 표시합니다. `answer/verify.ts`는 문서 인용형 답변의 선택 셀 또는 문장을 원본과 대조합니다. 서비스의 최종 검증은 승인·리비전·권한 재조회와 숫자·OCR·학생 식별 검사를 수행합니다.

현재 마이그레이션 단계에는 기존 정형·학습 분석 템플릿을 재사용하는 후보 어댑터가 포함됩니다. 도메인별 조건을 모두 제거하지는 않았습니다. 문서 인용형 답변에 원본 주장 검증을 적용했으며, 파생 정형 사실과 생성 문장의 모든 주장까지 공통 모델로 전환하는 작업은 남았습니다. BM25 순위와 접근 필터는 저장소에서 실행합니다. 계획 경로는 검색 점수를 근거 충족으로 간주하지 않습니다. 기본 엔진 전환은 보류했습니다.

## 후속 진단과 비용 근거 경로

- NR-T-003과 NR-T-093은 검색·인용 문서가 맞았으나 answerFee의 월 수강료 템플릿이 원본의 8주 기준을 바꿨습니다. 최초 실패는 답변 구성입니다.
- 공개 합성 평가의 세로형 비용표에는 대상 반의 재료비 행이 있었습니다. 기존 응답은 수강료 행만 인용했습니다. 최초 실패는 요청한 필드별 행 선택과 충분성 판단입니다.
- NR-T-041은 타인 명단을 학습 분석으로 해석했습니다. 별도 과정의 비용을 현재 반 수강료로 답하는 사례도 있었습니다. 미해결 과정과 명단 신호가 질문 분할 과정에서 사라지지 않도록 했습니다.
- NR-T-107은 검색 결과에 점수 근거가 없었고, OS-T-009는 강사 문서를 찾았지만 최종 검증에서 차단됐습니다. 두 사례는 이번에도 오답입니다.

cost-evidence.ts는 확정 반과 비용 필드로 원본 표 행·열을 찾습니다. 승인 검색 결과에서 유효기간·반·OCR 상태·셀·충돌을 검사하고, 그 뒤에만 결과를 작성합니다. 같은 출처의 일치 정형 사실은 추적에 보존합니다. 일부만 확인되면 확인된 셀과 누락 항목을 반환합니다. 최종 서비스의 ACL·승인·리비전·숫자·인용 검증을 그대로 거칩니다.

지원하는 비용 요청은 기존 템플릿의 답변에 의존하지 않습니다. 할인·합계·이력·개정 시점, 정형 사실만 있는 요청, 학습 분석 등은 기존 어댑터가 남아 있습니다. 충돌 검사는 BM25 후보 범위 안에서 동작합니다.

## 비용 슬롯과 문서 근거 선택 진단

- OS-T-011의 승인 수강료와 교재비는 같은 출처에 있었지만, 질문 해석에서 일반어로 표현한 첫 월 수강료가 빠졌습니다. 계획에서 두 필드를 보존하고 표 근거가 부족할 때 승인 정형 조회에도 전달합니다.
- 비용표를 다루는 기존 독립 경로는 교재비와 재료비를 하나의 유형으로 처리해 두 항목을 동시에 묻는 경우 하나만 선택하거나 충돌로 처리할 수 있었습니다. query/plan.ts의 비용 슬롯과 cost-evidence.ts의 원본 행·열 선택을 연결했습니다. 교재비와 재료비를 모두 요청하면 범용 material_fee 사실만으로 두 항목을 확정하지 않습니다.
- NR-T-113은 문서 안에 삽입된 상담 비서 대상 지시를 실제 할인 근거로 사용했습니다. 계획 경로의 문서·절 선택에서 해당 후보를 제외해 모집 사실만 부분 답변합니다. NR-T-040도 같은 지시 인용을 제거했으며, 확인된 정가는 유지하고 할인은 미확인으로 표시합니다.
- 기존 v1 채점은 정답 출처 중 하나만 있으면 통과할 수 있습니다. 이번 JSON에는 기재된 모든 출처의 검색·인용 누락 목록과 최종 인용 위치를 별도로 남깁니다. 기재 출처가 대체 출처인지 복수 필수 출처인지는 기존 라벨에 따라 별도 검토합니다.

비용표의 값은 슬롯별 원본을 검증한 뒤 작성합니다. 정형 사실만 있는 월 수강료 요청과 나머지 상담 분야에는 기존 어댑터가 남아 있습니다. 비용표 충돌 탐색은 검색 후보와 승인 정형 조회 범위이며, PDF 추출기나 전체 상담 엔진을 교체하지 않았습니다.

## 구조 검토 후 개선

- 시간표 근거 경로는 대상 반과 유효 시점의 표 셀을 먼저 선택하고 접근 권한, 판독 상태, 원본 위치를 검증합니다. 모호한 요일 및 기존 정형 어댑터가 필요한 요청은 기존 분기를 유지합니다.
- 교재비와 재료비를 동시에 묻는 이번 달 질문은 현재 적용 시점의 별도 슬롯으로 평가합니다. 금액만 있는 표에서 포함 관계를 추론하지 않습니다. 금액의 구분 기호는 무시하고 청구 주기는 별도로 비교합니다.
- 복합 요청에서 생략된 대상과 시점은 앞 절부터 이어받습니다. 보고서 확인과 분석 항목이 함께 있으면 명시된 하나의 단원으로 범위를 유지합니다. 누락 필드 이름이 없는 부분 답변도 완료로 합치지 않습니다.
- 슬롯 채점은 필요한 출처의 조합과 대체 출처를 분리하고 주석이 제공된 경우 행·열·검색 청크 누락을 출력합니다. 안전 위반 문항은 정답에서 제외합니다.

연구의 적용 범위는 두 가지입니다. RAGChecker가 검색과 답변 단계 오류를 분리해 진단하듯 출처 검색 누락과 인용 누락을 구분합니다. ALCE의 인용 정확성과 완전성 구분은 슬롯별 필수 출처 검사에 적용합니다. 표 셀을 근거로 사용하는 TAPAS의 접근은 원본 좌표 보존에만 참고했습니다. 이번 구현에는 새 모델을 도입하지 않았습니다.

- RAGChecker https://arxiv.org/abs/2408.08067
- ALCE https://arxiv.org/abs/2305.14627
- TAPAS https://aclanthology.org/2020.acl-main.398/

남은 범위는 공통 답변 경로의 주장별 검증, 청구 기간 전체 조회, 검색 상한 밖의 승인 표 충돌 검사, PDF 표에서 유실된 셀 관계 복원입니다. 현재 슬롯 진단은 답변의 개별 문장이 어떤 인용에 연결됐는지 자동으로 증명하지 않습니다.

## PDF 표와 복합 질문 후속 개선

PDF의 페이지 연결은 열 수 대신 정규화된 머리글 일치를 확인합니다. 이어지는 표의 반복 머리글을 제거하되 데이터 행의 원본 페이지는 유지합니다. 머리글과 값 한 개가 정렬된 희소 열은 표 스키마에 남겨, 빈 적용 기간 셀 때문에 뒤쪽 열이 이동하지 않도록 했습니다. 바뀐 파서로 이전 캐시가 재사용되지 않도록 버전을 갱신했습니다.

계획 엔진은 담당 강사·비용처럼 독립된 학원 정보 항목을 한 문장에 요청할 때 각 절을 별도 경로로 확인합니다. 합계·포함·비교처럼 두 절의 관계가 답에 필요한 경우 기존 경로를 유지합니다. 교습비와 강사를 함께 묻되 강사 자료가 없는 경우, 교습비 출처만 인용하는 부분 답변을 통합 테스트에서 확인합니다.

공개 393의 직전 계획 엔진은 생성 Mock을 5건 호출했고, 전체 오답 172건 중 169건은 생성 호출 없이 발생했습니다. 이 실행에서 우선 병목은 생성 모델 교체보다 파싱·요청 해석·근거 선택 및 결합입니다. 실제 모델 성능은 같은 승인 근거를 고정한 조언 문항에서 별도로 검증해야 합니다.

이전 검색 실험에서는 BM25·e5 하이브리드·bge 재정렬이 207/393으로 동률이었습니다. 다음 검색 실험은 정답 셀을 직접 제공할 때만 회복되는 문항을 분리한 뒤 진행할 수 있습니다. Docling/TableFormer는 현재 추출에 실패한 복잡한 표의 오프라인 대조 후보입니다. 정답 셀의 페이지·행·열 일치와 처리 비용을 함께 측정하는 데 적합하며 AXR 개선 효과는 별도 실험이 필요합니다.

- Docling Technical Report https://arxiv.org/abs/2408.09869
- RAGChecker https://arxiv.org/abs/2408.08067
