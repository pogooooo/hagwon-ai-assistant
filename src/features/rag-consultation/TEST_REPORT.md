### 채점 버전과 판정 순서

1. **기존 v1**은 먼저 문항의 대표 상태 또는 사전 정의된 대안 상태와 비교합니다. 해당 상태에서 요구하는 필수 문자열을 전부 포함하고 공통 금지 문자열은 포함하지 않아야 합니다. 답변·부분 답변에 기대 출처 ID가 하나 이상 지정되어 있으면 그중 하나를 인용해야 합니다. 생성 횟수는 문항의 상한 이하여야 합니다. 구어체 100문항은 보류·확인·연결·거부를 비응답으로 묶으므로, 이 점수로 비응답 유형 구분 능력을 판단하기 어렵습니다.
2. **슬롯 v2**는 정확한 상태와 요구 사실별 정답을 검사합니다. 한 슬롯의 대상·값·단위 등 라벨을 동일한 답변 줄에서 확인합니다. 출처 묶음 내부는 모두 필요하고, 여러 묶음 중 하나를 완전히 만족하면 대체 출처가 인정됩니다. 예를 들어 `[[A, B], [C]]`는 A와 B를 함께 인용하거나 C를 인용해야 한다는 뜻입니다. 위치·열 라벨이 있으면 같은 출처의 지정된 원본 위치와 열도 일치해야 합니다.
3. **슬롯 v2의 추가 조건**은 누락 항목 표시, 확인 질문 후보, 연결 사유, 금지 내용, 비응답 인용 없음, 호출 예산입니다. 검색 단계에서 슬롯의 필수 근거가 전부 발견됐는지도 별도로 기록합니다. 검색 성공만으로 답변을 정답 처리하지 않습니다. 공개 합성 300의 CSV/JSON 재채점 어댑터는 출처 ID와 출력 문자열을 사용합니다. 모든 행·열 위치나 API 상태 메타데이터를 검수하는 것은 원본 관측값과 별도 라벨이 있을 때 가능합니다.

## 후속 평가 · 슬롯 v4의 전체 답변과 인용 검증

## 독립 평가 사전 점검과 95% 판정

`automatedGate.passed`는 해당 입력의 자동 채점 결과를 유지합니다. `independentGate`는 별도로 독립 평가의 적격성과 95% 달성 여부를 표시합니다. 최소 3개 학원의 300문항을 사용하며 300문항이면 285개 이상이 슬롯 v4에서 정답이어야 합니다. 알려진 입력 중복, 검수 기록 누락, 정상 상담에서 Mock 생성 사용, 권한·승인 위반은 별도의 실패 사유로 기록합니다.

원본 자료의 폴더와 검수된 슬롯 v4 라벨을 준비한 뒤 다음 명령으로 해시와 문항 목록을 확인합니다. 이 단계는 색인·모델 호출·평가 결과 파일 작성을 시작하지 않습니다.

```powershell
node --disable-warning=MODULE_TYPELESS_PACKAGE_JSON src/features/rag-consultation/server/eval/run-eval.ts --holdout-root '<원본 자료 폴더>' --gold-v4 '<검수 라벨.json>' --holdout-preflight --reject-known-overlap
```

검수자가 확인할 범위는 원본의 신규성, PDF·스캔 표·학습 리포트, 구어체·복합 조건·근거 충돌·자료 부족 문항, 정답과 출처의 대응입니다. 사전 점검에서 이미 알려진 문항과 질문·대화가 같은 항목도 따로 표시합니다. 검수 완료 후에는 평가 원본 폴더 밖에 다음 형식으로 기록합니다. 해시와 ID는 사전 점검 출력에서 가져옵니다.

```json
{
  "version": 1,
  "datasetSha256": "<원본 폴더 해시>",
  "goldSha256": "<슬롯 v4 정답 파일 해시>",
  "engineSha256": "<RAG 기능과 평가 코드 및 package-lock.json 해시>",
  "reviewedBy": "<검수 담당자 식별값>",
  "reviewedAt": "<시간대를 포함한 ISO 8601 시각>",
  "reviewedCaseIds": ["<검수한 모든 문항 ID>"],
  "reviewedRepeatedCaseIds": [],
  "independentInputs": true
}
```

정확히 같은 질문·대화가 확인된 경우에는 사람 검수 후 그 문항 ID들을 `reviewedRepeatedCaseIds`에 기록합니다. 자료 공개 및 작성 경위는 담당자가 확인합니다. 검수 기록과 해시는 어떤 자료를 어떤 코드로 평가했는지 추적하는 데 사용합니다.

```powershell
node --disable-warning=MODULE_TYPELESS_PACKAGE_JSON src/features/rag-consultation/server/eval/run-eval.ts --holdout-root '<원본 자료 폴더>' --gold-v4 '<검수 라벨.json>' --review-manifest '<검수 기록.json>' --out '<결과 상위 폴더>' --label blind-v4 --reject-known-overlap --variant engine,engine-planned
```

`summary.json`의 `holdoutComparison`에서 같은 문항과 라벨로 평가한 기존 엔진과 계획 엔진의 차이를 확인합니다. 외부 모델을 사용할 때는 운영 정책에 따라 `--generation gemini --max-live-calls <횟수>`를 별도로 지정하고 실제 HTTP 요청 수를 확인합니다. Mock 정상 생성으로 얻은 성능과 Gemini 응답 품질을 구분합니다.

합성 통합 테스트에서 재사용한 자료와 1문항 표본은 자동 채점이 100%여도 독립 판정을 통과하지 않았습니다. 정답 해시·코드 해시 불일치와 검수 문항 누락은 실행 전에 거부했습니다. 300문항에서 285개와 284개의 경계, 권한 밖 반과 교직원 전용 자료의 검출도 확인했습니다. 고정 회귀 7세트의 정오 변화는 없었고 계획 엔진의 공개 회귀는 384/393이었습니다. 두 모드에서 전체 테스트가 각각 528개 통과했고 정적 검사와 빌드도 통과했습니다. 이 실험은 새 학원의 실제 독립 정확도나 Gemini 응답 품질을 산출하지 않았습니다. [기술별 기록](RAG_TECHNIQUES.md)

세트 5의 기존 엔진은 최초 141/300, 최종 144/300을 통과했습니다. 계획 엔진은 최종 학원별 95/100이며 기존 정답 손실이 없었습니다. `AUTO5_SCHOOL_2-066`, `-067`, `-070`의 공통 원인은 단원명 ‘관점의 변화’를 정답률 추이 요청으로 읽어 비교 월을 추가한 것입니다. 단원명 밖에 실제 변화 요청이 있는 경우에는 비교를 유지합니다.

세트 5의 남은 15문항은 모두 스캔 공지에 연결됩니다. 승인 행사에서 장소·시각을 확인해야 하는 문항 12개가 실패했습니다. 장소 표기의 글자·띄어쓰기 오독, 시각 토큰 불확실, 문단 배치에 따라 필요한 필드를 찾지 못한 경우가 포함됩니다. 다른 회차를 물은 세 문항은 모두 보류했고 인용은 없었습니다. 엔진이 회차 부재 대신 스캔 판독 확인을 누락 항목으로 반환해 엄격 채점에서 실패했습니다. 관측된 권한·승인 위반, 답할 수 없는 질문에 대한 과잉 응답, 외부 생성 요청은 각각 0건입니다. 답할 수 있는 문항의 잘못된 보류는 4.5%였습니다.

세트 5의 95%는 오류 진단 이후 같은 문항과 정답으로 확인한 합성 회귀 점수입니다. 최신 세트 최초 실행은 94.0%였습니다. 생성기가 만드는 질문·문서의 종류에는 범위가 있으며 실제 학원 상담과 Gemini 생성 품질은 이 측정의 범위 밖입니다.

공개 7세트의 모든 문항을 전후 대조했습니다. 두 엔진 모두 신규 오답 0개입니다. 계획 엔진은 공개 384/393, 개발 152/153, 기존 90/90, 구어체 100/100, 합성 300/300, 슬롯 v2 240/240이었습니다. 기본·계획 모드에서 전체 테스트 537개가 각각 통과했고 정적 검사와 빌드도 통과했습니다.

합성 자동 판정은 `--automated-holdout --reject-known-overlap`으로 실행합니다. 3개 학원·300문항 이상, 슬롯 정확도 95% 이상, 권한·승인 위반 0건이 필요합니다. 정상 응답에서 Mock 생성이 사용되면 판정을 통과할 수 없습니다. `automatedHoldoutGate`로 출력되며 사람 검수가 있는 평가의 `independentGate`와 구분됩니다.

```powershell
$caseRoot = '.git/rag-validation/automated-holdout/seed-5'
$runner = 'src/features/rag-consultation/server/eval/run-eval.ts'
$env:RAG_MODEL_CACHE_DIR = (Resolve-Path "$caseRoot/cache").Path
node --disable-warning=MODULE_TYPELESS_PACKAGE_JSON $runner --automated-holdout --holdout-root "$caseRoot/inputs" --gold-v4 "$caseRoot/gold-v4.json" --contract-state --reject-known-overlap --holdout-preflight
node --disable-warning=MODULE_TYPELESS_PACKAGE_JSON $runner --automated-holdout --holdout-root "$caseRoot/inputs" --gold-v4 "$caseRoot/gold-v4.json" --contract-state --reject-known-overlap --out "$caseRoot/runs" --label seed-5-recheck --variant engine,engine-planned
```

첫 실행과 수정 후 문항별 결과는 각각 `seed-5-first-pass/`, `seed-5-trend-scoped/`의 JSON·CSV에 있습니다. 채점 버전, 원본·정답·코드 해시는 각 `summary.json`에 포함됩니다. [기술별 기록](RAG_TECHNIQUES.md)

## 스캔 행사 근거와 새 합성 평가 최초 실행

계획 엔진은 OCR로 읽은 같은 문장에서 날짜가 확인되고 시각만 불확실한 경우, 날짜를 회차 필터로 사용합니다. 불확실한 시각은 인용에서 제외합니다. 같은 제목이 반복돼도 절의 출현 위치를 구분하며, 날짜가 확실히 다른 회차의 검수 상태나 장소를 요청 회차에 붙이지 않습니다. PDF에서 연달아 찍힌 ‘일시’와 ‘장소’는 별도의 근거 문단으로 남깁니다. 날짜 뒤의 조사와 동작 표현을 행사명과 분리하고, 반 이름과 겹치는 단원명도 분석 질문에서 유지합니다. 보고서에 기록된 학습 방향 조회에는 승인 리포트의 해당 월만 사용합니다.
