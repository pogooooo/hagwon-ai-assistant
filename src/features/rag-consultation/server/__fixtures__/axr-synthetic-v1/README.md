# AXR 기능 4 — 구현 전 합성 평가 자료 v1

- 작성 기준: 2026-11-01. **실제 학원/학생/보호자 정보가 아닌 완전한 가상 데이터**.
- 골드셋 예시: **81문항**, 출처 문서 18건, 정형 사실 17건, 가상 계정 9개.
- 개발/평가 분리: `dev` / `holdout`; 동일 `scenario_group`은 같은 분할에 배정(시나리오 누출 감소). 단 같은 사실을 참조하는 다양한 질문이 두 split에 걸쳐 있을 수 있으므로 **독립 벤치마크가 아닌 예비 스모크 테스트**이며, 최종 300문항은 문서·학원 시나리오를 별도 분리해야 함.
- `users.json`: 서버에서 부여해야 할 가상 조회 권한. 데이터셋 안의 권한을 실제 서비스 인증 정책으로 사용하지 말 것.
- `corpus.jsonl`: 가상 문서와 승인상태, 유효시점, revision, 근거 ID. 실제 파서 시험용 PDF/HWP가 아닌 **텍스트 구조를 가정한 검색·논리 테스트용**.
- `facts.jsonl`: 값·대상·기간·출처 식별자가 포함된 구조화 사실.
- `cases.jsonl`: 질문, 기준 시점, 세션 상태, API 장애 상황, 기대 상태(`answered`, `partial`, `abstained`, `clarify`, `denied`, `handoff`) 및 근거 ID.
- `fee_table.csv`: 표의 행·열 바인딩 테스트용 CSV.
- `manifest.json`: 개수·버전·범주 검사용 메타데이터.
- `validate_fixtures.py`: 파일 내부 참조·권한·실험 분할·자료 유효시점 검사. **RAG 정확도 시험 아님**.

## 예상 결과의 해석

- `expected.fact_ids`는 **최소로 필요한 근거**다. 답변 내용/자연어 표현의 완전한 정답 텍스트는 별도 사람 검수가 필요하다.
- `expected.generation_budget_max`는 각 테스트에서 허용하는 생성 호출 상한(0 또는 1)이며, **실제 API 사용량이 아님**.
- 같은 값 65%가 두 학생에게 등장하더라도 학생을 바꿔 인용하면 실패다.
- 과거 버전 조회는 공개할 수 있는 이력 권한을 구현한 경우에만 허용한다. 현재 예시는 과거 자료 중 공개 수강료 안내를 보여 주지만, 개인 이력 조회는 서버 정책 재검토가 필요하다.
- `draft` 문서는 유사도가 높아도 검색·답변에서 제외해야 한다.
- 외부 API의 실입력은 개인정보 처리·이용약관 확인이 끝날 때까지 이 합성 데이터만 사용할 것.
