# 띄어쓰기 오판정 1차 개선 시도 — 미채택

기준 커밋 `78e87fa`, 작업 브랜치 `feat/homework-grading-v3`. 이번 범위는 띄어쓰기 오판정 한 건과 맞춤법 회귀 검사뿐이다. `main`, 공개 배포, 보강 투표·월간 리포트 기능에는 착수하지 않았다. 주간 잔여량 조회는 시작과 중간에 9%를 반환했으며 모델 설정을 변경하지 않았다. 도구에서 현재 모델명·추론 노력 설정은 제공되지 않았다.

## 실제 시험

외부 모델 요청은 총 3회다. 직접 만든 한 페이지에 기존 실패 문항과 독립적인 짧은 가상 사례 세 개를 배치했다. 기존 실패 문항의 내용은 재사용했지만 페이지 구성은 기존 15문항 시험과 다르다. 정답과 채점 기준은 모델 판독에 전달하지 않았다.

1. 기존 일반 판독 1회: `할수있다`를 `할 수 있다`로 읽어 만점 2점을 주는 오류가 재현됐다. 나머지 세 문항의 점수·정오답은 일치했지만, 그중 한 개는 전사 자체가 원문과 달랐다.
2. 문자·공백 배열을 별도로 요구하는 검증 판독 2회: 배열 증거와 전사가 일치하지 않거나 증거가 없으면 보류하도록 시험했다. 두 번 모두 네 문항 전체가 보류됐다.
3. 같은 사진·문항에 대한 실제 응답을 서비스에 재생해 검수 전 초안도 확인했다. 기존 만점 오판정은 보류로 바뀌었지만 정상 사례까지 보류됐다.

| 구분                        | 점수 제안 | 전체 4문항 기준 일치 | 보류 |
| --------------------------- | --------- | -------------------- | ---- |
| 기존 일반 판독              | 4/4       | 3/4                  | 0    |
| 문자 단위 검증 제안, 각 2회 | 0/4       | 0/4                  | 4/4  |

모든 문항은 채점 가능한 가상 사례다. 보류를 정답으로 세지 않았다. 기존 14문항 또는 별도 12문항 전체를 재실행하지 않았으므로 프로젝트 정확도를 갱신하지 않는다. 기존 13/14(92.9%), 새 10/12(83.3%, 보류 2개), 목표 95% 미달 표시는 유지한다.

이 실험은 과도한 보류라는 역효과 때문에 **미채택**했다. 실험의 모델 프롬프트·문자 배열 강제 조건은 기본 엔진에서 제거했다. 원래의 띄어쓰기 오판정은 아직 완전히 해결되지 않았다. 다음 단계에서는 문자 간격을 실제로 뒷받침할 수 있는 판독 증거가 필요하며 이번 턴에는 추가 실험하지 않는다.

## 유지한 회귀 검사

이번 최종 실행은 채점 기능 자동 테스트 55개 통과, 실패·건너뜀 0개다. 새로 유지한 회귀 검사는 아래 두 묶음이며 타입 검사와 변경 파일의 lint·포맷 검사도 통과했다. 전체 프로젝트 성능 재평가나 대규모 회귀 실행으로 표시하지 않는다.

- 띄어쓰기가 필요한 정답 `할 수 있다`에 `할수있다`를 직접 주면 기존 규칙대로 오답이다.
- 올바른 `갈 수 있다`는 정답이다.
- `됐다`에 대한 `됬다`, `어이없다`에 대한 `어의없다`는 오답이다. 공백 제거·맞춤법 자동 교정으로 규칙을 완화하지 않았다.
- 일반 전사가 교정된 문자열이고 검증 전사가 실제 붙여 쓴 문자열이면 서비스는 만점 대신 보류/null로 처리한다. 두 전사가 똑같이 잘못 읽는 기존 한계가 해결됐다는 뜻은 아니다.

## 남겨 둔 두 수학 보류 원인

- `new-math-wrong`: `UNSUPPORTED`, 읽은 답안을 지원 숫자·수식 문법으로 채점하지 못했다. 과거 원문 전사는 보존하지 않았으므로 어떤 구체적 문자·표기가 원인이었는지는 기존 JSON만으로 확정할 수 없다.
