# 공공정보·학교 시험 일정·음성 상담 구현과 검증

기준: `main`의 `157d24b9f94c35e8698fc1e40ece25af2c8c1c8c`, 2026-11-17.
`새기능_SRS.pdf` 중 F1·F4·F6을 구현한다. F2 ‘가르치면 배우기’는 사용자 요청에 따라 제외했다. 상담 답변을 지식으로 전환하는 버튼·API·모델 호출·전용 평가를 제거했으며, 아래 등록 정보 승인은 F1의 공공정보 검수용이다.

## 동작과 저장 구조

| 기능         | 입력 → 처리 → 상담 연결                                                                                                               | 화면 / 주요 파일                                                                |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| F1 공공정보  | 나이스 학원 검색 → 실제 검색 결과 선택 → 등록 정보 초안 → 공개 범위·적용 기간 확인 및 승인 → 기존 RAG 색인                            | `/public-data`, `/knowledge`; `neis.ts`, `public-data.ts`, `knowledge.ts`       |
| F4 학교 일정 | 나이스 학교 등록 → 최대 200일 기간 조회 → 행사명에 고사·시험·평가가 있는 후보 → 학년·날짜 승인 → 반과 학교·학년 연결 → 상담·보강 추천 | `/schools`, `/schedule`; `schools.ts`, `team-schedule.ts`                       |
| F6 음성 상담 | 로그인한 보호자의 녹음 → CLOVA Speech → 인식 원문 확인 → 기존 채팅 엔진 → 근거 버전 재확인 → CLOVA Voice                              | `/voice`; `voice.ts`, `voice-ui.js`, `voice-worklet.js`, `external-services.ts` |

새 테이블은 운영 서비스의 `op_` 영역에만 추가한다. `op_knowledge`는 등록 정보의 초안·승인·기간·공개 범위·출처·버전을, `op_public_search`와 `op_school_search`는 사용자별 15분 검색 결과를 저장한다. `op_schools`, `op_class_schools`, `op_school_exams`는 학교·반 연결·시험 후보와 확정 버전을 저장한다. `op_voice_sessions`, `op_voice_turns`에는 인식 원문, 확인 상태, 답변과 출처를 기록한다. 음성 바이너리는 저장하지 않는다. `op_external_usage`는 UTC 날짜와 서비스별 요청 횟수를 저장해 재시작 후에도 한도를 유지한다.

팀 휴보강 도메인은 변경하지 않는다. 기존 후보 생성·교실/강사/예약 충돌 검사 후 시험 기간에 겹치는 후보의 순위만 내린다. 휴강일이 시험 시작 14일 이내이면 시험 전 후보를 우선한다. 자동 확정하지 않으며 기존 승인 절차를 사용한다.

## 근거·권한·실패 처리

- 공공 교습비는 `THCC_OTHBC_YN=Y`인 경우만 가져온다. 공개하지 않은 수치를 추측하거나 채우지 않는다. 등록 정보는 최신 실제 청구 금액을 보증하지 않으므로 원장 확인 전에는 검색 근거가 되지 않는다.
- 외부 검색 결과 선택은 서버에 저장한 학원·사용자별 결과 인덱스로 검증한다. 클라이언트가 임의의 등록 정보나 학교를 보내 승인 경로를 우회할 수 없다.
- 나이스 응답 오류를 ‘검색 결과 없음’으로 바꾸지 않는다. 5분 캐시, 동시 요청 합치기, 타임아웃을 적용한다. API 키는 출처 URL에 남기지 않는다.
- 승인 전·만료·철회 자료를 상담에서 제외한다. 등록 정보 교체에는 기존 버전 선택 확인이 필요하며 미래 개정은 적용 시점 전까지 기존 정보를 유지한다.
- 시험 일정은 학교·학년·반·시험명·연월별 원본 그룹으로 만든다. 시험명과 날짜를 하나의 `시험 일정` 셀에 함께 둬 날짜가 없는 시험명만 답하는 것을 방지한다. 조회한 달의 그룹만 선택하며, 답변용으로 행을 재번호화하지 않는다. 다른 날짜 철회 시 그룹 버전이 바뀌어 이전 인용을 무효화한다.
- 학교·학년이 없거나 여러 대상으로 모호한 순수 시험 날짜 질문에는 빈 근거를 제공한다. 다른 학교의 일반 안내를 대신 답하지 않는다. 선택한 학생은 서버의 현재 학생·반 권한으로 제한한다.
- 모든 음성 질문은 확인 후에만 답변한다. 두 번의 인식/확인 실패는 담당자 확인으로 연결한다. 동일 확인의 중복 처리, 인식 중 종료, 다른 보호자의 세션 접근을 검사한다.
- 성적·채점·개인 학습 근거는 음성으로 읽지 않고 화면으로 안내한다. TTS 호출 전후에 현재 권한과 인용 버전을 확인한다. 요약과 문자 초안에서 전화번호를 가린다. 실제 전화·문자 발송 기능은 없다.
- 브라우저에서 최대 60초를 녹음해 16kHz 모노 PCM WAV로 변환한다. 서버가 형식·길이·크기를 다시 확인한다. Speech 요청의 `resultToObs=false`는 Object Storage 저장을 요청하지 않는 설정이며, 제공자의 모든 로그 보존까지 없다는 뜻은 아니다.
- 키가 없거나 서비스가 실패해도 글 상담을 사용할 수 있다. 기본 외부 호출 한도는 DB별 서비스당 UTC 하루 100건, 최대 설정 1,000건이다. 실패 요청도 센다. 이 한도는 원화 비용 상한을 보장하지 않는다. 자동 재시도는 하지 않는다.

## 평가 항목 선정과 판정

기존 테스트를 삭제·비활성화하지 않았다. 새로운 자동 테스트는 승인 전후, 기간 만료, 교체 충돌, 학교/학년/날짜 혼동, 다일 시험, 철회에 따른 인용 변경, 실제 HTTP 인증·CSRF·HTML 이스케이프, 음성 확인·중복·동시 종료·권한·호출 제한을 다룬다. HTTP 테스트는 실제 Node 서버를 띄워 로그인과 폼 요청까지 실행한다. 외부 Speech/Voice 요청은 요청 형식과 실패 처리를 검증하는 모의 응답이다.

별도 실행기는 `scripts/verify-new-features.ts`이며 다음 합성 데이터를 사용한다. 정답과 질의는 실행기 코드에 고정하고 결과 JSON에는 실제 답변과 인용을 저장한다. 기존 300/393문항 평가와 합산하지 않는다.

| 평가 묶음                | 선정 기준                                                                 | 통과 기준                                                                                            | 결과  |
| ------------------------ | ------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- | ----- |
| 학교 날짜 20문항         | 2개 학년 × 10개 표현. 중간/기말, 4·7·12월, 단일/복수 시험일을 구분        | `answered`, 답변의 모든 2027년 날짜 집합이 정답 집합과 정확히 일치, 출처가 학교 자료이고 학년이 일치 | 20/20 |
| 보강 추천 20시나리오     | 시험 시작일·교실·시간·입력 순서를 바꾸고 겹침/시험 전/시험 후 후보를 포함 | 시험 전 비중복 후보 우선, 겹침 후보 후순위, 후보 수 보존                                             | 20/20 |

30문항은 녹음이 아니라 **음성 UI의 글 입력 대체 경로** 테스트다. STT의 정확도나 3명 × 30회 녹음 결과로 해석하면 안 된다. 20개 추천 시나리오는 합성 시뮬레이션이며 실제 학원 배정 성공률이 아니다. 전체 상담 엔진의 95% 독립 정확도를 입증하는 평가도 아니다.

초기 학교 날짜 검증은 14/20이었다. ‘시험 일정/기간’ 질문에서 표의 시험명만 선택하고 시작일·종료일 열을 누락한 6건을 수정해 20/20이 되었다. 복수 날짜·다른 달·다른 학년·철회·출처 위치를 별도 회귀 테스트로 검증했다.

음성 경로 내용 확인은 최초 27/30이었다. ‘통학버스’를 셔틀 주제로 인식하지 못해 보류하거나 와이파이 안내를 반환한 2건에 대해 공통 엔진의 운영 사전에 `통학버스`, `통학차량` 동의어를 추가했다. 음성 전용 답변 로직을 만들지 않았다. 수정 후 29/30이며 문항·기대 문자열을 바꾸지 않았다.

남은 1건은 ‘학원 셔틀을 이용할 수 있나요?’이다. 자료는 ‘셔틀 신청은 안내 데스크에서 접수’만 설명하고 실제 운행 가능 조건은 제공하지 않아 엔진이 보류했다. 내용 확인 점수는 실패로 유지한다. 운영 가능 여부를 답하려면 실제 운행 근거를 등록해야 하며 이 결과를 성공으로 재분류하지 않았다.

## 실제 외부 연결과 아직 확인하지 못한 것

나이스 실제 API로 충남 아산의 아래 10개 학교를 조회하고 2026-08-01~2026-12-31 학기를 요청했다. 모두 학교 식별 조회는 가능했지만 인증키가 없는 요청은 학교마다 5개 행만 반환했다. 각 응답은 `complete=false`로 기록했다. 반환된 샘플에 시험 후보가 없다는 사실을 ‘학기에 시험이 없다’로 해석하지 않는다.

| ------------------ | --------------------- |
| 아산중학교         | 5 / 64                |
| 온양중학교         | 5 / 58                |
| 온양여자중학교     | 5 / 63                |
| 온양용화중학교     | 5 / 67                |
| 아산고등학교       | 5 / 120               |
| 온양고등학교       | 5 / 48                |
| 온양여자고등학교   | 5 / 49                |
| 설화고등학교       | 5 / 63                |
| 배방고등학교       | 5 / 64                |

학원 등록 정보도 실제 나이스 응답 5개를 확인했다. 이 검증은 전체 학원 검색 누락률이나 공공 교습비 정확도 검증이 아니다. 빈 폼 대비 실제 입력 시간 측정, 전체 학기 시험 누락률, 실제 녹음 90회의 인식률·지연·TTS 청취 품질은 미측정이다.

Naver 콘솔에 접근했으나 세션 만료 화면을 확인했다. 현재 Speech 도메인 Invoke URL/키와 Voice 애플리케이션 인증정보를 확보하지 못했다. CLOVA Studio 키는 Speech/Voice 인증정보를 대신하지 못한다. 제외된 F2 실험에서 Studio 요청 1회는 HTTP 400 후 수정 재호출 1회가 HTTP 200이었지만, 이를 현재 음성 기능의 실연결 성공으로 계산하지 않는다.

## 설정과 재실행

비밀값은 서버 환경 변수/Cloudflare secret으로만 주입한다. `.env.example`에는 이름과 빈 값만 둔다.

- `AXR_NEIS_API_KEY`: 전체 페이지 수집용 나이스 키. 키가 있을 때 페이지당 100행, 최대 20페이지까지 읽으며 초과 시 불완전으로 표시한다.
- `AXR_CLOVA_SPEECH_INVOKE_URL`, `AXR_CLOVA_SPEECH_KEY`: Speech 도메인 연결.
- `AXR_CLOVA_VOICE_CLIENT_ID`, `AXR_CLOVA_VOICE_CLIENT_SECRET`: Voice 애플리케이션 연결.
- `AXR_EXTERNAL_DAILY_CALL_LIMIT`: 외부 Speech/Voice 요청 횟수. `0`이면 호출 차단.

```powershell
npm run check
npm test
npm run build
node --disable-warning=MODULE_TYPELESS_PACKAGE_JSON scripts/verify-new-features.ts --out .local/new-features-verification
# 실제 나이스 요청을 추가할 때만:
node --env-file-if-exists=.env.local --disable-warning=MODULE_TYPELESS_PACKAGE_JSON scripts/verify-new-features.ts --out .local/new-features-verification --live-neis
node deploy/cloudflare/prepare-hosted.mjs
npx wrangler@4.163.0 deploy --config deploy/cloudflare/wrangler.hosted.jsonc --dry-run
```

이번 기록의 실제 답변·인용·판정은 [검증 결과 JSON](new-features-validation.json)에 둔다. 전체 회귀 테스트와 배포 확인 결과는 아래 최종 검증란에 기록한다.

## 최종 검증

- 기존 675개 + 추가 27개 = **702개 자동 테스트 통과**, 실패·건너뜀 0개. 제거한 F2 전용 테스트는 이 개수에 포함하지 않는다.
- `npm run check` 통과: ESLint, Next 타입 생성/TypeScript, Prettier.
- `npm run build` 통과: 기존 Next 정적 프로토타입도 빌드된다.
- Cloudflare 패키지 생성과 Wrangler 배포 dry-run 통과.
- 로컬 Cloudflare Workers/Durable Object에서 로그인, 관리자 4개 경로와 보호자 2개 경로 HTTP 200, 음성 질문 저장 및 확인 대기 상태 확인.
- 시험의 이름이 같아도 여러 월의 일정이 있으면 적용 기간을 선택하도록 `clarify` 처리하는 회귀 검증을 포함한다.
- 빌드 중 기존 Next 16.4.3과 `follow-redirects`의 취약점을 확인했다. Next/ESLint 설정을 16.4.6으로, `follow-redirects`를 호환 패치로 갱신했다. `npm audit --omit=dev` 결과 2건 → 0건이다. 개발 의존성까지 모두 무결하다는 의미는 아니다.
- 실제 Cloudflare secret 이름 목록에도 나이스/Speech/Voice 인증정보가 없음을 확인했다. 값은 출력하거나 저장하지 않았다.
