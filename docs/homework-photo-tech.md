# AXR 학원 AI 비서 기술 문서 — 교재 사진 숙제와 유형 분석

기준 2026.11.16 · 브랜치 `feat/photo-reading-accuracy` 1916be7

## 1. 구성과 데이터 계약

교사가 교재 쪽 사진을 올리면 쪽수·문항 번호·원문을 읽고, 문항마다 평가원 행동영역 기준의 대분류·소분류를 제안한다. 교사가 확인한 문항으로 숙제를 배정하고, 학생은 틀린 번호를 한 번 제출하며, 교사가 확인 완료한 결과만 반 브리핑과 학생별 분석에 집계한다. 생성 모델은 판독과 유형 제안에만 쓰고, 정답률·집계는 DB 값으로만 계산한다.

| 구성 요소      | 입력과 책임                                                                                                                                                             |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 운영 웹·SQLite | 같은 Node.js HTTP 서버의 `/homework`·`/briefing` 모듈. 교재·문항·배정·제출·확인 이력·분석 초안을 SQLite에 저장한다.                                                     |
| 사진 판독      | CLOVA OCR(General)로 글자와 위치를 읽어 쪽수·번호·문항 영역을 정한다. 수학은 문항 영역을 잘라 HCX-005로 수식을 다시 읽는다. OCR 미설정 시 HCX-005 쪽 판독으로 대체한다. |
| 유형 분류      | HCX-007에 과목 기준서(`rubrics/*.md`)와 원문을 보내 소분류 태그를 받고, 태그마다 원문 인용을 검사한다.                                                                  |
| 대분류 추천    | 문항마다 HCX-007에 대분류 하나(수학 4개, 영어 7개 중)를 묻는다. 예시는 새로 지은 문항만 쓴다.                                                                           |
| 집계           | 확인 완료(`confirmed_at`)된 제출과 배정 당시 문항 스냅샷으로 전체·대분류·소분류 정답률과 많이 틀린 문항을 계산한다. AI를 부르지 않는다.                                 |

### 데이터 흐름

사진은 분석 요청 동안 메모리에서만 쓰고 저장하지 않는다. 판독·분류 결과는 교사별 분석 초안(`homework_analysis_drafts`)으로 24시간 보관하며, 화면에는 초안 ID(`sourceId`)와 제안 값만 돌려준다. 교사가 쪽수·번호·유형을 고쳐 배정하면 교재 문항(`book_questions`)과 배정 당시 스냅샷(`homework_question_snapshots`)이 생긴다. 교재 문항과 스냅샷에는 쪽수·번호·유형만 남고 문항 원문은 남지 않는다. 원문은 분석 초안과 함께 24시간 뒤 지워진다.

### 문항의 식별

교재는 학원·과목(M/E)·이름·학년·학기·개정판 조합으로 식별한다. 교재 문항은 교재·쪽수·인쇄 번호로 고정하고 `version`을 가진다. 숙제 문항은 배정 시점의 쪽수·번호·태그·기준서 버전(`rubric_version`)을 스냅샷으로 따로 저장하므로, 나중에 교재 문항의 유형을 바꿔도 지난 숙제의 집계는 바뀌지 않는다.

### 운영 진입점

통합 운영 웹의 `/homework`(숙제 목록·제출·확인), `/homework?view=books`(교재 목록), `/homework?view=create`(숙제 등록), `/homework?view=review`(확인할 제출물), `/homework?view=analysis`(학생별 분석), `/briefing`(반 브리핑)에서 이 흐름을 쓴다. 분류 파이프라인은 같은 코드를 CLI(`npm run classify`)와 평가 스크립트에서도 실행한다.

## 2. 사진 입력과 판독 경로

| 단계      | 처리 방식                                                                                                                  |
| --------- | -------------------------------------------------------------------------------------------------------------------------- |
| 권한·과목 | 관리자·교사만 분석할 수 있다. 과목은 M/E이고, 계정이 볼 수 있는 반 중 그 과목(반 과목에 '수학'·'영어')의 반이 있어야 한다. |
| 파일 검사 | 5 MB 이하. 확장자가 아니라 첫 바이트(PNG `89504e47…`, JPEG `ffd8ff`)로 형식을 판단한다. 그 밖은 415.                       |
| 키 확인   | `CLOVA_STUDIO_API_KEY` 또는 `RAG_CLOVA_API_KEY`가 없으면 503. 키는 서버 환경 변수에서만 읽는다.                            |
| 판독 선택 | `CLOVA_OCR_INVOKE_URL`·`CLOVA_OCR_SECRET`이 있으면 OCR 경로(`readSheetService`), 없으면 HCX-005 쪽 판독(`readSheet`).      |
| 분류·추천 | 판독된 문항 전체를 한 번에 HCX-007로 분류하고, 수학이면 문항마다 대분류를 추천한다.                                        |
| 초안 저장 | 결과를 문항별 초안으로 저장하고 쪽수·번호·대분류·소분류·검수 사유를 돌려준다. 만료된 초안은 다음 분석 때 지운다.           |

### 두 판독 경로

OCR 경로는 결과가 결정적이고 문항 나누기를 모델이 만든 JSON에 의존하지 않으므로, 형식 오류로 쪽 전체를 잃지 않는다. HCX-005 쪽 판독 경로는 수학을 두 번 읽어 비교하고 사진과 전사를 한 번 더 대조하며(쪽당 3회), 영어는 한 번 읽는다. 두 판독이 선택지·배점만 다르면 합의한 발문으로 통과시키고, 발문이 다르면 그 문항을 보류한다.

### 실패와 검수 대상

어떤 판독·분류 호출이든 실패하면 사진 전체를 502로 돌려준다. 문항 단위 문제는 실패로 만들지 않고 검수 대상으로 표시한다. 수식 다시 읽기 실패, 빈 원문, 분류 모델의 '읽기 불가' 판정이 여기에 해당한다. 검수 대상에는 OCR 글 등 판독 후보를 함께 보여 주고, 교사가 원문을 고쳐 보내면 그 문항만 다시 분류한다(`[불명]`이 남아 있으면 거절).

구현 경로 `src/features/academy-operations/homework-classifier.ts` · `src/features/question-classification/pipeline.mjs` · `read-page.mjs`

## 3. CLOVA OCR 판독과 문항 나누기

### 줄과 단 순서

OCR 응답의 글자 조각을 줄 끝 표시(`lineBreak`)로 묶어 줄마다 상자와 최저 신뢰도를 남긴다. 쪽 전체 폭의 가운데에서 폭의 3% 여유를 두고 왼쪽·오른쪽 줄이 각각 3줄 이상이면 두 단으로 본다. 두 단이면 단보다 위의 가로지르는 줄(제목·머리글), 왼쪽 단 전체, 오른쪽 단 전체, 단 아래의 가로지르는 줄 순서로 읽는다. 한 단이면 위에서 아래 순서다.

### 쪽 번호

쪽 위·아래 가장자리(쪽 높이의 8%) 안에서 숫자만 있는 줄을 쪽 번호로 본다. `2`, `2 20`, `- 24 -` 형태를 받는다. 교사가 쪽수를 직접 입력하면 그 값을 쓴다.

### 문항 번호와 공유 지문

| 표기                    | 처리                                                                                                   |
| ----------------------- | ------------------------------------------------------------------------------------------------------ |
| `5.` · `12)` · `0012`   | 줄 맨 앞의 번호를 문항 시작으로 본다. 네 자리 번호는 마침표 없이도 받는다.                             |
| 번호 증가 조건          | 앞 번호보다 크고 10 이내로 늘어날 때만 받는다. 본문 속 숫자를 문항 번호로 오인하지 않기 위한 조건이다. |
| `[41~42]` 머리말        | 공유 지문으로 모아 범위 안 각 문항 원문 앞에 붙인다.                                                   |
| 원문 앞에 되풀이된 번호 | 판독 정리에서 걷어 낸다(`$6.$`, `$19$.`, `7.`, `0012` 등).                                             |

### 문항 영역

번호 줄이 있는 단(두 단이면 왼쪽·오른쪽 절반)의 폭 전체를 가로 범위로, 번호 줄부터 같은 단의 다음 문항 번호 줄 바로 위(없으면 그 단의 마지막 줄)까지를 세로 범위로 잡는다. 읽기 순서로 모은 줄들의 상자를 합치는 방식은 단 순서가 어긋난 줄 하나 때문에 이웃 문항까지 잘려 들어가서 쓰지 않는다. 이 수정으로 수식 일치도 평균이 0.623에서 0.897로 올랐다(10절).

구현 경로 `src/features/question-classification/ocr-page.mjs` (`fieldsToLines` · `readingOrder` · `findPrintedPage` · `segmentItems` · `itemRegions`)

## 4. 수학 수식 판독

### 과목별 원문

영어는 OCR 글을 그대로 원문으로 쓴다. 수학은 OCR이 수식 구조를 잃으므로(예: `√2×∛4` → `V2×4`) 문항 영역을 잘라 HCX-005로 다시 읽는다.

### 자르기와 판독

| 항목      | 값과 이유                                                                                                      |
| --------- | -------------------------------------------------------------------------------------------------------------- |
| 여백·배율 | 영역 둘레 20px, 1.5배 확대. 긴 변은 2,000px 이하.                                                              |
| 비율 보정 | HCX-005가 너무 길쭉한 이미지를 HTTP 400으로 거절하므로 흰 여백으로 가로세로 비율을 4:1 안에 맞춘다.            |
| 지시문    | 문항 번호와 선택지(①~⑤)를 빼고 발문·조건·<보기>를 옮기며, 수식은 `$...$` 안의 LaTeX로 쓰고 풀이는 쓰지 않는다. |
| 출력 정리 | 코드 울타리, `<box>` 태그, 앞에 되풀이된 번호를 지운다.                                                        |
| 재시도    | HTTP 429일 때만 3초 뒤 한 번 더 요청한다. 출력 한도 1,500 토큰.                                                |
| 실패      | 영역을 못 찾거나 판독이 비거나 오류면 그 문항을 보류하고 OCR 글을 교사 확인용 후보로 남긴다.                   |

### 실제 원본 확인

10월 고3 미적분 2쪽 사진에서 5·6·7번 번호, 쪽 번호 2, 수식이 모두 맞게 읽혔다. 6번 판독 원문은 다음과 같다.

```
$\dfrac{\pi}{2}<\theta<\pi$인 $\theta$에 대하여 $\tan^{2}\theta =2$일 때, $\cos\theta$의 값은? [$3$점]
```

구현 경로 `ocr-page.mjs` (`cropRegion` · `ITEM_PROMPT` · `tidyItemReading` · `readSheetService`) · `read-image.mjs`

## 5. 유형 분류와 근거 검증

### 기준서와 태그

평가원 『2026학년도 수능 학습 방법 안내』의 행동영역 설명을 바탕으로 수학 11개(대분류 계산·이해·추론·문제 해결), 영어 14개(대분류 7개) 소분류를 정했다. 태그 목록은 `rubrics/tags.json`(기준서 버전 1.0), 판정 기준은 `math-behavior-rubric.md`·`english-behavior-rubric.md`다.

### 요청 형식

| 항목      | 처리                                                                                                                                                        |
| --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 모델·설정 | HCX-007, `thinking.effort=none`, 출력 한도 4,096, CLOVA `responseFormat` JSON 스키마. `CLASSIFICATION_MODEL`로 바꿀 수 있다.                                |
| 문항 ID   | 숫자가 태그 번호로 새어 들어가지 않도록 숫자 없는 임시 ID로 바꿔 보내고 응답에서 되돌린다.                                                                  |
| 응답 항목 | 문항마다 `assessed`(태그·인용·행동·상태·근거) 또는 `insufficient_evidence`·`out_of_scope`·`unreadable`. 영어는 태그 1개, 수학은 여러 개와 `reference` 상태. |
| 그림 정보 | HCX-005 쪽 판독 경로가 남긴 그림 정보는 원문 뒤 `[그림N]` 줄로 붙인다. 그림이 필수인데 근거가 추정·불명 그림뿐이면 그 태그를 보류한다.                      |

### 인용 검사

태그마다 모델이 고른 인용이 원문에 실제로 있는지 찾는다. 글자·숫자·기호의 순서는 그대로 대조하고, 따옴표 종류, 공백·줄바꿈, 밑줄 위치 표시(①~⑳), 수식의 `$`·중괄호·`\left`·`\right`·간격 명령만 같게 본다. 찾으면 원문 구간으로 인용을 바꿔 저장하고, 못 찾으면 그 태그를 `held`(원문 인용 확인 실패)로 바꾼다. 같은 태그가 두 번 나오고 판정이 갈리면 그 태그만 보류한다.

### 재시도 규칙

응답이 형식 검증을 통과하지 못하면(빈 근거, 문항 수 불일치, 깨진 JSON) 같은 요청을 한 번 더 보낸다. 두 번째 응답은 느슨하게 받아, 빠졌거나 중복된 문항만 `unreadable`로 두고 나머지는 살린다. HTTP 오류와 출력 한도 도달은 재시도하지 않는다.

구현 경로 `src/features/question-classification/classify.mjs` (`buildInstructions` · `aliasItemIds` · `findQuote` · `verifyResponse` · `annotateEvidence`) · `pipeline.mjs` (`classifyAssignment`)

## 6. 대분류 추천

### 방식

소분류 태그를 먼저 정하고 대분류를 따라가게 하는 방식은 실제 시험 문항에서 수학은 '전부 이해' 기준선보다 낮았고, 영어도 직접 고르는 방식보다 낮았다(10절). 그래서 대분류 하나를 직접 고르게 하는 요청을 따로 보낸다. 지시문에는 대분류 정의와 새로 지은 예시(수학 11개 전부, 영어는 발문이 비슷한 6개)를 넣고, `{"area":"…"}` 하나로 답하게 한다.

| 항목        | 수학                                                                                                           | 영어                                                                                                      |
| ----------- | -------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| 대분류      | 계산·이해·추론·문제 해결                                                                                       | 중심 내용 파악·세부 정보 파악·함축적 의미 추론·맥락 파악·간접 말하기·간접 쓰기·언어형식·어휘              |
| 정의        | 평가원 출제의도 방식(계산·이해·추론·문제해결의 구별 기준)                                                      | 영어 기준서 소분류 14개를 대분류별로 묶고, 발문(무엇을 고르라고 하는지)으로 판단하게 한다                 |
| 입력 정리   | 배점과 선택지 줄(①~⑤)을 지운다. 선택지가 남아 있으면 모델이 대분류 대신 풀이를 써서 추천이 비는 경우가 있었다. | OCR 글을 그대로 쓴다(측정 조건과 같다).                                                                   |
| 유사도      | 공백을 지운 글자 2-gram 빈도의 코사인                                                                          | 한글만 남긴 글자 2-gram 코사인. 지문 내용은 문항마다 제각각이라 빼고, 한글 발문으로 비슷한 문항을 찾는다. |
| 예시 고르기 | 지어낸 예시 11개를 모두 붙인다.                                                                                | 지어낸 예시 19개 중 발문이 가장 비슷한 6개.                                                               |
| 지어낸 예시 | 평가원 출제의도 문장(예: '지수법칙 계산하기'→계산)에 맞춰 새로 지은 문항                                       | 소분류마다 흔한 발문 형태와 새로 지은 짧은 영어 문장. 시험 문항을 옮긴 것이 아니다.                       |

응답은 전체를 JSON으로 읽지 않고 마지막 `"area"` 값만 꺼내 목록의 대분류 이름(띄어쓰기 무시)으로 맞춘다. JSON이 없으면 처음 나온 대분류 이름을 쓴다. 모델은 HCX-007, 출력 한도 200, HTTP 429일 때 3초 뒤 한 번 더 요청한다. 실패하면 추천 없이 기존 분류 결과를 그대로 쓴다.

### 소분류와 합치기

추천 대분류가 있으면 기존 분류의 소분류 태그 중 그 대분류에 속한 것만 남긴다. 남은 채택 태그가 없으면 문항 상태를 `no_adopted`로 바꿔 교사가 소분류를 고르게 한다. 화면은 추천 대분류를 미리 골라 둔다.

### 문항 원문을 예시로 쓰지 않는 이유

교사가 확인한 학원 교재 문항을 예시로 쓰면 정확도가 더 오를 것으로 보인다(다른 달 실제 문항 예시로 수학 64.1%, 영어 99.0%). 하지만 그러려면 교재 문항 원문을 기한 없이 저장하고 이후 요청마다 CLOVA로 보내야 한다. 교재 원문은 출판사 저작물이고 기존 설계도 원문을 24시간 뒤 지우므로, 원문은 저장하지 않고 새로 지은 예시만 쓴다.

구현 경로 `src/features/question-classification/area-suggest.mjs` (`suggestArea` · `chooseExamples` · `parseArea`) · `homework-classifier.ts` (`suggestAreas` · `withArea`)

### 배정과 제출

교사는 문항(최대 300개)을 확인한 뒤 제목, 여러 반 또는 학생 개별 대상, 마감 날짜(필수)·시간(선택)을 정한다. 마감은 한국 시간이며 시간을 비우면 그 날짜가 끝날 때까지다. 학생은 교재·쪽수·번호를 보고 틀린 번호 또는 '모두 맞음'을 한 번 제출하고, 마감 뒤 제출은 지각으로 표시한다.

### 교사 확인과 정정

교사가 개별 또는 일괄로 '제출 내용 확인 완료'를 누르면, 교사가 고친 오답 번호로 문항별 점수(정답 1, 오답 0)를 다시 쓰고 `confirmed_at`과 `review_version`을 올리며 `homework_grade_revisions`에 이력을 남긴다. 화면이 보낸 버전과 현재 버전이 다르면 409로 막아 동시 수정을 방지한다. 이미 확인한 제출을 고칠 때는 정정 사유가 필수다.

## 8. 정답률 집계

### 집계 입력

반 브리핑과 학생별 분석은 같은 함수로 계산한다. 확인 완료된 제출만 읽고, 숙제·교재·과목·마감 날짜 기간으로 거른다. 여러 대상 반을 함께 듣는 학생의 제출은 학생별 분석에서 한 번만 센다.

### 산식

전체 정답률은 정답 문항 수 ÷ 확인 완료 문항 수다. 대분류·소분류 정답률은 배정 당시 스냅샷의 태그로 나눈다. 한 문항에 같은 대분류 태그가 여러 개 있어도 그 대분류에서는 한 번만 센다. 기간 전체 값은 분자와 분모를 합쳐 계산한다. 많이 틀린 문항은 교재 문항별 오답 수가 많은 순서로 보여 준다.

구현 경로 `src/features/academy-operations/workbook-results.ts` (`workbookAnalytics`) · `briefing.ts`

### 수학 대분류(184문항, 한 달씩 빼고 4번 반복)

교재에는 배점이 없으므로 배점과 문항 번호를 지우고 쟀다. 예시 후보는 평가하는 달을 뺀 나머지 세 달의 문항에서만 골랐다.

| 방식                                                      | 정답            |
| --------------------------------------------------------- | --------------- |
| 모두 '이해'로 답하기(기준선)                              | 83/184 (45.1%)  |
| 참고: 소분류 태그 → 대분류(기존 분류, 10월 공통 22문항만) | 6/22 (27.3%)    |
| 대분류 직접 고르기 + 정의 + 지어낸 예시 11개 (현재)       | 100/184 (54.3%) |
| 대신 비슷한 실제 문항 예시 6개                            | 109/184 (59.2%) |
| + 예시를 같은 과목(공통·확통·미적분·기하)에서만           | 118/184 (64.1%) |

같은 조건에서 예시 10개(65.2%), CLOVA 임베딩 검색(61.4%), 예시에 출제의도 근거 추가(61.4%)는 달마다 ±4~5문항씩 엇갈려 우연 범위로 보고 채택하지 않았다. 배점만 보는 규칙(2점→계산, 3점→이해, 4점→문제 해결)이 68.5%로 더 높았지만, 배점이 없는 교재에는 옮겨지지 않아 쓰지 않는다.

### 영어 대분류(104문항, 한 달씩 빼고 4번 반복)

3·5·7·10월 영어 112문항 중 정답지에 대분류가 없는 6개와 원문이 없는 2개를 뺐다. 원문은 문제지 PDF 글자층이라 판독 영향이 없다.

| 방식                                | 정답            | 3월   | 5월   | 7월   | 10월  |
| ----------------------------------- | --------------- | ----- | ----- | ----- | ----- |
| 모두 '맥락 파악'으로 답하기(기준선) | 28/104 (26.9%)  |       |       |       |       |
| 소분류 분류 → 대분류(기존 방식)     | 76/104 (73.1%)  |       |       |       |       |
| 대분류 직접 고르기 + 정의           | 87/104 (83.7%)  | 23/28 | 24/28 | 17/22 | 23/26 |
| + 지어낸 예시 (현재)                | 90/104 (86.5%)  | 25/28 | 24/28 | 19/22 | 22/26 |
| 대신 다른 달 실제 문항 예시 6개     | 103/104 (99.0%) | 28/28 | 27/28 | 22/22 | 26/26 |

지어낸 예시만 쓸 때 틀린 14개는 모두 31~34번 빈칸 문항(정답 맥락 파악)이었다. 영어 대분류는 발문이 거의 정하므로, 발문이 비슷한 실제 문항이 예시로 들어가면 대부분 맞는다. 입력 토큰은 문항당 약 1,000~1,200이다.

### 운영 통합 확인

| 검증                        | 결과                                                                                                                          |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 실제 CLOVA, 10월 미적분 2쪽 | 번호 5·6·7, 쪽 2, 수식 정확. 대분류 추천 계산·이해·문제 해결(정답 계산·이해·이해) 2/3.                                        |
| 실제 CLOVA, 10월 영어 7쪽   | 번호 28/28. 대분류 추천 24/28(85.7%), 기존 방식 14/28. 틀린 4개는 31~34번 빈칸이며 33·34번은 앞 쪽의 공유 발문이 잘려 있었다. |
| 코드 테스트                 | 전체 테스트 통과.                                                                                                             |

### 미해결 범위

- 서비스는 교재 원문을 저장하지 않으므로 지어낸 예시만 쓴다(수학 54.3%, 영어 86.5%). 실제 문항 예시(수학 64.1%, 영어 99.0%)는 원문 보관 정책이 정해지면 다시 검토한다. 수학 54.3%는 예시마다 짧은 근거 문장을 붙인 측정이라 서비스 지시문과 완전히 같지는 않다.
- 정답지 대분류는 평가원 출제의도 기준이라 학원 교재 문항의 '정답'과 같다는 보장이 없다. 학원 교사가 붙인 대분류로 만든 평가 세트는 아직 없다.
- 영어 99.0%는 발문이 정형화된 모의고사의 값이다. 발문이 다양한 교재에서는 낮아질 수 있다. 공유 발문(`[31~34]`)이 앞 쪽에 있으면 사진 한 장만으로는 발문을 잃는다.
- 판독 비교와 대분류 측정 스크립트는 저장소에 넣지 않았다(로컬 전용). 한 회차 측정의 한두 문항 차이는 실행마다 달라질 수 있다.
