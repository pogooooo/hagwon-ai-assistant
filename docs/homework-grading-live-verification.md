## 무엇을 실행했나

- 실제 로컬 HTTP 서버에 강사·학생·보호자 계정으로 로그인했다. 일반 업로드·검수·확정·리포트 폼 경로를 사용했다.
- 각 묶음은 PNG 국어 1쪽, JPG 영어 1쪽, 이미지가 들어 있는 스캔 PDF 수학 1쪽으로 제출했다. PDF는 실제로 렌더링한 후 모델에 전달했다.
- HCX-005가 모든 문항을 전사한다. 등록 정답은 판독 요청에 전달하지 않는다. 객관식·등록 단답·숫자·단위·형식 점수는 코드로 비교하고, 의미 단답은 HCX-007이 승인 루브릭에 따라 제안한다.
- 문항 초안을 먼저 평가·기록한 후 강사 역할 계정이 수정·확정한다. 강사 수정 결과가 맞았다는 사실을 AI 초안 정확도에 포함하지 않는다.
- 확정 후 원문·전사·임시 초안의 삭제 확인, 보호자 리포트 승인 전/후 접근, 리포트의 실제 AI 사용과 수치 근거를 검사했다.
- 추가 12문항에서는 최종 확정 통계가 실제 상담 경로의 과목별 값·인용에 연결되는 것까지 확인했다. 수치 조회는 추가 생성 호출 없이 기존 근거 기반 답변을 사용했다.

## 문항 수와 선정 기준

서로 다른 문항은 27개다. 개발 확인용 15개를 6번 실행하고, 이후 고정한 새 12개를 1번 실행했다. 재실행을 새로운 문항 수로 세지 않는다. 초기에 실패한 실행도 history.json에 남겼다.

문항은 직접 작성했다. 국어는 맞춤법·띄어쓰기·부정·원인 표현, 영어는 어형·철자·대소문자·의미 보존, 수학은 정수·분수 동치·기약분수 부분점수·단위·객관식·오답을 포함했다. 개발 묶음에는 빈칸과 고의로 알아볼 수 없게 그린 답안도 넣었다. 추가 묶음은 구현 수정에 쓰지 않은 별도 문항이며, 그 오류에 맞춰 정답이나 채점 판정 로직을 변경하지 않았다.

이미지는 [Nanum Pen Script](https://github.com/google/fonts/tree/main/ofl/nanumpenscript) 필기체와 직접 그린 선으로 렌더링했다. 이는 실제 학생 필체·휴대전화 촬영 자료가 아니며 학원 독립 평가도 아니다. 공개 폰트는 검증 시 로컬에 받아 사용했고 저장소 의존성으로 추가하지 않았다.

## 채점 기준

정답표는 모델 호출 전 고정했다. 문항 ID·학생·과제·과목이 맞고, 점수와 정오답 상태가 모두 같아야 해당 AI 판정이 일치한 것으로 본다. 근거 없는 만점과 판독 불가의 강제 채점은 별도로 검사한다. 기존 grading-eval-3.0을 사용했으며 정답을 바꿔 통과시키지 않았다.

- 전체 기준 일치율: 맞는 AI 판정 수 / 채점 가능한 고정 문항 수. 보류·누락·호출 오류도 분모에서 빼지 않는다.
- 채점률: AI가 점수를 제안한 문항 수 / 채점 가능한 고정 문항 수.
- 채점한 문항에서의 일치율: 맞는 판정 수 / AI가 점수를 제안한 문항 수. 이것을 전체 정확도로 표시하지 않는다.
- 의도적으로 읽을 수 없게 그린 1개는 기대값이 보류/null이다. 채점 가능 14개의 분모에 포함하지 않고 강제 점수 생성 여부를 별도로 본다. 평가기의 failures 배열은 이런 보류도 deferred로 열거하므로 이를 오채점 1건으로 읽지 않는다.
- 여기의 채점 정확도와 예제 학생의 정답률은 다르다. 예제 학생의 오답을 올바르게 0점으로 판정해도 AI 판정은 일치한 것이다.

## 실제 실행에서 찾아 고친 부분

1. HCX-007에는 maxTokens 대신 maxCompletionTokens와 thinking=none을 사용하고 JSON Schema로 응답을 제한했다. 공식 [추론 API](https://api.ncloud-docs.com/docs/clovastudio-chatcompletionsv3-thinking)와 [Structured Outputs](https://api.ncloud-docs.com/docs/clovastudio-chatcompletionsv3-so)를 확인했다. 기존 파라미터 단독의 실패 효과는 별도 실험으로 분리 측정하지 않았다.
2. 긴 문항·루브릭·통계 ID를 모델이 그대로 복사하게 하지 않고 짧은 임시 ID를 사용했다. 응답은 서버의 허용 목록으로만 원래 ID에 복원하며 다른 ID는 거부한다.
3. 한 문항이나 한 페이지의 잘못된 응답이 다른 페이지까지 지우지 않도록 분리했다. 모두 실패하면 공급사 장애로 처리한다. 알 수 없는 항목은 임의 대상에 연결하지 않는다.
4. 기존 JSON 직렬화 복구 함수를 재사용했다. 답안 의미나 정답을 보충하지 않고 문법만 복구하며 이후 엄격한 계약 검증을 적용한다. 출력 잘림은 복구하지 않는다.
5. 한 요청에 이미지 한 장만 보내므로 실제 출처 페이지는 서버가 결정한다. 모델이 쪽 번호를 1로 되돌려 적어도 다른 페이지에 연결하지 않는다.
6. 모델이 추정한 사각형으로 잘라 다시 읽는 방식은 주변 문항·문자 문맥이 빠져 과도한 보류를 만들었다. 네이버 기본 검증은 페이지별 두 전사 비교로 바꿨고 두 번째는 문자·공백·단위를 따로 강조한다. 같은 모델의 두 응답은 독립 모델의 검증이나 정답 증명이 아니다.
7. 단위가 답 문자열에 붙어 있거나 별도 필드로 오는 차이는 관측된 단위를 분리해 비교한다. 숫자를 바꾸거나 단위를 추정하지 않는다. 상충하는 단위는 보류한다.
8. 리포트는 과목마다 별도 사실을 사용하도록 최소 항목 수·근거 ID 개수를 제한했다. 근거 검사 실패의 안전한 코드와 정형 대체 여부를 남긴다.
9. 강사 화면에서 전체 페이지를 먼저 확인하고 원본 크기로 열 수 있게 했다. 문항별 확대는 AI 추정 영역으로 표시한다. 리포트는 유형 ID 대신 등록 유형명을 쓴다.
10. 검증 중 취소·권한 변경이 있으면 후속 의미 채점·초안 쓰기를 차단한다. 무효 인증키는 후속 호출을 중단하고 실제 요청 수는 DB 한도로 제한한다.

## 호출과 보존

7회 흐름 시험의 실제 NAVER 요청은 48건이다. 별도 연결 확인 1건과 응답 형식 진단 1건을 더해 이번 작업의 실제 호출은 50건이다. 27개는 고유 문항 수이며 호출 수와 같지 않다. 실패 실행에도 사용된 호출을 포함했다. 요청별 모델·HTTP 상태·토큰·시간은 JSON에 기록했다. 원화 비용이나 계정의 전체 사용액은 측정하지 않았다.

검증 스크립트의 일일 한도는 .local/grading-validation/usage.sqlite의 60건이며 재실행해도 같은 날짜의 누적 수를 사용한다. 일반 npm test는 실제 모델을 호출하지 않는다. 키는 실행 중 프로세스에만 전달했으며 파일·커밋에 저장하지 않았다. 입력 허용 설정은 직접 만든 합성 검증에만 적용했고 운영의 실자료 승인 설정은 바꾸지 않았다.

## 재실행

서버 프로세스에 CLOVA_STUDIO_API_KEY 또는 RAG_CLOVA_API_KEY를 제공한다. AXR_GRADING_LIVE_VALIDATION=synthetic-only로 명시하고 npm run grading:validate를 실행한다. 추가 묶음은 AXR_GRADING_VALIDATION_SET=holdout을 설정한다. AXR_GRADING_VALIDATION_FONT에 필기체 TTF 경로를 지정할 수 있다. API 키 값을 명령 인수·문서·출력에 쓰지 않는다.

기본 폰트로 바꿔 실행하면 이미지가 달라지므로 동일 입력의 재현으로 보지 않는다. 실제 모델은 같은 요청·온도 0에서도 결과가 달라질 수 있다. 최신 결과는 .local/grading-validation/latest-result.json 및 묶음별 latest-development.json/latest-holdout.json에 생성된다.

## 자동 회귀 검사와 남은 제한

최종 `npm test`는 865개 통과, 실패·건너뜀 0개다. 작업 전 852개와 신규 회귀 검사 13개를 합한 수이며 실제 평가 문항 27개와는 별개다. `npm run check`의 lint·타입·포맷 검사와 `npm run build`도 통과했다. 새 회귀 검사는 실제 요청 파라미터, 인증 실패 후 호출 중단, 짧은 ID 복원, 페이지 실패 분리, 잘못된 ID와 형식이 깨진 중복 문항 차단, 페이지 출처, JSON 직렬화 복구, 전체 페이지 검증, 문자/단위 불일치 보류, 취소 후 쓰기 차단, 정형 리포트 대체 사유, 유형명과 강사 전체 사진 링크를 포함한다.

실제 학생 필체·촬영 흔들림·그림자·여러 교재·학원 자료에서의 성능과 검수 시간은 미측정이다. 원문 삭제 영수증은 자체 메모리 저장소의 논리 삭제 확인이며 공급사 보관·물리 메모리의 삭제 증명이 아니다. 운영 실자료 입력 조건, 외부 저장소/분산 작업, Cloudflare 사진/PDF 디코더 연결은 별도 과제다. 이번 작업은 Cloudflare 배포나 main 병합을 수행하지 않았다.
