## 화면 변경

- 홈의 그라데이션·홍보 문구·캐릭터 장식 영역을 제거하고 일정, 상담 요청, 숙제와 공개 자료를 실제 데이터 목록으로 배치했다.
- 직원의 상담·제출물 건수는 한 줄의 업무 요약으로 표시한다. 비어 있는 목록은 짧은 안내로 표시한다.
- 같은 크기의 서비스 카드 묶음을 아이콘과 이름으로 된 메뉴로 바꿨다. 캐릭터는 프로필·상담 안내·로그인에 작게 유지한다.
- 홈의 중복 상담 배너를 제거했다. 질문 입력과 이전 상담 진입은 기존 동작을 유지한다.
- 상담은 목록/대화 구조로 정리하고 추천 질문을 단순한 행으로 표시한다. 답변 원문과 근거 펼침은 유지한다.
- 모바일 상담 관리에서는 처리할 목록을 먼저 표시한다. 일반 상담에는 목록으로 이동하는 링크를 제공한다.
- 모바일 입력에 초점이 있을 때 하단 메뉴를 숨기고 초점이 해제되면 복원한다. 이는 브라우저 레이아웃 검증이며 실제 기기의 소프트 키보드 검증을 대신하지 않는다.
- CSS 버전을 v7로 올렸다. API·권한·AI 공급자·DB 스키마는 변경하지 않는다. 새 패키지나 이미지 자산은 추가하지 않는다.

## 검증

```powershell
npm run check
node --disable-warning=MODULE_TYPELESS_PACKAGE_JSON --test src/features/academy-operations/service-ui.test.ts src/features/academy-operations/server.test.ts
node --disable-warning=MODULE_TYPELESS_PACKAGE_JSON scripts/verify-service-browser.mjs --responsive --out .local/service-layout-review
```

`--responsive`는 역할별 화면을 1440/1024/820/768/390/360/320px로 검사하고 로그인도 포함한다. 페이지 응답, 가로 넘침, 스크립트 오류, 접근성, 메뉴 조작, 질문 전달, 상담 인용, 오프라인 민감 정보 저장 여부를 확인한다. 짧은 화면 높이에서의 질문 편집, 하단 메뉴 표시 복원, 상담 목록 이동도 확인한다.

최종 결과:

- 페이지 280개 통과: 역할별 경로 총 39개 × 화면 폭 7종 = 273개, 로그인 7개.
- 390px 접근성 검사 40개 통과: 역할별 경로 39개, 로그인 1개. 자동 검출 위반 0건.
- 상호작용 10개 통과: 기존 8개에 모바일 순서/입력 초점 및 짧은 화면 편집/목록 이동 검사를 추가.
- 기존 UI·서버 테스트 15개, lint·TypeScript·서식 검사 통과.
- 320×550의 별도 재현 검사에서도 홈 질문 전달과 하단 메뉴의 숨김/복원이 정상 동작.

확장 검사 중 입력창에서 전송 버튼으로 초점이 옮겨갈 때 하단 메뉴가 다시 나타나 클릭을 가로챌 수 있는 문제를 발견했다. 개별 입력창 대신 폼 전체의 `:focus-within`으로 표시 상태를 유지하고 버튼의 스크롤 여백도 확보해 수정했다. 실패한 실행을 최종 통과 결과와 합산하지 않았다.

생성 AI를 호출하는 변경이 없어 이번 화면 검사에는 유료 AI 호출을 추가하지 않는다. 실기기·APK 검증은 포함하지 않는다.
