# 교재 숙제 개편 · DB 변경과 학습 기록 연동

2026년 11월 15일 기준 · 학습 기록 담당자 공유용 · 로컬 작업 브랜치 `feat/workbook-assignment-flow`

**새 교재 숙제는 학생이 자기 책으로 풀고 틀린 번호를 제출하면, 선생님이 내용을 확인하는 방식입니다.** 선생님이 **제출 내용 확인 완료**를 누른 결과만 새 반 브리핑과 학생별 분석에 들어갑니다. 이때 학습 기록 등록이나 상담 근거 발행은 일어나지 않습니다. 팀에서 결정할 부분은 **확인을 마친 숙제 결과를 학습 기록에 언제, 어떤 ID와 버전으로 전달할지**입니다.

## 1. 어떤 기능을 구현했나

| 누가   | 화면에서 하는 일                                                                                                                                                                                                          |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 선생님 | 학원 공용 교재 하나를 선택합니다. 저장된 문항을 가져오거나 사진을 한 장씩 분석해 쪽수·번호를 확인합니다. 유형은 수학·영어 기준서에서 대분류를 고른 뒤 해당 소분류를 선택합니다. 사진 원본은 표시하거나 저장하지 않습니다. |
| 선생님 | 선택한 문항으로 여러 쪽을 묶고, 다음 단계에서 숙제 이름·배정 대상·마감을 정합니다. 여러 반에 한 번에 배정하거나 학생을 개별 지정할 수 있습니다.                                                                           |
| 학생   | 자기 책에서 풀고 틀린 문항 또는 ‘모두 맞았어요’를 한 번 제출합니다. 지각 제출도 가능하며, 제출 후에는 ‘선생님 확인 대기’로 표시됩니다.                                                                                    |
| 선생님 | ‘확인할 제출물’에서 학생이 처음 낸 오답을 보고 필요하면 수정합니다. 한 명씩 또는 여러 제출물을 함께 확인할 수 있습니다. 확인 후 다시 고칠 때에는 정정 사유를 남깁니다.                                                    |

## 2. DB를 어떻게 바꿨나

예전에는 교재와 문항 위치가 숙제별 분류 JSON에 들어갔고, 숙제 한 건에는 반 하나가 연결됐습니다. 이번에는 **공용 교재를 관리하는 테이블 3개와 배정 당시의 정보를 보관하는 테이블 4개**를 추가했습니다. 숙제·제출·정오답·정정 이력은 기존 테이블을 재사용합니다.

| 추가한 테이블                 | 한 행이 뜻하는 것            | 연결할 때 필요한 정보                                                                                                     |
| ----------------------------- | ---------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `books`                       | 학원 공용 교재 한 권         | 학원·과목·이름·학년·학기·개정판 조합으로 구분합니다.                                                                      |
| `book_questions`              | 책에 인쇄된 문항 하나        | 교재 ID·쪽수·인쇄 번호 조합으로 재사용합니다. `version`으로 유형 수정 충돌을 검사합니다.                                  |
| `book_question_types`         | 공용 문항에 붙인 소분류 하나 | `tag_id`로 기준서의 소분류와 상위 대분류를 찾습니다. 복수 유형은 여러 행으로 저장합니다.                                  |
| `homework_workbooks`          | 숙제 한 건에 사용한 교재     | `assignment_id`당 교재 한 권입니다. 선택 마감 시간 `due_time`과 배정 방식 `target_kind`도 여기에 있습니다.                |
| `homework_targets`            | 숙제를 배정한 반 하나        | 여러 반에 배정하면 같은 `assignment_id`로 반마다 한 행이 생깁니다. 개별 배정도 해당 학생의 반을 기록합니다.               |
| `homework_recipients`         | 배정 당시 대상 학생과 그 반  | `(assignment_id, class_id, student_id)`로 실제 대상자를 식별합니다.                                                       |
| `homework_question_snapshots` | 배정 당시 문항의 사본        | 숙제 문항 `question_id`와 공용 문항 `book_question_id`를 연결하고 당시 쪽수·번호·`tag_ids`·`rubric_version`을 보존합니다. |

예를 들어 수학 교재 11쪽 22번을 이번 주 숙제와 다음 주 숙제에서 재사용하면, **공용 문항 ID는 하나이고 숙제 문항 ID는 두 개**입니다. 공용 문항의 유형을 오늘 수정해도 지난주 브리핑은 그때 배정한 유형으로 계산됩니다. 정오답을 연결할 키는 `homework_questions.id`입니다. [테이블 정의와 배정 저장 코드](../src/features/academy-operations/workbook-catalog.ts)

## 3. 학생 제출에서 브리핑까지 어떤 값을 읽나

| 시점               | 기존 테이블에 기록하는 내용                                                                                                                                                                                                                                                                           |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 숙제 배정          | `homework_assignments`에 `submission_mode='catalog'`, 제목, 마감 날짜를 저장합니다. `homework_questions`에는 숙제별 문항 ID를 만듭니다.                                                                                                                                                               |
| 학생 제출          | `homework_submissions`에 `submitted_at`을 기록하고 `confirmed_at`은 비워 둡니다. `homework_marks.response`와 `automatic_points`에는 학생이 직접 표시한 정오답을 보존합니다. 이 모드에서 `automatic_points`의 0과 1은 각각 학생이 보고한 오답과 정답입니다. `awarded_points`도 같은 값으로 시작합니다. |
| 선생님 확인·정정   | 최종 정오답을 `homework_marks.awarded_points`에 반영하고 `confirmed_at`과 `review_version`을 갱신합니다. `homework_grade_revisions`에는 해당 버전의 문항별 결과, 확인자, 시각, 정정 사유를 기록합니다.                                                                                                |
| 브리핑·학생별 분석 | 새 교재 숙제 중 `confirmed_at`이 있는 제출의 `awarded_points`와 배정 당시 유형을 읽습니다. 기간 필터는 숙제 마감 날짜 기준입니다.                                                                                                                                                                     |

**예시** · 학생이 22번을 오답으로 제출한 뒤 선생님이 정답으로 정정하면, 그 문항은 `automatic_points=0`, `awarded_points=1`입니다. 학생이 처음 체크한 번호는 숙제 상세에서 확인할 수 있고, 브리핑에는 선생님이 확인한 정답 1건이 반영됩니다. [학생 제출 코드](../src/features/academy-operations/homework.ts) · [확인·정정·집계 코드](../src/features/academy-operations/workbook-results.ts)

## 4. 기존 기능에 어떤 영향이 있나

- **반별 조회와 권한** · 기존 `homework_assignments.class_id`는 필수 컬럼이라 새 숙제에도 첫 번째 대상 반을 기록합니다. 이 값만 조회하면 두 번째 반은 빠지고, 개별 배정을 반 전체 배정으로 오해할 수 있습니다. 새 기능은 `homework_targets`와 `homework_recipients`를 조회하고, 강사의 담당 반과 학생의 현재 수강 여부도 확인합니다.
- **중복 집계** · 두 대상 반을 모두 수강하는 학생도 한 숙제에 한 번만 제출합니다. 그 제출은 각 반 브리핑에 한 번씩 들어갑니다. 두 반을 아울러 학생별 분석을 만들 때에는 같은 `submission_id`를 한 번만 셉니다.
- **과거 숙제** · 기존 `answers`·`workbook` 데이터와 ID는 유지하며, 과거 교재를 새 공용 목록으로 자동 이관하지 않았습니다. 특히 기존 `workbook`은 학생 제출 시 `confirmed_at`을 채우므로, 과거 자료까지 합산하는 쿼리는 `submission_mode`를 함께 확인해야 합니다.
- **학습 기록과 상담** · 기존 `/learning`과 상담은 기존 `op_learning_*` 경로를 사용합니다. 새 `catalog` 숙제는 제출하거나 선생님이 확인해도 해당 테이블에 복사되지 않습니다. 기존 자료의 브리핑은 ‘기존 학습 기록 브리핑’에서 볼 수 있습니다. [브리핑 진입점](../src/features/academy-operations/briefing.ts) · [학습 기록 확정과 상담 근거 발행 코드](../src/features/academy-operations/learning.ts)

## 5. 팀에서 결정할 사항

| 결정할 질문                                  | 논의할 제안                                                                                                                                                                                                                                                           |
| -------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 학습 기록 전달과 상담 공개는 각각 언제 할까? | ‘제출 내용 확인 완료’ 시 학습 기록에 초안을 전달하고, 상담 공개는 학습 기록의 기존 확정 절차에서 결정하는 방안을 검토합니다.                                                                                                                                          |
| 어떤 ID와 유형을 전달할까?                   | 숙제 ID·반 ID·학생 ID와 함께 **숙제 문항 ID**, 배정 당시 유형 ID·기준서 버전을 전달하는 방안을 검토합니다. 기존 학습 기록이 숙제 하나에 반 하나를 연결하므로 여러 반의 전달 ID를 어떻게 만들지 정해야 합니다. 개별 배정은 실제 대상 학생 범위도 함께 전달해야 합니다. |
| 확인 후 정정되면 어느 결과를 사용할까?       | 숙제의 최종 정오답과 `review_version`을 기준으로 새 버전을 전달하는 방안을 검토합니다. 학습 기록에서도 수정할 수 있게 할지, 이미 공개된 상담 근거를 언제 갱신할지도 함께 정해야 합니다.                                                                               |
| 과거 숙제까지 합산할까?                      | 이관 대상과 실제 교사 확인을 판별할 근거를 먼저 정합니다. 새 분석의 마감 날짜와 기존 학습 기록의 분석 월을 어느 기준으로 맞출지도 결정해야 합니다.                                                                                                                    |

## 적용·검증 범위

로컬 기본 SQLite DB를 백업한 뒤 테이블을 **30개에서 37개**로 확장했습니다. 적용 전후 기존 테이블의 행 수를 대조했고, 외래키 위반은 0건이었습니다. 팀원이 이 브랜치의 변경분으로 운영 서버를 시작하면 초기화 코드가 필요한 테이블을 생성합니다. 운영 환경 배포와 과거 데이터 이관은 별도 작업입니다.

회귀 테스트에서는 개별·복수 반 배정, 확인 전 집계 제외, 오답 정정, 복수 반 중복 집계 방지를 확인했습니다. 브라우저에서도 학생이 제출한 두 문항을 선생님이 확인한 뒤 반 브리핑과 학생별 분석에 정답률 50%가 표시되는 흐름을 검증했습니다. [숙제 흐름 테스트](../src/features/academy-operations/workbook.test.ts) · [실행 안내](../src/features/academy-operations/README.md)
