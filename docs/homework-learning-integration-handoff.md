# 교재 숙제 개편 · DB 변경과 학습 기록 연동

2026년 11월 15일 DB 개편 기록 · 11월 16일 분석·상담 연결 갱신 · 현재 작업 브랜치 `feat/homework-approval-analysis`

**새 교재 숙제는 학생이 자기 책으로 풀고 틀린 번호를 제출하면, 선생님이 내용을 확인하는 방식입니다.** 선생님이 **제출 내용 확인 완료**를 누른 결과만 새 반 브리핑과 학생별 분석에 들어갑니다. 상담 공개는 분석 화면에서 별도로 실행합니다. 기존 학습 기록의 숙제·결과 테이블로 복제하지 않으며, 기존 공개 기록 테이블에 새 분석 형식을 분리해 저장합니다. 아래 1~5절은 DB 개편과 기존 학습 기록 연동 검토 내용이고, 현재 구현한 상담 연결은 마지막 **2026-11-16 분석·상담 연결 반영** 절에 정리했습니다.

## 2. DB를 어떻게 바꿨나

예전에는 교재와 문항 위치가 숙제별 분류 JSON에 들어갔고, 숙제 한 건에는 반 하나가 연결됐습니다. 이번에는 **공용 교재를 관리하는 테이블 3개와 배정 당시의 정보를 보관하는 테이블 4개**를 추가했습니다. 숙제·제출·정오답·정정 이력은 기존 테이블을 재사용합니다.

| 추가한 테이블                 | 한 행이 뜻하는 것            | 연결할 때 필요한 정보                                                                                                     |
| ----------------------------- | ---------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `books`                       | 학원 공용 교재 한 권         | 학원·과목·이름·학년·학기·개정판 조합으로 구분합니다.                                                                      |
| `book_questions`              | 책에 인쇄된 문항 하나        | 교재 ID·쪽수·인쇄 번호 조합으로 재사용합니다. `version`으로 유형 수정 충돌을 검사합니다.                                  |
| `book_question_types`         | 공용 문항에 붙인 소분류 하나 | `tag_id`로 기준서의 소분류와 상위 대분류를 찾습니다. 복수 유형은 여러 행으로 저장합니다.                                  |
| `homework_workbooks`          | 숙제 한 건에 사용한 교재     | `assignment_id`당 교재 한 권입니다. 선택 마감 시간 `due_time`과 배정 방식 `target_kind`도 여기에 있습니다.                |
| `homework_targets`            | 숙제를 배정한 반 하나        | 여러 반에 배정하면 같은 `assignment_id`로 반마다 한 행이 생깁니다. 개별 배정도 해당 학생의 반을 기록합니다.               |
| `homework_recipients`         | 배정 당시 대상 학생과 그 반  | `(assignment_id, class_id, student_id)`로 실제 대상자를 식별합니다.                                                       |
| `homework_question_snapshots` | 배정 당시 문항의 사본        | 숙제 문항 `question_id`와 공용 문항 `book_question_id`를 연결하고 당시 쪽수·번호·`tag_ids`·`rubric_version`을 보존합니다. |

예를 들어 수학 교재 11쪽 22번을 이번 주 숙제와 다음 주 숙제에서 재사용하면, **공용 문항 ID는 하나이고 숙제 문항 ID는 두 개**입니다. 공용 문항의 유형을 오늘 수정해도 지난주 브리핑은 그때 배정한 유형으로 계산됩니다. 정오답을 연결할 키는 `homework_questions.id`입니다. [테이블 정의와 배정 저장 코드](../src/features/academy-operations/workbook-catalog.ts)

## 3. 학생 제출에서 브리핑까지 어떤 값을 읽나

| 시점               | 기존 테이블에 기록하는 내용                                                                                                                                                                                                                                                                           |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 숙제 배정          | `homework_assignments`에 `submission_mode='catalog'`, 제목, 마감 날짜를 저장합니다. `homework_questions`에는 숙제별 문항 ID를 만듭니다.                                                                                                                                                               |
| 학생 제출          | `homework_submissions`에 `submitted_at`을 기록하고 `confirmed_at`은 비워 둡니다. `homework_marks.response`와 `automatic_points`에는 학생이 직접 표시한 정오답을 보존합니다. 이 모드에서 `automatic_points`의 0과 1은 각각 학생이 보고한 오답과 정답입니다. `awarded_points`도 같은 값으로 시작합니다. |
| 선생님 확인·정정   | 최종 정오답을 `homework_marks.awarded_points`에 반영하고 `confirmed_at`과 `review_version`을 갱신합니다. `homework_grade_revisions`에는 해당 버전의 문항별 결과, 확인자, 시각, 정정 사유를 기록합니다.                                                                                                |
| 브리핑·학생별 분석 | 새 교재 숙제 중 `confirmed_at`이 있는 제출의 `awarded_points`와 배정 당시 유형을 읽습니다. 기간 필터는 숙제 마감 날짜 기준입니다.                                                                                                                                                                     |

**예시** · 학생이 22번을 오답으로 제출한 뒤 선생님이 정답으로 정정하면, 그 문항은 `automatic_points=0`, `awarded_points=1`입니다. 학생이 처음 체크한 번호는 숙제 상세에서 확인할 수 있고, 브리핑에는 선생님이 확인한 정답 1건이 반영됩니다. [학생 제출 코드](../src/features/academy-operations/homework.ts) · [확인·정정·집계 코드](../src/features/academy-operations/workbook-results.ts)

## 4. 기존 기능에 어떤 영향이 있나

- **반별 조회와 권한** · 기존 `homework_assignments.class_id`는 필수 컬럼이라 새 숙제에도 첫 번째 대상 반을 기록합니다. 이 값만 조회하면 두 번째 반은 빠지고, 개별 배정을 반 전체 배정으로 오해할 수 있습니다. 새 기능은 `homework_targets`와 `homework_recipients`를 조회하고, 강사의 담당 반과 학생의 현재 수강 여부도 확인합니다.
- **중복 집계** · 두 대상 반을 모두 수강하는 학생도 한 숙제에 한 번만 제출합니다. 그 제출은 각 반 브리핑에 한 번씩 들어갑니다. 두 반을 아울러 학생별 분석을 만들 때에는 같은 `submission_id`를 한 번만 셉니다.
- **과거 숙제** · 기존 `answers`·`workbook` 데이터와 ID는 유지하며, 과거 교재를 새 공용 목록으로 자동 이관하지 않았습니다. 특히 기존 `workbook`은 학생 제출 시 `confirmed_at`을 채우므로, 과거 자료까지 합산하는 쿼리는 `submission_mode`를 함께 확인해야 합니다.
- **학습 기록과 상담** · 기존 `/learning`은 기존 `op_learning_assignments`·`op_learning_results` 경로를 유지합니다. 새 `catalog` 숙제는 제출하거나 선생님이 확인해도 이 두 테이블에 복사되지 않습니다. 11월 16일 연결부터는 분석 화면에서 별도 공개한 결과가 `op_learning_publications`에 저장되어 상담에서 사용됩니다. 기존 자료의 브리핑은 ‘기존 학습 기록 브리핑’에서 볼 수 있습니다. [브리핑 진입점](../src/features/academy-operations/briefing.ts) · [기존 학습 기록 처리](../src/features/academy-operations/learning.ts)

## 적용·검증 범위

로컬 기본 SQLite DB를 백업한 뒤 테이블을 **30개에서 37개**로 확장했습니다. 적용 전후 기존 테이블의 행 수를 대조했고, 외래키 위반은 0건이었습니다. 팀원이 이 브랜치의 변경분으로 운영 서버를 시작하면 초기화 코드가 필요한 테이블을 생성합니다. 운영 환경 배포와 과거 데이터 이관은 별도 작업입니다.

회귀 테스트에서는 개별·복수 반 배정, 확인 전 집계 제외, 오답 정정, 복수 반 중복 집계 방지를 확인했습니다. 브라우저에서도 학생이 제출한 두 문항을 선생님이 확인한 뒤 반 브리핑과 학생별 분석에 정답률 50%가 표시되는 흐름을 검증했습니다. [숙제 흐름 테스트](../src/features/academy-operations/workbook.test.ts) · [실행 안내](../src/features/academy-operations/README.md)

## 2026-11-16 분석·상담 연결 반영

작업 브랜치는 `feat/homework-approval-analysis`, 기준은 팀 `main`의 `367180d`다. 위 11월 15일 기록에서 미연결이었던 **새 교재 숙제 → 분석 → 상담 근거** 경로를 연결했다. DB 스키마·마이그레이션과 사진 인식·문항 분류 파이프라인은 변경하지 않았다.

### 읽는 데이터와 집계 기준

- `homework_targets`와 `homework_recipients`로 실제 반·학생 배정을 읽는다. `homework_assignments.class_id` 하나만으로 범위를 정하지 않는다.
- `submission_mode='catalog'`이며 교사 승인 시각과 버전이 있는 제출만 사용한다. 같은 버전의 `homework_grade_revisions.scores`와 모든 `homework_marks.awarded_points`가 일치해야 한다. 누락 문항·유형 오류·승인 이력 불일치는 해당 제출 전체를 집계에서 제외하고 화면에 알린다.
- 쪽수·번호·유형은 `homework_question_snapshots`에서 읽는다. 공용 문항의 현재 유형을 과거 숙제에 덮어쓰지 않는다.
- 전체 정답률은 승인된 숙제의 모든 문항이 분모다. 유형 미지정 문항도 전체에는 포함하며 유형별 집계에서만 제외한다. 같은 대분류의 복수 소분류가 붙어도 대분류에서는 한 번만 센다.
- 학생별 합산은 `submission_id`로 중복 제거한다. 반 브리핑에는 해당 반에 배정된 제출을 각각 한 번 반영한다. 기간은 숙제 마감 날짜 기준이며 교재 ID로 개정판을 구분한다.

[조회·집계 어댑터](../src/features/academy-operations/workbook-analysis.ts)는 원본 숙제 테이블을 읽기만 한다. 브리핑과 학생별 분석이 이 어댑터의 같은 결과를 사용한다.

### 상담 공개와 정정

1. 학생 제출과 교사 승인은 상담 공개를 자동 실행하지 않는다.
2. 교사·관리자는 `숙제 → 학생별 분석 → 상담 공개`에서 학생·반·마감 월별 승인 결과를 확인하고 공개한다. 이 공개 단위는 해당 반의 **월 전체 승인 결과**다. 화면 위의 특정 교재·일자 필터와는 별도로 범위와 정답/전체 문항 수를 표시한다.
3. 기존 `op_learning_publications`에 `workbook-` 접두사의 문서 ID로 저장한다. JSON payload에는 `format='workbook-analysis-v1'`, 공개자, 원본 fingerprint, 문서, 정형 사실이 들어간다. 새 테이블이나 컬럼을 추가하지 않는다. 기존 `learning-` 기록과 숙제·문항·학생 ID를 덮어쓰지 않는다.
4. 원본 fingerprint에는 학생·교재·배정 반·숙제·마감일·승인 버전·문항별 최종 결과·배정 당시 유형이 포함된다. 조회 때 원본과 다시 대조하므로 교사 정정, 승인 취소, 문항 누락 또는 새로운 승인 결과 발생 시 이전 근거는 즉시 상담에서 제외된다. 현재 범위의 승인 결과 중 검증에 실패한 제출이 있으면 일부만 월 전체로 공개하지 않는다.
5. 원본을 확인한 뒤 다시 공개하면 새 공개 버전을 남긴다. 공개 철회는 최신 버전에 null payload를 저장하며 이전 버전이 다시 활성화되지 않는다. 공개 처리 중 결과나 권한이 바뀌면 저장을 거절한다.
6. 새 자료는 `student_private`이며 학생·보호자 관계, 강사의 현재 담당 반·수강 관계를 기존 RAG 권한 검사에 적용한다. 예전 상담도 인용 버전이 더 이상 유효하지 않으면 답변을 가린다.

기존 `/learning`의 분류 등록·결과 수정·확정 절차는 유지한다. 새 교재 데이터를 `op_learning_assignments`나 `op_learning_results`로 복제하거나 양방향 동기화하지 않는다. 기존 학습 기록 조회가 새 형식의 공개 기록을 잘못 읽지 않도록 `workbook-` 기록은 별도 어댑터로 처리한다.

### 상담의 수치와 근거

새 정형 사실의 내부 `basis`는 `approved_homework`다. 기존 `classified_assessed`와 전체 정답률 분모가 다르므로 답변에 각각의 기준을 구분한다. 사실의 유형 이름·정답 수·전체 수가 함께 있는 원문 문단만 인용한다. 원문에는 교재, 쪽수, 문항 번호, 최종 정오답, 숙제 ID와 승인 버전도 남긴다.

질문에 특정 반을 지정하면 그 반의 분석만 선택한다. 같은 과목·기간에 여러 반의 공개 분석이 있고 반을 특정하지 않았다면 확인 질문을 한다. 중복 배정된 숙제를 임의 합산하지 않는다. 기존 학습 기록과 새 숙제 기록도 자동으로 합치지 않으며, 서로 충돌하는 근거는 기존 충돌 검사에 따라 보류한다.

### 이번 검증

신규 회귀 10개를 추가했다. DB 승인 기록과 정오답 일치, 미지정 유형의 분모, 복수 유형·반의 중복 방지, 과거 사본 보존, 기간·교재 필터, 상담 공개·정정·철회, 최신 인용 문단, 권한·반 이동, 동시 수정, 반별 근거 선택과 HTTP 전체 흐름을 검증한다. 테스트는 메모리/임시 SQLite와 가상 계정으로 실행하며 실제 운영 DB를 변경하지 않는다. 스키마가 공개 처리 전후 같다는 검사도 포함한다.

기준 `367180d`의 전체 테스트는 655/655 통과였고, 변경 후 전체 테스트는 **665/665 통과**했다. 실패·건너뜀은 0개다. 기존 테스트 삭제·비활성화 없이 10개를 추가했다. `npm run check`의 린트·타입·서식 검사도 통과했다. 로그는 로컬 `.local/homework-baseline-tests.log`, `.local/homework-analysis-final-tests.log`, `.local/homework-analysis-check.log`에 보존했다.

브라우저에서는 1440px·390px에서 분석 화면, 공개 버튼, 보호자 상담, 인용 원문, 정정 후 이전 답변 차단을 확인했다. 이번 검증은 정형 조회·집계·RAG 연결 검증이며 외부 생성 AI를 호출하지 않았다. 새로운 상담 정확도 평가나 문제 인식 성능 평가를 의미하지 않는다.
