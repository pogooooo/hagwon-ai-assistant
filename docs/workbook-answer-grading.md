# 교재 정답 채점 기술 문서

작성일 2026년 11월 22일. 교재 숙제를 사진 채점(`/grading`) 화면 안에서 등록·제출·검수하는 방식을 설명한다. 요구사항 변경 내역은 [기획서 0절](homework-workflow-plan.md)에 있다.

## 흐름

1. **과제 등록**(교사, 과제 등록 탭)
   - 학원 공용 교재를 고르거나 새로 등록한다.
   - 교재 사진 한 장씩 분석해 쪽수·문항 번호·대분류·소분류를 찾고, 문항마다 정답을 입력한다. 객관식을 체크하면 정답 보기 번호(예: `3`)를 입력한다. 주관식은 체크를 해제하고 수와 단위(`5/6 L`) 또는 글자 답을 입력한다. 인정할 답이 여럿이면 `|`로 구분한다.
   - 정답과 유형은 `book_questions`에 저장되어 같은 교재의 다음 과제에 다시 쓴다. 과제를 만들 때 문항마다 정답·대표 유형을 복사하므로 교재를 고쳐도 지난 과제는 바뀌지 않는다.
   - 반을 여러 개 고르면 반마다 과제를 하나씩 만든다.
2. **학생 제출**(숙제 제출·대리 제출 탭)
   - 학생은 푼 교재 사진을 올린다. 사진 없이 답만 내는 제출은 받지 않는다.
   - CLOVA OCR로 사진마다 책 쪽수를 찾는다. 인쇄된 쪽 번호를 우선 쓰고, 못 읽으면 사진에서 찾은 문항 번호가 가장 많이 겹치는 과제 쪽으로 정한다. 모든 사진이 서로 다른 쪽으로 확정되면 사진 순서를 쪽 순서로 바꾼다.
   - 객관식은 체크 감지기로 학생이 표시한 보기를 읽어 확인 화면에 미리 채운다. 학생이 고치거나, 못 읽은 문항을 직접 고른 뒤 제출한다.
   - 등록한 정답과 비교해 자동 채점한다. AI 풀이·판독(HCX)은 호출하지 않는다.
3. **검수와 확정**(제출 검수 탭)
   - 답마다 출처를 기록한다: `photo`(사진에서 읽은 답 그대로), `photo_edited`(학생이 고침), `typed`(사진에서 못 읽어 학생이 고름). 학생이 고친 문항과 못 읽은 문항은 검수 화면 위쪽 요약과 문항 표시로 먼저 보이게 한다.
   - 사진은 최대 1시간(`AXR_GRADING_RAW_TTL_MS`) 보관하고 검수 화면에서 원본을 연다.
   - 확인 필요 목록에서 여러 제출을 골라 한 번에 확정할 수 있다. 교사 판단이 필요한 문항이 남은 제출은 건너뛰고 개별 검수로 남긴다.
4. **집계**: 확정 결과는 기존 채점 리포트·브리핑·학습 기록 집계(`computeFacts`)를 그대로 쓴다. 문항 유형 이름이 `대분류 · 소분류`(예: `계산 · 식 정리`)로 표시된다.

## 사진 읽기

교재 등록에서 CLOVA OCR이 쪽수를 놓치면 사진 하단을 세 구역으로 나누고, OCR에서 글자를 찾지 못한 구역만 확대해 서버의 Tesseract로 읽는다. 선명한 숫자가 한 구역에서만 확인되면 쪽수에 채운다. 로컬·NAVER Cloud 서버의 모델 캐시에 `eng.traineddata`가 있어야 한다. 경로는 `RAG_MODEL_CACHE_DIR/tesseract`이며 기본값은 `~/.cache/axr-rag-models/tesseract`다. 모델이 없거나 판독이 모호하면 교사가 쪽수를 입력한다.

| 단계                | 방법                                                                                                                                                                                                                    | 코드                                                |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------- |
| 문항 번호·영역·쪽수 | CLOVA OCR General 1회/쪽. 각 단에서 왼쪽 위치가 같은 숫자 줄을 문항 번호로, 위에서 아래로 커지는 가장 긴 묶음을 고른다. `01`처럼 0을 붙인 번호가 있으면 그런 번호만 받는다.                                             | `ocr.ts` `layoutFromLines`                          |
| 보기 배치           | OCR이 읽은 ①~⑤ 위치로 한 줄에 몇 개씩(5·3·2·1) 놓였는지 정하고, 못 읽은 기호 위치를 같은 간격으로 채운다. 같은 기호가 두 번 읽히면 신뢰도가 높은 쪽을 쓴다.                                                             | `ocr.ts` `choiceGrid`                               |
| 표시한 보기         | 보기 기호 주변의 어두운 픽셀 수에서 중앙값을 뺀 초과량을 비교한다. 초과량이 10픽셀 이상이고 둘째의 3배 이상이면서 그 기호를 OCR이 못 읽었으면 표시로 본다. OCR이 기호를 읽었다면 4배 이상을 요구한다. 아니면 비워 둔다. | `media.ts` `pickMarkedChoice`, `detectMarkedChoice` |

- 학생 사진을 OCR로 보내는 것은 외부 전송이므로 `AXR_GRADING_EXTERNAL_DATA_APPROVED=true`일 때만 하고, OCR 주소는 `*.apigw.ntruss.com`만 허용한다.
- CLOVA Studio가 분당 한도(HTTP 429)를 돌려주면 `AXR_GRADING_RATE_LIMIT_WAIT_MS`(기본 20초)만큼 기다렸다 두 번까지 다시 보낸다.
- Cloudflare Workers에는 픽셀을 읽는 기능(`darkPixels`)이 없어 체크 감지를 건너뛴다. 이때 학생이 확인 화면에서 모든 답을 고른다. Workers용 미디어 런타임에 `darkPixels`를 추가하면 같은 코드가 동작한다.

## 측정

시연용 예시 문제지(직접 만든 12문항, 객관식) 손글씨 사진 2쪽.

| 조건                                                            | 결과                                                                 |
| --------------------------------------------------------------- | -------------------------------------------------------------------- |
| 이전 방식: HCX-005 쪽 전체 판독                                 | 표시한 보기를 7문항 중 1문항 맞게 읽음, 자동 판정 0                  |
| HCX-005에 문항 하나만 잘라 질문                                 | 6문항 중 2문항(우연 수준)                                            |
| 저해상도 596×844 / 고해상도 1500×2000, 체크 감지기              | 각 12/12, 보류 0, 오판 0                                             |
| 고해상도 사진을 쪽 순서를 뒤집어 제출 → 확인 화면 → 그대로 제출 | 순서 바로잡음, 미리 채움 12/12, 자동 채점 12/12 정답, OCR 2회·약 4초 |

판정 기준값(초과량 10픽셀, 3배·4배)은 이 두 사진 세트로 정했다. 다른 학생의 손글씨, 동그라미 표시, 기울어진 사진으로 다시 확인해야 한다. 측정 스크립트와 결과는 로컬 `.local/grading-baseline/`에 있다.

## 체험 데이터

체험 학원의 두 활동지(분수 계산 복습, 일과와 약속 시간 복습)는 서버를 켤 때 교재 과제로 등록된다. 문항·대표 유형·정답은 `demo-homework-materials.ts`에 있으며, 이미 등록한 과제는 다시 만들지 않는다. 이전 체험 DB에는 예전 방식의 과제가 남아 있을 수 있다.

## 제한

- 검수 전 사진과 초안은 서버 메모리(`MemoryRawStore`)에만 있어, 서버가 다시 시작되면 검수 전 제출은 닫힌다(사진 채점 v3의 기존 동작).
- 사진 채점 과제에는 마감일과 학생 개별 배정이 없다.
- 체크 감지는 객관식 단일 선택에만 쓴다. 수·글자 답은 학생이 확인 화면에서 입력한다.
