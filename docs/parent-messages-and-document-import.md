# 학부모 정기 알림과 원본 문서 등록

최신 검증은 [문서 형식·자동 리포트 검증](document-parent-report-verification.md)을 기준으로 한다. 현재 전체 테스트는 779개이며, 아래 747/755개는 구현 단계별 이전 검증 이력이다. 최신 실제 네이버 검사에서는 PNG 1건이 검수로 보류됐으며, Cloudflare 스캔 PDF 변환은 여전히 미지원이다.

디자인 변경은 main `1213d45`에 병합했다. 이 기능은 별도 `feat/parent-monthly-messages` 브랜치에서 작업했다.

## 관리자 사용

상단 봉투 또는 메뉴의 **학부모 알림**에서 설정한다.

1. 정기 리포트에서 수신 대상 반, 매월 날짜(1~28일), 한국 시간(08~20시)을 고른다. 선택한 달의 전월 기록을 사용한다.
2. 기본 문구를 바로 쓰거나 직접 고친다. **AI 문구 만들기**는 네이버 CLOVA에 일반 안내용 인사·마무리 문장만 요청한다. 이름·학원·월·학습 수치와 필수 항목은 서버가 넣는다. 학생 정보를 AI에 보내지 않는다.
3. 분석 월을 고르고 **리포트 미리보기 만들기**로 실제 대상·내용·학습 근거를 확인한다. 승인된 기록이 없으면 리포트를 꾸며내지 않는다.
4. **알림함에 전달 · 예약 확정**을 누르면 학부모 알림함으로 전달한다. **매월 자동 전달**을 켜 두면 설정한 날 이후 담당자가 접속하지 않아도 서버가 처리한다. 자동 전달을 끄면 검토 대기에 보관한다.

새 안내에서는 자유 문구를 작성하고 전체 반 또는 특정 반의 학부모를 선택한다. 전달 시각을 비우면 확정 즉시, 지정하면 해당 시각 이후 전달한다. 미리보기에서 취소할 수 있다. 학생별 이름은 자동 입력된다.

**현재 전달 채널은 로그인한 학부모의 서비스 내 알림함이다.** 문자·카카오톡·휴대폰 푸시를 발송했다고 표시하지 않는다. 네이버 SENS 문자에는 별도 서비스 ID, 등록 발신 번호와 인증이 필요하며 알림톡은 채널·승인 템플릿도 필요하다. 현재 프로젝트에 이 설정과 학부모 전화번호가 없어 외부 발송은 연결하지 않았다.

## 기록과 자동 처리

- `op_parent_policies`: 학원별 일정·대상 반·문구·자동 전달 여부와 설정 버전.
- `op_parent_messages`: 수신 학부모/학생, 작성·예약·전달·취소 상태, 본문, 근거 버전, 읽음 시각, 작성 당시 대상 반.
- `op_parent_runs`: 이미 처리한 학원·분석 월. 메시지에도 학원·학생·학부모·월별 고유 키가 있어 재시작·같은 요청 재전송으로 중복되지 않는다.
- 로컬 서버는 1분 주기로 처리한다. Cloudflare는 Durable Object의 지속 알람을 사용하므로 방문자가 없어도 처리된다. 정확히 해당 초에 도착하는 실시간 발송을 보장하지 않으며 일반적으로 다음 처리 주기에 전달한다.
- 보호자 연결, 학원, 현재 대상 반을 전달 시 다시 검사한다. 다른 학부모의 ID로 접근하면 내용을 반환하지 않는다.
- 결과는 기존 승인 학습 기록·승인 교재 분석에서 얻는다. 같은 학생의 항목별 집계를 별도로 표시하고 겹칠 수 있는 분석의 문항 수를 서로 합산하지 않는다. 전달 전 근거가 바뀌면 차단하고, 이미 전달한 자료가 철회·변경되면 이전 본문을 숨긴다.
- 검토 중인 리포트는 미리보기를 다시 만들어 새 문구·근거로 갱신할 수 있다. 미리 만든 초안도 예약 시각에 최신 승인 근거로 갱신해 자동 전달하며, 자동 전달을 나중에 켠 경우에도 기존 초안을 처리한다. 이미 전달하거나 명시적으로 취소한 같은 월의 리포트는 자동 재발송하지 않는다.
- AI 문구 생성은 기존 네이버 호출 한도와 장애 처리 정책을 사용한다. 월별 대상마다 생성 API를 호출하지 않고 저장한 문구를 재사용한다. 키가 없어도 기본/직접 작성 문구와 정기 리포트는 동작한다.

AI 검증 중 자동 입력 변수 누락과 근거 없는 노력 평가 문장이 실제로 나왔다. 변수는 서버 소유로 바꾸고, 일반 안내·문의 목적을 벗어난 평가 문구는 기본 안내로 대체한다. 구조화된 필수 내용·수치 삽입은 모델의 자유 생성에 맡기지 않는다.

## RAG 원본 파일

기존 PDF·DOCX·HWPX·TXT·Markdown에 **XLSX·CSV·TSV·PPTX**를 추가했다. 업로드 시 빈 제목은 파일명으로 채운다. 파싱 결과를 검수·승인하면 기존 색인·검색·상담·인용으로 연결된다.

| 형식    | 처리                                                                                                                                                                                                                                                                      |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| XLSX    | 통합 문서의 실제 시트 연결 순서, 공유 문자열, 원본 행 번호, 표 헤더·셀을 보존한다. 빈 행으로 구분된 표는 분리한다. 숨긴 시트·행·열과 외부 링크는 읽지 않는다. 일반 시간/날짜/백분율 표시를 처리한다. 수식은 실행하지 않고 불확실 형식·수식·병합은 검수 대상으로 표시한다. |
| CSV/TSV | UTF-8/EUC-KR 텍스트에서 따옴표 안 구분자·줄바꿈을 셀로 유지한다. 열 개수 불일치·깨진 따옴표는 실패 처리한다. 첫 행을 헤더로 읽으며 수식을 실행하지 않는다.                                                                                                                |
| PPTX    | 프레젠테이션 연결 순서대로 공개 슬라이드의 텍스트·표와 슬라이드 번호를 보존한다. 발표자 메모·숨긴 슬라이드는 제외한다. 이미지/차트는 검수 대상으로 표시하고 복잡한 병합 표는 변환 안내 후 거부한다.                                                                       |

파일 크기·ZIP 압축 해제 제한과 개인정보 가림은 유지한다. 새 라이브러리를 추가하지 않았다. 표의 행·열·시트·슬라이드 정보는 기존 청크와 인용 위치에 들어간다. 구형 바이너리 HWP·DOC·XLS·PPT는 HWPX·DOCX·XLSX·PPTX 또는 PDF로 저장해야 한다. 이 작업은 파일 업로드 형식 확대이며 외부 폴더를 주기적으로 동기화하는 기능은 아니다.

## 작업을 늘리지 않는 기본 경로

- 정기 리포트는 기본 문구로 사용한다. 문구 꾸미기와 AI 말투 생성은 선택 항목이며 접힌 영역으로 이동했다. 학생별 문구를 직접 작성할 필요가 없다.
- 수신 대상·날짜를 한 번 저장하고 정기 사용과 자동 전달을 켜면 기존 승인 기록을 매월 재사용한다. 자동 전달을 끄면 검토 대기에 남으므로 매월 확정 작업이 필요하다.
- 월간 리포트 때문에 학습 기록을 다시 입력하거나 별도 분석 양식을 만들지 않는다. 기존 승인·공개된 학습 결과를 사용한다. 승인된 결과가 없는 학생에게는 생성하지 않는다.
- 자료 등록도 기존 원본을 올리고 추출 결과를 한 번 확인·승인하는 방식이다. 청크·표 셀을 직접 입력하지 않는다. 권한·적용 기간 확인과 부정확한 판독 수정은 남는다.
- 현재 외부 문자·카카오 발송과 폴더 자동 동기화는 없다. 서비스 내 알림을 보는 데에는 학부모 로그인이 필요하다.

## 사진 지원과 서버별 제한

JPG/JPEG·PNG 외에 WEBP·BMP를 추가하고 확장자가 아닌 바이트 서명으로 형식과 MIME을 구분한다. 네이버 HCX-005의 이미지 사양에 맞춰 크기·비율을 호출 전에 검사한다. 큰 사진은 브라우저에서 긴 변 2240px의 등록용 JPEG 사본으로 자동 변환한다. 기기의 원본은 변경하지 않으며 DB에는 실제 업로드된 사본이 저장된다. HEIC·TIFF·GIF·SVG는 아직 직접 지원하지 않는다.

네이버 키가 있으면 사진 판독 연결을 기본으로 제공하며 AXR_CLOVA_SCAN_ENABLED=false로 끌 수 있다. Cloudflare에도 같은 판독 연결을 추가했다. 다만 작업 브랜치의 기능이므로 기존 main 배포에 이미 적용된 것은 아니다.

사진은 개인정보가 없는 학원 공개 자료에 한해 파일별 판독 동의를 받고 처리한다. 학생 비공개 사진을 외부 AI로 전송하는 기능으로 확대하지 않았다. 한 페이지를 두 번 읽고 동일한 제목·본문·표 셀만 채택한다. 한글 띄어쓰기 차이는 비교 시 정리하지만 글자·숫자·구두점·숫자 사이의 공백 차이는 유지한다. 판독이 다르면 표시한 칸을 원본과 대조해 수정해야 승인할 수 있다. 두 번 읽었다고 OCR의 정답을 보장하는 것은 아니다.

사진 판독도 상담과 같은 DB의 일일 네이버 요청 한도를 소비한다. 페이지당 보통 2회이며 텍스트·Office 파싱에는 이 호출을 쓰지 않는다. 일일 요청 수 제한은 금액 한도 보장이 아니다.

- 로컬 Node 서버: 기존 렌더러로 스캔 PDF를 변환하고 동의한 경우 최대 3페이지를 판독할 수 있다.
- Cloudflare: 텍스트 PDF와 사진 판독을 지원하도록 연결했다. 네이티브 PDF 이미지 변환기가 없어 스캔 PDF는 아직 직접 처리하지 못한다. 읽지 못한 스캔 페이지가 섞인 PDF를 일부 텍스트만으로 저장하는 것도 막았다. 텍스트 PDF 또는 페이지 사진을 사용해야 한다.
- 업로드 크기: 로컬 기본 20MB, 현재 Cloudflare 설정은 파일당 5MB이다. 웹에서 큰 사진의 등록용 사본을 자동으로 줄인다.

## 현재 문서 보관·검색 방식

1. 관리자가 자료 종류·공개 범위·대상 반/학생·적용 시작/종료를 지정해 원본을 올린다. 제목은 비어 있으면 파일명에서 채운다.
2. 원본 파일과 추출한 정규화 본문, 페이지 품질·경고를 DB의 op_document_versions에 개정 번호별로 보관한다. 원본은 파일 이름과 BLOB으로 저장하며 별도 외부 드라이브를 가리키지 않는다.
3. 새 문서는 검수 대기 상태이며 상담에서 검색되지 않는다. 관리자가 내용을 확인해 승인하면 검색 대상이 된다. 추출 경고·불확실 셀은 확인이 필요하다.
4. 승인된 문서를 메모리 검색 색인으로 만들고 질문자의 학원·역할·반·학생 권한, 적용 시점을 검사한 뒤 근거를 선택한다. 원본 PDF 페이지, 표 행·열, Excel 시트/원본 행, PPT 슬라이드 위치를 정규화 본문과 인용에 남긴다.
5. 수정은 같은 문서의 새 개정판으로 저장한다. 승인 변경·철회 시 DB 색인 세대가 바뀌어 검색 캐시를 갱신한다. 최종 답변과 기존 대화의 출처도 현재 공개 상태를 다시 검사한다.
6. 철회는 상담 사용 중단이며 원본·개정 이력을 물리적으로 삭제하는 기능은 아니다. 원본 파일 다운로드는 관리자에게만 제공하며 다른 사용자는 자신의 권한에 맞는 공개 본문만 볼 수 있다.

현재는 파일별 업로드 시점의 사본을 관리한다. PC 폴더 전체 등록·폴더 감시·Drive 동기화·원본 파일 변경 자동 반영은 구현하지 않았다. 문서가 바뀌면 새 개정판으로 등록해야 한다. 따라서 '학원 원본을 활용'하는 것과 '모든 원본을 자동으로 동기화'하는 것을 구분해야 한다.
