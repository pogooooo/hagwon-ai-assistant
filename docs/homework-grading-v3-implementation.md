# 국영수 사진 숙제 채점 — v3 구현 기록

기준: `AXR-GRADING-FINAL-V3`, 2026-11-19. 실제 기준 코드는 `main`의 `d1ee3c0a289ff860ee4f6307ff0b34b0116d9a86`이다. 작업은 별도 브랜치 `feat/homework-grading-v3`, 별도 worktree에서 진행한다. 기존 `/homework`, 교재 분류·강사 채점, 기존 학습 기록 테이블은 유지한다. 기존 데이터를 새 평가 기준으로 소급 변경하지 않는다.

## 실제 구현 범위

새 화면은 `/grading`이다. 강사는 반·과제·국영수 문항·대표 유형·등록 정답·배점·허용 점수·채점 기준과 자료 이용 근거를 등록한다. 정답이 없는 문항은 채점 불가로 남길 수 있다. 학생/보호자는 현재 관계와 과제 배정을 확인한 후 사진/PDF를 제출한다. 학생 계정의 대상 ID는 서버 세션이 결정한다.

- 객관식 단일/복수 선택: 전체 정답 집합 비교. 중복 표시는 보류한다.
- 국어/영어 등록 단답: 문항별 Unicode·공백·대소문자 정책 적용. 철자·부정·굴절형·구두점을 자동 교정하지 않는다. 대체 정답은 강사가 등록한다.
- 수학 숫자/분수: BigInt 유리수 계산, 명시적 오차·단위·지원 단위 환산·요구 형식 검사. 기약분수 형식 점수를 내용 점수와 분리할 수 있다. 임의 코드 실행/일반 CAS 파싱을 사용하지 않는다.
- 수식: 등록된 대체 수식 답안을 비교한다. 임의의 다항식·방정식 동치나 정의역을 증명하는 기능은 없다. 등록하지 않은 표기는 강사 검수로 넘긴다.
- 의미 단답/풀이/서술: 승인된 정답·루브릭에 대한 HCX-007 요소 점수 제안을 지원한다. 인용은 실제 전사에 있는 문자열이고 점수는 허용 목록에 있어야 한다. 이는 실제 의미 채점 정확도가 검증됐다는 뜻이 아니다.
- HCX-005는 정답표를 받지 않고 실제 답안을 전사한다. 문항 ID·페이지·영역·최종 답·지움/모호함을 구분하며, 답안 crop 재판독과 차이가 있으면 보류한다. 같은 모델의 일치는 정확성 증명이 아니다.
- 모든 등록 문항을 초안에 유지한다. 누락·중복·판독 불가를 빈칸/오답/0점으로 바꾸지 않는다. 모든 문항을 강사가 확인해야 확정할 수 있다.

## 원문·결과·공개 경계

장기 DB는 기존 Node SQLite/Cloudflare SQLite 어댑터를 유지한다. 문서의 PostgreSQL/Python 구성은 참조 제안이므로 도입하지 않았다. 새 테이블은 `grading_v3_*`이며 자동 수치 통계는 코드가 계산한다.

사진, PDF 렌더링 페이지, 전사, 검수 초안과 과거 임시 초안은 프로세스 메모리 저장소에만 둔다. SQLite BLOB, 영구 파일, 로그, 검색/벡터 저장소에 원문을 복사하지 않는다. 기본 TTL은 개발 설정 60분이며 `AXR_GRADING_RAW_TTL_MS`로 조정한다. 메모리 저장소 총량은 64 MiB로 제한한다. 이 개발 기본값을 승인된 운영 보존기간으로 주장하지 않는다.

처리 상태, 원문 상태, 현재/공개 성적 revision을 분리한다. 확정 시 최소 결과·쓰기 fence·삭제 job을 같은 DB 트랜잭션으로 기록한다. 원문 쓰기 lease가 남아 있으면 삭제 확인을 완료하지 않는다. 실제 scope 목록을 열거해 manifest에 없는 객체도 삭제하고, 잔존 목록과 writer가 없는 것을 확인한 후 자체 영수증과 공개 head를 기록한다. 실패는 재시도 상태이며 성적·리포트·RAG 공개를 차단한다. 늦게 돌아온 모델 응답과 PUT은 초안/원문을 재생성할 수 없다.

임시자료 조회는 강사/관리자만 가능하고 `Cache-Control: no-store`를 사용한다. 원문 삭제 후 재판독은 지원하지 않는다. 새로 촬영한 같은 답안은 정정 증거로 연결하며, 다시 푼 제출과 구분한다. 정정 증거는 별도 attempt가 아니며 대상 결과 revision·학생·과제 버전·증거 draft revision·raw generation을 함께 검사한다. 새 증거의 삭제 확인 전에는 기본 결과 조회를 차단한다.

기본 결과에는 전사·학생 자유답안·사진·임시 설명이 없다. 요소 점수/오류 코드 보존은 기본 비활성이다. 메타데이터 기반 수행일 정정과 평가 제외, 새 증거 기반 점수 정정을 제공한다. 새로운 유형 체계로의 사후 매핑과 루브릭 교체 정정은 아직 제공하지 않는다. 과거 payload를 덮어쓰지 않는다.

자체 영수증의 범위는 해당 메모리 저장소의 논리 삭제 확인이다. 공급사 로그·물리 메모리·사용자 기기·외부 사본의 삭제 증명이 아니다. 메모리 저장소이므로 재시작 시 미확정 사진은 복구되지 않고 만료 처리된다. 같은 DB의 동시 runtime 교체는 진행 중 writer가 있으면 거부한다.

DB 백업을 복원할 때는 시작 전에 `AXR_GRADING_RESTORED_BACKUP=true`를 설정해야 한다. 이전 공개 head를 격리하고 리포트를 stale 처리한다. 별도 신뢰 이력/대조 없이 임의의 DB rollback을 자동 탐지하는 외부 제어 영역은 구현하지 않았다. 운영 백업·복구 절차 검증이 필요하다.

## 분석·리포트·RAG

`first_ever`는 전체 시도에서 첫 시도를 선택한 뒤 기간을 검사한다. `latest_in_window`는 기간 안의 최근 시도를 선택한 뒤 공개/평가 가능 여부를 검사한다. 최근 시도가 대기·판독 불가·철회 상태여도 과거 정답으로 대체하지 않는다. 아직 업로드가 완료되지 않은 예약과 정정 증거는 학습 시도 분모에 넣지 않는다.

정답/오답/부분 정답/빈칸을 같은 평가 집합으로 사용해 정답률과 점수율을 산출한다. 판독 불가·제외는 별도 수량이다. 각 과목의 0건 fact와 null 비율, 선택/공개/대기/불가 수량을 남긴다. 점수 합계는 정밀 정수 단위로 계산하고 비율만 소수 6자리 ROUND_HALF_UP으로 직렬화한다. 통계 snapshot은 원천 result revision/item과 선택 시도 목록을 포함한다.

리포트에서 HCX-007은 실제 fact에 대한 관찰·비교·일반 복습 제안을 선택한다. 숫자와 최종 문장은 검증된 renderer가 구성한다. 요청 과목 누락, 가짜 fact, 잘못된 비교 기간/유형 버전은 거부한다. 생성 실패/연동 차단은 정형 초안으로 대체하며 AI 생성으로 표시하지 않는다. 학생·보호자에게는 강사가 승인한 현재 generation의 리포트만 제공한다. 정정·시도 등록·공개 변경은 같은 트랜잭션에서 통계 generation을 갱신하고 옛 리포트를 stale 처리한다.

RAG에는 삭제가 확인된 현재 결과의 과목·반·학생·월별 통계만 전달한다. 과목별 근거 문서를 분리한다. 기존 FactValue에 선택적 `subject`, 카탈로그에 선택적 `subjects`를 추가해 하나의 반에서 다과목 숙제를 사용할 때 반 이름으로 과목을 오판하지 않게 했다. 기존 필드가 없는 자료는 기존 반 과목 해석을 유지한다. 인용 문단 형식은 기존의 엄격한 통계 근거 검증을 따르며 검증기를 완화하지 않았다.

기존 학부모 자동 발송 설정을 바꾸거나 새 리포트를 자동 승인/외부 발송하지 않는다. v3 공개 리포트는 사진 채점 화면에서 볼 수 있다.

## 실제 스택에 맞춘 계약 차이

첨부 D08 전체 JSON Schema/`/api/v1` 경로를 기존 앱 위에 그대로 복제하지 않았다. 서버 내부 Zod 계약과 기존 로그인·Origin 검사·폼 라우터를 사용한다. `/grading`의 과제 등록·제출·검수·확정·정정·리포트 동작과 `/grading/photo`가 실제 경로다. 내부 요청은 revision과 별도 멱등 키를 사용하며 학생/학원/확정자 권한은 서버가 결정한다. 독립 과제 자산만 장기 등록하며 제출 원문을 등록 자산으로 옮기지 않는다.

문서 D의 선택적 교육과정 레지스트리·독립 키/루브릭 관리 API·전체 정정 DTO·외부 객체 저장소 버전/multipart·분산 worker는 구현하지 않았다. 신규 점수/분류 버전, 실제 학교급/교재 운영 지원 범위는 별도 검증이 필요하다.

## NAVER 설정과 실행

기존 `CLOVA_STUDIO_API_KEY` 또는 `RAG_CLOVA_API_KEY`를 서버에서만 사용한다. Gemini/OpenAI 대체 호출은 없다. 동일 DB의 기존 NAVER 일일 요청 상한을 공유하며 실패한 요청도 사용량에 포함된다. 이 상한은 금액 상한이 아니다.

실제 배포의 입력·보관 조건을 확인한 후에만 `AXR_GRADING_EXTERNAL_DATA_APPROVED=true`와 `AXR_GRADING_INPUT_POLICY_REF`를 설정한다. 기본 false이며 학생 업로드 체크박스로 이 정책을 켜지 않는다. 키/정책이 준비되지 않으면 자동 판독 불가 초안을 강사 수동 검수로 처리할 수 있다. CLOVA OCR 별도 서비스 어댑터는 아직 추가하지 않았고 현재 구현은 HCX-005/007 경로다.

```powershell
npm run academy:dev
# 로그인 후 /grading
npm test
npm run check
npm run build
```

사진 실제 디코딩과 텍스트/스캔 PDF 렌더링은 로컬 Node의 기존 `@napi-rs/canvas`/`pdfjs-dist`를 재사용한다. Cloudflare의 현재 native-unavailable 배포에는 이 디코더가 없다. 해당 환경에서 새 사진 채점을 운영 가능하다고 주장하지 않는다. 기존 배포는 변경하지 않았으며, 운영 연결에는 별도 디코딩 경로 검증이 필요하다.

## 검증의 의미

2026-11-19 첫 v3 반영 시에는 기존 779개와 신규 채점 40개를 합한 자동 테스트 819개가 통과했다. 이후 기존 방식의 사진 판독·대분류 개선 PR #3을 `main`에 병합하고, 그 `main`을 새 채점 브랜치에도 병합했다. 이 과정에서 기존 방식의 테스트 33개가 추가됐으며 최종 실행 결과는 다음과 같다.

| 검증 대상                                      | 검증 코드 | 전체 자동 테스트 | 실패 / 건너뜀 | 코드 검사 / 빌드 |
| ---------------------------------------------- | --------- | ---------------- | ------------- | ---------------- |
| `main` 기존 방식                               | `4d260ee` | 812개 통과       | 0 / 0         | 모두 통과        |
| `feat/homework-grading-v3` 기존 기능 + 새 채점 | `b256acf` | 852개 통과       | 0 / 0         | 모두 통과        |

두 브랜치의 차이 40개는 새 채점 기능의 테스트다. 819개는 PR #3 통합 전 결과이고, 852개는 통합 후 결과다. 문항 정확도 평가의 분모가 아니라 자동 소프트웨어 테스트 개수다. 코드 검사는 `npm run check`의 lint·타입·포맷 검사이며 빌드는 `npm run build`다.

첫 v3 반영 시 Cloudflare Worker 배포 패키지의 `wrangler deploy --dry-run`도 통과했으며 실제 업로드/배포는 수행하지 않았다. 이 빌드 결과는 아래 손글씨 인식·채점 성능 검증을 대신하지 않는다. 두 버전의 공통 수정·전용 수정 절차는 [병행 개발 규칙](./grading-branch-workflow.md)을 따른다.

추가 시험은 명시된 합성 정답·모의 공급사 응답과 실제 이미지/PDF 디코딩, 실제 HTTP 폼/세션을 사용한다. 원문 삭제 후 결과·리포트·RAG 인용을 확인하며, 국영수 과목 간 값/인용 혼합을 별도로 시험한다. 강사 검수·권한·중복 확정·동시 수정·삭제 403·지연 PUT/모델 응답·만료·재시작·선언된 백업 복원·재풀이 선택·0건 통계·부분점수·정정 중 생성 등을 포함한다.

평가기는 `grading-eval-3.0`으로 기존 평가기와 분리했다. 독립 gold manifest를 기준으로 예측 누락·timeout·오류·잘못된 학생/문항 연결·판독 불가 강제 채점을 분모에 남긴다. 운영 coverage, 평가 가능 조건부 coverage, 점수/상태 일치율과 부적절 만점을 구분한다. 이 평가기 자체의 작은 합성 fixture를 실제 손글씨 모델 성능으로 해석하지 않는다.

실제 NAVER 호출, 학생 숙제 인식률, 국영수 95% 정확도, 강사 검수시간 절감, 실제 개인정보 전송 조건, 공개 Cloudflare의 새 기능 실행은 이번 변경의 통과 실적으로 보고하지 않는다.
