# 기존 방식과 새 채점 방식의 병행 개발

## 유지할 두 버전

- `main`: 기존 교재 사진 판독·문항 분류·강사 채점 방식. PR #3의 사진 판독·대분류 개선도 여기에 포함한다.
- `feat/homework-grading-v3`: `main`의 공통 기능에 국영수 정답·루브릭 기반 채점 초안, 강사 전수 검수, 원문 삭제 확인, 최소 결과·리포트를 추가한 버전.
- `prototype`: 별도로 보존한다.

새 채점 코드는 `src/features/homework-grading/`에 둔다. 기존 `/homework` 동작과 기존 기록을 덮어쓰지 않으며 새 화면은 `/grading`, 새 DB 테이블은 `grading_v3_*`다. 이 브랜치 전체를 `main`으로 병합하면 새 채점 방식도 들어가므로, 두 방식을 따로 유지하는 동안에는 해당 병합을 하지 않는다.

## 두 버전에 필요한 공통 수정

1. 최신 `main`에서 `feat/<기능명>` 또는 `fix/<문제명>` 작업 브랜치를 만든다.
2. 기존 방식에서 동작을 확인하고 검사·테스트·빌드를 통과시킨 뒤 PR을 `main`에 병합한다.
3. 새 채점 브랜치에서 작업 중인 변경을 먼저 커밋한 뒤 `git fetch origin`, `git merge origin/main`으로 같은 변경을 가져온다.
4. 충돌이 있으면 공통 수정과 새 채점 연결을 함께 유지해 해결한다. 새 채점 브랜치에서도 검사·전체 테스트·빌드를 실행한다.
5. 두 브랜치를 각각 푸시한다. `main`으로 새 채점 브랜치를 역병합하지 않는다. 강제 푸시나 이력 재작성은 필요하지 않다.

이 방식은 동일 저장소의 두 개발 버전을 관리하는 절차다. 한쪽 수정이 다른 쪽에 실시간 자동 복사되는 기능은 아니다. 같은 커밋을 두 번 만드는 대신 `main`의 이력을 병합하므로 이후 중복 적용을 줄일 수 있다.

## 한 버전에만 필요한 수정

- 새 채점 규칙·전사·검수·삭제·v3 통계 변경은 `feat/homework-grading-v3`에서 작업한다. 필요하면 이 브랜치에서 짧은 하위 작업 브랜치를 만들고 PR 대상도 `feat/homework-grading-v3`로 지정한다.
- 기존 방식만 바꿔야 하는 수정은 `main` 기준 작업 브랜치에서 처리한다. 새 채점 버전에도 기존 화면이 남아 있으므로 `main`을 가져온 뒤 함께 확인한다.
- 새 채점 브랜치에서 발견한 공통 오류는 `main` 기준의 별도 커밋/PR로 분리한다. v3 구현 전체를 `main`에 가져와서 공통 오류를 고치지 않는다.
- 불가피하게 특정 공통 커밋 하나만 옮길 때는 변경 의존성을 확인한 뒤 `git cherry-pick -x <SHA>`를 사용하고 양쪽을 검증한다.

## 충돌 시 확인할 경계

공통으로 자주 겹치는 파일은 `academy-operations/application.ts`, `consultation.ts`, `service-navigation.ts`, RAG 타입·질문 해석·통계 근거, `.env.example`, Cloudflare 실행 파일이다. 파일 전체를 한쪽 버전으로 선택하지 않고 기존 방식의 개선과 v3의 연결을 모두 확인한다. 특히 PDF/이미지 decoder 대체 모듈은 같은 export를 중복 선언하지 않는다.

검증 명령은 `npm run check`, `npm test`, `npm run build`다. 기존 방식의 문항 판독/분류와 강사 채점, 새 방식의 원문 삭제·권한·정정·통계·RAG 인용을 각각 포함한다. 모의 공급사 응답을 사용한 테스트 통과를 실제 손글씨 정확도로 해석하지 않는다.

## 로컬 실행과 데이터

두 버전은 별도 worktree에서 연다. 각 폴더의 기본 DB는 `.local/academy-operations.sqlite`이므로 상대 경로 기본값을 쓰면 DB 파일도 분리된다. 두 프로세스에 같은 절대 `AXR_OPERATIONS_DB` 경로를 지정하지 않는다. 기존 운영 DB를 새 방식 시험에 재사용하지 않는다.

동시에 실행하려면 `AXR_OPERATIONS_PORT`를 다르게 설정한다(예: 기존 8791, 새 방식 8792). `.env.local`과 API 키는 Git으로 공유하지 않는다. 공개 서비스가 `main`을 배포하더라도 새 채점 브랜치는 자동으로 배포되지 않는다. 배포 경로와 사진/PDF decoder 지원은 별도 검증 대상이다.
