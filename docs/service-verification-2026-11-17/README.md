# 현재 기능 검증과 실사용 판정 — 2026-11-17

**학원 직원이 확인하는 운영 보조 용도로는 제한된 시범 운영이 가능하다. 보호자에게 검토 없이 답변하는 자동 상담, 스캔 문서 중심 운영, 음성 상담을 완성된 서비스로 제공할 수준은 아니다.**

검증 기준 코드는 main `5f60c7de6c77fd381f1ba0b9eff6566bfd814fc2`다. 이번 브랜치에서는 웹·모바일 화면과 마이크 시작 처리를 수정했다. 상담 정답을 높이려고 엔진·기존 정답·평가 문항을 수정하지 않았다.

기능·상담·브라우저 검증은 Windows/Node 24.19.0의 임시 합성 DB에서 실행했다. 실제 Gemini 요청은 로컬 어댑터에서 공식 API로 보냈다. 운영 사이트의 비밀번호를 바꾸거나 운영 자료를 수정해서 시험하지 않았으며, 로그인한 운영 사이트에서 같은 상담을 재실행한 결과로 주장하지 않는다. 배포 확인은 공개 화면·자산·비로그인 접근 제한을 따로 검사한다.

## 판정 방법

- **통과**: 이번 실행에서 기대 동작을 확인했다. 표시된 합성 데이터·로컬 환경 범위에 한한다.
- **제약**: 기능은 실행되지만 사용 조건이나 실패가 확인됐다.
- **실패**: 입력과 기대 결과가 있는 검사에서 요구를 만족하지 못했다.
- **미검증**: 필요한 연결·원본·단말·운영 접근 또는 장기 관측이 없어 결론을 내리지 못했다.
- 자동 테스트 수는 테스트 코드 개수다. 상담 문항 수, 학원 문서 수, 실제 이용자 수와 합산하지 않는다.
- 기능의 유용성은 작업을 끝낼 수 있는지로 판단한다. 운영 시간 절감률·담당자 업무 감소율·사용자 만족도는 측정하지 않았으며 수치를 주장하지 않는다.

## 상담 평가의 의미

### 기존 문항: 회귀 확인

| 세트                      |                      문항 수 |           Mock 생성 |                     Gemini 설정 |
| ------------------------- | ---------------------------: | ------------------: | ------------------------------: |
| 기존 기본                 |                           90 |                  90 |                              88 |
| 표현 변형                 |                          100 |                 100 |                             100 |

| 합계                      | 1,036 / 실제 Gemini 대상 736 | 1,026/1,036 (99.0%) |                 721/736 (98.0%) |

기존 채점은 상태·필수/금지 문자열·출처 등의 기존 계약을 그대로 사용했다. 복수 출처 일부만 맞는 문제와 모든 주장의 의미를 검사하는 한계가 있으므로 이 점수를 새 평가의 엄격한 합격률과 직접 비교하면 안 된다.

Gemini 설정에서 Mock 때 맞았던 5문항이 기존 채점상 실패했다. 전체 실패 ID·상태·답변은 [회귀 결과](regression-results.json)에 보존했다. 그중 GA-018, SS-021은 원응답까지 재확인했으며, API 장애가 아니라 모델이 JSON status=unknown을 반환해 담당자 연결로 처리한 경우다. 원문에 학습 방법이 없는데 Mock은 답을 생성했던 평가 기대와 차이가 있다. 이를 전부 모델 성능 악화로 단정하거나 정답을 바꾸지 않았다.

이전 보고서의 별도 합성 학원 300문항/96%는 이번에 재실행한 위의 구조 회귀 300문항과 **다른 데이터**다. 별도 평가 원본 경로가 현재 체크아웃에 없으므로 96%를 현재 검증 결과로 사용하지 않았다.

### 새 문항: 운영 모듈의 새로운 문서·표현 도전

새마루라는 가상 안내 자료 12개(주소·주차·와이파이·자습실·환불·셔틀·도서 대여·분실물·체험·사물함·결석·상담시간)를 작성했다. 운영 모듈에서 자료 등록·승인→색인→상담→답변 저장까지 실행했다. 초기 데모 문서는 이 임시 DB에서만 제거했다.

| --------- | ------------------------------------------------------------------------ | ------------: |
| 답변 가능 | 12주제 × 3표현, 위치·수치·단위·기간·방법을 원문과 연결                   |         24/36 |
| 복합      | 두 주제의 요구 사실과 출처가 모두 필요한 질문                            |           2/8 |

답변 가능한 44문항만 분모로 쓰면 **26/44 (59.1%)**다. 근거 없는 8문항 중 2개는 관련된 문장만 제시하면서 answered로 처리했다. 문서에 없는 요금 숫자를 새로 지어낸 사례와는 구분하지만, 질문을 해결했다는 잘못된 표시다.

채점은 허용 상태, 모든 필수 사실 문자열(공백/NFKC 정규화), 모든 필수 자료 ID, 승인 revision=2, 비어 있지 않은 인용 위치를 함께 검사한다. 권한 거부는 HTTP 403에 해당하는 OperationError와 메시지 미저장을 확인한다. 근거 없음/거부에서 출처가 남으면 실패다. 새로 만든 전 문항·기대값·실제 답변은 [60문항 상세표](chat-cases.md), 원문과 원시 결과는 [JSON](chat-challenges.json)에 있다.

**한계:** 일부 의역을 엄격하게 오답으로 셀 수 있고, 필수 문구 외 추가 주장의 의미나 모든 인용 위치의 실제 셀을 자동 증명하지 못한다. 학원 계정/반 카탈로그는 기존 합성 카탈로그를 재사용했다. 실제 새 학원·실제 학부모의 독립 검증이 아니다. 문항이 이제 공개됐으므로 이후에는 회귀 자료다.

기대 문항/자료의 실행 전 SHA-256은 `bf5074710e6c4b13217e26a8e2b592f4b164bc908946f74b868aefef41a57438`다. 최초 평가 코드가 권한 경계의 403을 일반 오류로 세어 32/60으로 출력한 문제는 평가기 v2에서 고쳤다. 엔진·문항·기대 사실은 동일하며, 8건의 정상 차단을 반영해 40/60이 됐다. 정답 문구를 바꿔 통과시킨 것이 아니다.

## 디자인과 모바일 변경

- [NAVER Cloud Platform Design Kit 사례](https://newtype.design/works/article/ndk)의 기능별 색·아이콘과 일관된 정보 위계를 참고했다. 라이브러리 설치나 네이버 로고/디자인 자산 복사는 하지 않았다.
- 상담/일정/숙제, 기록/자료, 운영 관리로 메뉴를 묶었다. 같은 기능에는 화면마다 같은 아이콘과 색을 사용한다.
- 홈은 실제 처리 건수와 다가오는 일정 중심으로 정돈했다. 기존 캐릭터와 역할별 접근을 유지한다.
- 모바일 하단 주요 메뉴+전체 메뉴, 키보드 초점, 입력 크기·여백·터치 영역을 개선했다.
- 모바일 웹앱은 온라인 운영 서비스를 그대로 사용한다. 오프라인 상담·개인 자료 저장 기능은 제공하지 않는다.
- APK는 이 웹앱을 여는 Android TWA 방식으로 별도 구성했다. 빌드·서명 검증은 통과했으며 패키지와 파일 해시는 [Android 안내](../android-preview.md)에 있다. 실제 기기 설치는 미검증이다.

브라우저 검증은 설치된 Chrome과 임시 메모리 DB를 사용한다. 운영 DB나 사용자 브라우저 프로필에 접속하지 않는다. 외부 생성 키가 없으면 상담 검증 공급자는 disabled이며 Mock으로 바꾸지 않는다. Gemini를 사용할 때는 기존 서버 환경 변수로만 주입한다.

[브라우저·접근성·로컬 응답 결과](browser-results.json), [기존/실제 Gemini 회귀 결과](regression-results.json), [새 문항 전체 결과](chat-challenges.json)를 함께 보아야 한다. 단순 통과 테스트 수만으로 서비스 준비가 완료됐다고 판단하면 안 된다.
